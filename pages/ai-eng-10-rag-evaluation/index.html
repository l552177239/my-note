10.RAG评估与优化

# 10. RAG 评估与优化

系列第 10 篇。09 篇的 RAG 能跑了，但"感觉还行"不是合格的工程判断——改了一个参数后到底是变好了还是变差了？ 这一篇用 RAGAS 把主观感觉变成可量化指标，建立黄金测试集，学会定位和修复 badcase。 这是从"demo"到"产品"的分水岭。

# 1. 学习目标

  • 理解为什么"我问了几个问题感觉不错"不够
  • 掌握 RAGAS 四大指标：忠实度、答案相关性、上下文精确度、上下文召回率
  • 构建 10~20 个问答对的黄金测试集
  • 用 RAGAS 跑自动评估，定位短板
  • 根据最低的指标项针对性调参
  • 产出物：一份测试集 JSON + 一份评估脚本，能输出四项分数，能对比调参前后

# 2. 为什么必须量化评估

改 RAG 参数是典型的"按下葫芦浮起瓢"：

  • top_k 从 3 调到 5，召回多了，但无关片段也多了
  • chunk_size 从 500 调到 300，片段更精准了，但上下文不完整了
  • score_threshold 从 0.3 调到 0.5，答案干净了，但有些问题直接答不出来了

没有指标，你只能靠"再问几个问题试试"——这不叫调参，叫碰运气。

# 3. RAGAS 四大指标

RAGAS 把 RAG 质量拆成两个阶段：检索（搜得对不对）和生成（答得好不好）。

指标 衡量什么 低了说明什么
上下文召回率 (Context Recall) 标准答案里的关键信息，检索到的 context 覆盖了多少 检索漏了相关片段，chunk_size/top_k 有问题
上下文精确度 (Context Precision) 检索到的片段里，有多少是真正相关的 噪声太多，需要 rerank 或调高 score_threshold
忠实度 (Faithfulness) LLM 回答的每句话，能不能在 context 里找到依据 LLM 在编造，prompt 约束不够或 temperature 太高
答案相关性 (Answer Relevancy) 回答有没有答到点上，有没有废话 回答跑偏，可能 context 给错了

排查顺序：先看检索两项（召回/精确），再看生成两项（忠实/相关）。检索错了，生成再强也没用。

# 4. 装 RAGAS

uv add ragas datasets
1

RAGAS 评估本身会调 LLM 来打分（用 LLM 当裁判），所以需要一个可用的 LLM。学习阶段直接用本地 Ollama 的 qwen2.5。

写测试集的原则：

  • 覆盖知识库里的每个话题，不要全是退货问题
  • 包含同义改写：文档写"退货"，用户可能问"怎么退钱"
  • 包含否定/边界问题："生鲜能退吗"（答案是不能）
  • 10~20 个够用，别贪多

# 6. 跑评估

新建 scripts/eval_rag.py：

import asyncio
import json
from pathlib import Path

from datasets import Dataset
from ragas import evaluate
from ragas.metrics import (
    context_precision,
    context_recall,
    faithfulness,
    answer_relevancy,
)

# 复用你的 RAG service
from app.services.rag_service import ask

async def run_eval(collection: str = "faq"):
    testset = json.loads(Path("tests/rag_testset.json").read_text(encoding="utf-8"))

    records = []
    for item in testset:
        result = await ask(collection, item["question"])
        records.append({
            "question": item["question"],
            "answer": result["answer"],
            "ground_truth": item["ground_truth"],
            "contexts": [h["text"] for h in result.get("sources", [])],
        })

    dataset = Dataset.from_list(records)

    result = evaluate(
        dataset=dataset,
        metrics=[context_precision, context_recall, faithfulness, answer_relevancy],
    )
    print(result)
    return result

if __name__ == "__main__":
    asyncio.run(run_eval())

# 7. 根据最低项调参

拿到分数后，找最低的那项，按表对症下药：

最低项 问题 怎么调
context_recall 低 相关片段没搜到 top_k 调大（3→5→8）；chunk_size 调小；检查 embedding 模型
context_precision 低 搜了一堆不相关的 score_threshold 调高（0.3→0.5）；接 rerank 模型；BM25 权重调
faithfulness 低 LLM 在 context 之外编造 system prompt 加强约束；temperature 降到 0；检查 score_threshold 是不是太低
answer_relevancy 低 回答答非所问 context 给错了（回到检索项）；prompt 里加"直接回答问题"

# 7.1 一个 badcase 调试示例

假设 context_recall 只有 0.6，问"生鲜能退吗"没答出来：

  1. 查检索：把这条 question 单独拿去 /api/search/query，top_k=5，看返回了什么
  2. 发现：搜出来的全是"退货政策"泛泛之谈，没有"生鲜不支持"那句
  3. 原因：chunk_size=500 时，"生鲜不支持退货"和"定制商品不支持退货"被切在同一块里，向量被"退货政策"这个大话题稀释了
  4. 修复：chunk_size 从 500 调到 300，overlap 保持 20%
  5. 重跑评估：context_recall 从 0.6 升到 0.85

这就是 badcase 驱动优化——不是瞎调，是看到具体问题再动手。

# 8. 指标权衡：没有银弹

调参时一定会遇到此消彼长：

调整 变好 变差
top_k 增大 召回率↑ 精确度↓，context 变长，token 成本↑
chunk_size 减小 片段更聚焦 上下文不完整，召回率可能↓
score_threshold 调高 精确度↑，faithfulness↑ 有些问题直接答不出来，召回率↓
temperature 降到 0 faithfulness↑ 回答可能呆板

没有全局最优，只有业务最优：客服场景宁可"答不出来转人工"也不要瞎编，就把 threshold 调高；知识问答场景宁可答得糙也要覆盖全，就把 top_k 调大。

# 9. 可观测性（预告第 17 篇）

调试 badcase 时，手动看检索结果很费劲。第 17 篇会接 Langfuse，它能：

  • 记录每次 RAG 调用：检索了哪些片段、LLM 看到什么 context、token 花了多少
  • 回放某一次 badcase：当时检索到了什么、LLM 基于什么回答的
  • 看趋势：调参后哪条曲线动了

现在知道有这个工具就行，第 17 篇接上。

# 10. 产出物验收清单

  • [ ] tests/rag_testset.json 有至少 10 个问答对
  • [ ] eval_rag.py 能跑出四项指标
  • [ ] 能指出四项里最低的是哪项，说出对应的优化方向
  • [ ] 至少做一次调参（改 chunk_size 或 top_k），重跑评估，对比分数变化
  • [ ] 能说出"指标高但体验差"的原因（测试集太简单）

# 11. 失败模式速查表

现象 原因 解法
RAGAS 跑分全是 0 或报错 LLM 裁判调用失败 RAGAS 内部要调 LLM，确认 Ollama 在跑；检查 base_url 配置
四项指标全 1.0 测试集太简单或 ground_truth 太泛 加刁钻问题；ground_truth 写具体事实
调参后分数没变 改了参数但没重跑 确认改的是运行时配置，不是只改了文档
context_recall 低但检索看着没问题 chunk 把关键句切断了 调小 chunk_size；检查 overlap
faithfulness 低但检索全对 LLM 没听 system prompt temperature 降到 0；prompt 里重复约束
评估很慢 RAGAS 每个问题都要调 LLM 打分 测试集先 10 个；生产用小模型打分
指标全降了 改了 chunk_size 但没重新入库 改 chunk_size 必须重新切分+重新 embed+重建 BM25
分数高但用户说不好 测试集和真实问题不匹配 测试集从真实用户提问里采样，不要自己编
