Redis工程实战案例

# Redis 工程实战案例

三个高频场景：接口限流、分布式锁、用户信息缓存。均基于 RedisTemplate 演示核心思路。

# 案例一：接口限流（计数器）

# 场景

单用户 1 分钟内最多访问接口 10 次。

# 原理

String + INCR 自增 + 过期时间。

# 代码

String key = "limit:" + userId;

// 自增
Long count = redisTemplate.opsForValue().increment(key, 1);

// 首次设置过期时间
if (count != null && count == 1) {
    redisTemplate.expire(key, 60, TimeUnit.SECONDS);
}

if (count != null && count > 10) {
    throw new RuntimeException("访问过于频繁，请稍后再试");
}

# 要点

  • 用 increment 保证计数原子性
  • 仅在 count == 1 时设置 TTL，形成固定窗口
  • 生产可升级为滑动窗口、令牌桶等更精细算法

# 案例二：分布式锁（简单版）

# 场景

集群环境防止重复下单、重复执行任务。

# 原理

SET NX + 过期时间 互斥抢占 Key。

# 代码

String lockKey = "lock:order:" + orderId;

// 抢占锁
Boolean lock = redisTemplate.opsForValue()
        .setIfAbsent(lockKey, "lock", 30, TimeUnit.SECONDS);

if (lock == null || !lock) {
    return "系统繁忙，请重试";
}

try {
    // 执行业务
} finally {
    // 释放锁
    redisTemplate.delete(lockKey);
}

# 要点与局限

点 说明
为什么要过期 防止进程崩溃导致死锁
简单版风险 业务超时后锁过期，其他线程抢锁；delete 可能误删别人的锁
进阶方向 锁值用唯一标识 + Lua 校验后删除；或 Redisson 等成熟客户端

本例适合理解原理；生产关键路径建议使用更完备实现。

# 案例三：用户信息缓存（Hash）

# 场景

查询用户信息，减少 DB 压力。

# 原理

Hash 存储用户字段；缓存未命中再查库回写。

# 代码

String userKey = "user:" + userId;

// 先查缓存
Map<Object, Object> userMap = redisTemplate.opsForHash().entries(userKey);
if (userMap != null && !userMap.isEmpty()) {
    return userMap;
}

// 查数据库
User user = userMapper.selectById(userId);
if (user == null) {
    return null;
}

// 写入缓存
redisTemplate.opsForHash().put(userKey, "id", user.getId());
redisTemplate.opsForHash().put(userKey, "name", user.getName());
redisTemplate.expire(userKey, 30, TimeUnit.MINUTES);

return user;

# 要点

  • Hash 适合对象多字段、可局部更新
  • 务必设置过期，避免脏数据常驻
  • 进一步可处理：缓存穿透（空值短缓存）、击穿（互斥锁）、雪崩（过期时间打散）

# 小结

案例 核心命令 / API 关键能力
限流 INCR + EXPIRE 保护接口
分布式锁 SET NX EX 互斥执行
用户缓存 Hash + TTL 降低 DB 压力
