# 01. Python 与工程化基础

系列第 1 篇。本篇是所有后续项目（Ollama 服务、RAG、Agent）的地基：环境管理 → 项目结构 → FastAPI 最小服务 → 异步并发 → 配置管理。 跑通再记笔记。

# 1. 学习目标

  • 用 uv 管理虚拟环境与依赖，说出它和 pip + venv 的差别
  • 搭出一个带热重载、健康检查、CORS、日志的 FastAPI 最小服务
  • 用 asyncio.gather 并发跑多个 IO 任务，理解为什么 LLM 调用必须异步
  • 用 .env + Pydantic Settings 管理配置，密钥不进代码仓库
  • 产出物：一个 GET /health 返回 {"status":"ok"}、GET /echo 回显参数、且允许前端跨域访问的服务

# 5. 异步基础：为什么 LLM 应用必须 async

LLM 调用、向量检索、HTTP 请求都是 IO 密集 操作：CPU 99% 时间在等网络返回。同步写法下，一个请求卡 3 秒，服务器就只能干等 3 秒。

import asyncio
import time

async def fake_llm_call(prompt: str) -> str:
    await asyncio.sleep(1)        # 模拟 1 秒的模型调用
    return f"reply to: {prompt}"

async def main():
    prompts = [f"问题{i}" for i in range(5)]

    # 同步思路（错误示范）：5 个调用串行 = 5 秒
    t0 = time.perf_counter()
    for p in prompts:
        await fake_llm_call(p)
    print(f"串行: {time.perf_counter() - t0:.2f}s")   # ≈ 5s

    # 并发：5 个调用同时发出 = 1 秒
    t0 = time.perf_counter()
    await asyncio.gather(*(fake_llm_call(p) for p in prompts))
    print(f"并发: {time.perf_counter() - t0:.2f}s")   # ≈ 1s

asyncio.run(main())

三个必须记住的点：

  1. async def + await：IO 操作前加 await，让出事件循环
  2. asyncio.gather：并发执行一组协程——09 篇的"混合检索 = 向量检索 ∥ BM25 检索"就是靠它
  3. FastAPI 路由怎么选 async def 还是 def？
    • 路由写成 async def：在事件循环里跑，遇到阻塞操作必须 await，否则卡住所有请求
    • 路由写成普通 def：FastAPI 自动把它丢进线程池执行，不会卡事件循环——适合调用老的同步库（如没异步版本的 SDK）
    • 红线：在 async def 里禁止用同步阻塞调用（requests.get、time.sleep、同步 psycopg2 查询），一律换 httpx.AsyncClient / asyncio.sleep / 异步驱动

# 8. 失败模式速查表

现象 原因 解法
uv run 找不到依赖 没跑 uv sync 换机器/拉代码后第一步永远 uv sync
改了代码不生效 --reload 没生效或看错端口 确认启动命令带 --reload，确认 curl 的端口
.env 修改后 Settings 没变化 服务没重启 Settings 在 import 时加载一次，改配置必须重启
pydantic_settings 报 extra fields .env 里有未声明的键 SettingsConfigDict(..., extra="ignore") 或在类里补字段
路由 404 include_router 漏了 / 路径前缀拼错 先看 /docs，没有的接口就是没注册上
异步代码偶发卡死 在 async 函数里用了同步 IO（requests、time.sleep） 换 httpx.AsyncClient、asyncio.sleep；或路由改普通 def
前端调接口报 CORS / 浏览器控制台 No 'Access-Control-Allow-Origin' main.py 没挂 CORSMiddleware，或前端源不在 allow_origins 里 按第 4 节配置，把前端 origin 加进去
访问日志格式乱 / 看不到 INFO 没配 logging.basicConfig，uvicorn 默认 WARNING 在 main.py 顶部加第 4 节的 basicConfig
