03.Prompt工程与输出控制

# 03. Prompt 工程与输出控制

系列第 3 篇。02 篇让模型能说话了，这一篇让它听话：系统提示怎么写、Few-shot 怎么喂、CoT 怎么诱导推理、怎么强制输出 JSON、怎么算 Token。 这是后面 RAG（要引用来源）、Function Calling（要解析工具参数）、Agent（要决策）的共同地基——模型输出不稳定，后面全是补丁。

# 1. 学习目标

  • 区分 system / user / assistant 三种消息角色，知道 system 提示该放什么
  • 会写 Few-shot 示例，让模型照着格式输出
  • 会用 CoT（Chain of Thought）让模型先想后答
  • 用 response_format={"type": "json_object"} 让模型稳定输出可解析的 JSON
  • 会数 Token，知道上下文窗口还剩多少
  • 产出物：一个 /api/extract 接口，输入一段用户评价，输出 {"sentiment": "positive/negative", "keywords": [...]} 这样的结构化结果

# 2. 三种消息角色：system / user / assistant

OpenAI 兼容接口的 messages 数组里，每条消息有 role：

role 谁在说 放什么
system 你（开发者） 人设、规则、输出格式约束。每次请求都带，不要省
user 最终用户 用户的问题
assistant 模型自己 历史回复（多轮对话时用）
messages = [
    {"role": "system", "content": "你是一个客服助手，用中文简洁回答，不超过50字。"},
    {"role": "user", "content": "我的订单什么时候到？"},
]

system 和 user 的区别：user 的话模型可能会"顺着"（用户说"你就说不知道"它可能就照做），system 的话优先级更高，是你设定的硬规则。生产环境的输出格式、安全约束、角色定位全放 system。

【格式说明】

关键原则：

  • 具体 > 模糊。"语气友好"没用，"回答不超过50字、不用感叹号"才有用。
  • 反面约束要写："不要输出 JSON 以外的任何文字"比"请输出 JSON"管用。
  • 格式要求放最后，模型对最后看到的内容记忆最深。

# 4. Few-shot：给示例，比讲道理管用

光说规则模型可能不听话，给 1~3 个示例准确率立刻上升。这叫 Few-shot：

messages = [
    {"role": "system", "content": SYSTEM_PROMPT},
    # --- 示例开始 ---
    {"role": "user", "content": "这手机续航真垃圾，一天三充"},
    {"role": "assistant", "content": '{"sentiment": "negative", "keywords": ["续航差"]}'},
    {"role": "user", "content": "物流很快，包装完好，五星好评"},
    {"role": "assistant", "content": '{"sentiment": "positive", "keywords": ["物流快", "包装好"]}'},
    # --- 示例结束，下面是真实输入 ---
    {"role": "user", "content": "{}",   # 真实评论
]

# 5. CoT：让模型"先想后答"

对于需要推理的问题（数学、多步判断），直接问会答错。加一句"请一步步思考"或在 system 里要求先输出推理过程，准确率明显上升：

你是一个用户评论分析器。
请先在 thinking 字段里用一句话说明判断依据，再输出结果。
输出格式：
{"thinking": "...", "sentiment": "...", "keywords": [...]}

# 6. 结构化输出：强制 JSON（本篇重点）

光靠提示词约束，模型偶尔还是会输出"好的，这是结果：```json ... ```"这种带包装的内容，解析就崩了。

OpenAI 兼容接口提供 response_format 参数，告诉模型"你只能输出合法 JSON"：

resp = await client.chat.completions.create(
    model=settings.ollama_model,
    messages=messages,
    response_format={"type": "json_object"},   # 关键
)

# 6.1 完整接口：app/routers/prompt_demo.py

import json
from fastapi import APIRouter
from pydantic import BaseModel
from openai.types.chat import ChatCompletionMessageParam

from app.core.llm import client
from app.config import settings

router = APIRouter(prefix="/api", tags=["prompt"])

SYSTEM_PROMPT = """你是一个用户评论分析器。
规则：
1. 只输出 JSON，不要任何额外文字
2. sentiment 只能是 positive / negative / neutral 之一
3. keywords 最多 5 个，从原文提取
4. thinking 字段用一句话说明判断依据

输出格式：
{"thinking": "...", "sentiment": "...", "keywords": ["..."]}
"""

class ExtractRequest(BaseModel):
    text: str

@router.post("/extract")
async def extract(req: ExtractRequest):
    messages: list[ChatCompletionMessageParam] = [
        {"role": "system", "content": SYSTEM_PROMPT},
        # Few-shot 示例
        {"role": "user", "content": "续航真垃圾"},
        {"role": "assistant", "content": '{"thinking":"直接抱怨续航","sentiment":"negative","keywords":["续航差"]}'},
        {"role": "user", "content": "物流快，包装好"},
        {"role": "assistant", "content": '{"thinking":"夸奖物流和包装","sentiment":"positive","keywords":["物流快","包装好"]}'},
        # 真实输入
        {"role": "user", "content": req.text},
    ]
    resp = await client.chat.completions.create(
        model=settings.ollama_model,
        messages=messages,
        response_format={"type": "json_object"},
        temperature=0.0,   # 结构化任务用 0，减少随机性
    )
    content = resp.choices[0].message.content or "{}"
    try:
        return json.loads(content)
    except json.JSONDecodeError:
        return {"error": "模型输出了非法 JSON", "raw": content}

# 6.4 temperature：什么时候用什么值

值 效果 适合
0.0 几乎确定输出，每次差不多 结构化抽取、分类、Function Calling 参数
0.3~0.5 稳定但略有变化 客服问答
0.7~1.0 更有创意 写作、头脑风暴

铁律：凡是要被代码解析的输出（JSON、工具调用参数），一律 temperature=0。

# 7. Token 计数：上下文窗口还剩多少

大模型有上下文长度限制（qwen2.5:14b 通常 32k），system 提示 + Few-shot + 历史对话 + 用户输入都会占。超了就报错或截断。

# 7.1 用 Ollama 自带接口数

Ollama 有 /api/tokenize 接口：

import httpx

async def count_tokens(text: str) -> int:
    async with httpx.AsyncClient() as http:
        r = await http.post(
            f"{settings.ollama_host}/api/tokenize",
            json={"model": settings.ollama_model, "prompt": text},
        )
        return len(r.json()["tokens"])

# 7.2 什么时候要关心 Token

  • system 提示 + Few-shot：现在就应该数一下，别写着写着占了 2k token
  • 多轮对话（第 11 篇）：历史消息会累积，必须截断或摘要
  • RAG（第 9 篇）：检索回来的片段拼进上下文，不控制会爆

现在先知道"怎么数"，第 11 篇讲对话历史管理时会真正用到。

# 8. Prompt 调试心法

实际写 Prompt 的迭代循环：

  1. 先写 system 提示，跑 5~10 个真实 case
  2. 发现模型在某类输入上跑偏 → 加一条规则或一个 Few-shot 示例
  3. 发现输出格式偶尔坏 → 上 response_format
  4. 不要一次写一大段提示词，一次改一处，观察变化

不要追求"一劳永逸的万能提示词"。生产系统的 Prompt 是随着 badcase 一个个长出来的，和写代码一样要迭代。第 10 篇 RAG 评估会再讲这个。

# 9. 产出物验收清单

  • [ ] /api/extract 能返回合法 JSON，字段齐全
  • [ ] 故意输入一条中性评论，sentiment 不会乱猜
  • [ ] 模型输出不再带 markdown 代码块或"好的"等前缀
  • [ ] 能说出 system 和 user 的区别；为什么结构化任务要用 temperature=0
  • [ ] 会用 /api/tokenize 数 system 提示占了多少 token

# 10. 失败模式速查表

现象 原因 解法
模型输出带 ```json 代码块 | 没开 response_format，或提示词里写了"用markdown" | 加 response_format={"type":"json_object"}；提示词里明确"不要代码块"
JSON 解析偶尔失败 模型加了前缀/后缀文字 response_format + temperature=0 + 代码里 try/except 兜底
sentiment 乱猜 规则太模糊，或没给示例 加 Few-shot，明确枚举值
每次输出都不一样 temperature 太高 结构化任务降到 0.0~0.2
报 context length exceeded system + 历史 + 输入超了模型窗口 减少 Few-shot 数量；第 11 篇做历史截断
response_format 不生效 旧版 Ollama 或模型不支持 升级 Ollama；部分小模型对 json mode 支持不好，换 qwen2.5 系列
模型不听 system 提示 system 放错位置/和 user 混淆 system 必须是 messages 第一条
中文输出乱码 没加 ensure_ascii=False 返回 JSON 时 json.dumps(..., ensure_ascii=False)（02 篇已踩过）
