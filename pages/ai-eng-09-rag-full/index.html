09.RAG完整实战

# 09. RAG 完整实战（项目 2）

系列第 9 篇，项目 2。前 8 篇把零件都做好了：能解析文档（08）、能切分（05）、能存向量（06）、能搜片段（07）。这一篇把它们和 LLM 接起来——用户问一个问题，系统先从知识库里找相关片段，再让 LLM 基于这些片段生成带引用的回答。 这就是 RAG（Retrieval-Augmented Generation）。

# 1. 学习目标

  • 说清楚 RAG 的完整流程：问题 → 检索 → 拼 prompt → 生成 → 引用
  • 实现 /api/rag/ask 接口：输入问题，输出带引用来源的回答
  • 实现混合检索：向量检索（语义）+ BM25（关键词）互补
  • 了解重排（rerank）：把初筛的 N 条精排成最相关的 K 条
  • 处理"检索不到相关内容"的情况，不让 LLM 胡说
  • 产出物：问一个你上传过文档里的问题，回答末尾带 [来源：xxx.pdf 第N段]

# 3. 基础版 RAG：先跑通

# 3.1 prompt 模板

RAG 的 system prompt 核心结构：

你是一个知识库问答助手。请严格根据下面提供的参考资料回答用户问题。

规则：
1. 只根据 &lt;context> 里的资料回答，不要编造
2. 如果资料里没有相关信息，直接说"根据现有资料无法回答这个问题"
3. 回答末尾用 [1]、[2] 标注引用了哪条资料

&lt;context>
[1] 来源：售后政策.md
退货政策：用户在签收商品后7天内可以申请退货...

[2] 来源：发票说明.pdf
发票申请后3个工作日内开具...
&lt;/context>

# 3.2 service 层：app/services/rag_service.py

import logging

from app.services.search_service import search_documents
from app.core.llm import call_llm
from openai.types.chat import ChatCompletionMessageParam

from app.core.bm25_index import search as bm25_search 

logger = logging.getLogger(__name__)

SYSTEM_TEMPLATE = """你是一个知识库问答助手。请严格根据下面提供的参考资料回答用户问题。

规则：
1. 只根据 <context> 里的资料回答，不要编造
2. 如果资料里没有相关信息，直接说"根据现有资料无法回答这个问题"
3. 回答末尾用 [1]、[2] 标注引用了哪条资料

<context>
{context}
</context>
"""

# 检索不到结果时的兜底
NO_ANSWER = "根据现有资料无法回答这个问题。"


def _build_context(hits: list[dict]) -> str:
    """把检索结果拼成带编号的 context。"""
    parts = []
    for i, hit in enumerate(hits, 1):
        source = hit["metadata"].get("source", "unknown")
        parts.append(f"[{i}] 来源：{source}\n{hit['text']}")
    return "\n\n".join(parts)


async def ask(
    collection: str,
    question: str,
    top_k: int = 5,
    score_threshold: float = 0.3,
) -> dict:
    """RAG 主流程。"""
    # 1. 向量检索 + 按阈值过滤
    vector_hits = await search_documents(collection, question, top_k=top_k)
    vector_hits = [h for h in vector_hits if h["score"] >= score_threshold]

    # 2. BM25 检索（关键词精确命中，不过滤，直接保留）
    bm25_texts = bm25_search(collection, question, top_k=top_k)

    # 3. 合并去重：向量结果优先，BM25 补充未命中的
    seen = set()
    hits = []
    for h in vector_hits:
        if h["text"] not in seen:
            seen.add(h["text"])
            hits.append(h)
    for text in bm25_texts:
        if text not in seen:
            seen.add(text)
            hits.append({"text": text, "metadata": {}, "score": 0.5, "source": "bm25"})

    if not hits:
        return {
            "answer": NO_ANSWER,
            "sources": [],
            "retrieved": 0,
        }

    # 3. 拼 prompt
    context = _build_context(hits)
    system = SYSTEM_TEMPLATE.format(context=context)
    messages: list[ChatCompletionMessageParam] = [
        {"role": "system", "content": system},
        {"role": "user", "content": question},
    ]

    # 4. 调 LLM（结构化/事实型回答用低 temperature）
    answer = await call_llm(messages=messages, temperature=0.1)

    return {
        "answer": answer,
        "sources": [
            {
                "index": i + 1,
                "source": h["metadata"].get("source"),
                "score": h["score"],
                "text": h["text"],          # 第 10 篇评估脚本需要 context 文本
            }
            for i, h in enumerate(hits)
        ],
        "retrieved": len(hits),
    }

from fastapi import APIRouter, HTTPException
from pydantic import BaseModel

from app.services.rag_service import ask

router = APIRouter(prefix="/api/rag", tags=["rag"])

class AskRequest(BaseModel):
    collection: str
    question: str
    top_k: int = 5
    score_threshold: float = 0.3

@router.post("/ask")
async def ask_endpoint(req: AskRequest):
    if not req.question.strip():
        raise HTTPException(status_code=422, detail="question 不能为空")
    return await ask(req.collection, req.question, req.top_k, req.score_threshold)

# 4. 混合检索：向量 + BM25

纯向量检索有个短板：关键词精确匹配不行。比如文档里写"SKU-12345"，用户搜"12345"，向量可能觉得"12345"和"SKU-12345"语义不接近（数字太短没有语义），但 BM25（关键词匹配）能精确命中。

# 4.1 装依赖

uv add rank_bm25 jieba
1
包 作用

jieba 中文分词，比按字切准确，对英文/编号也友好

# 4.2 独立 BM25 模块

为什么不放在 rag_service 里？ BM25 索引在入库时就要建（search_service），检索时也要用（rag_service）。放其中一个会造成循环导入。拆到独立模块 app/core/bm25_index.py，两边都引，干净。

新建 app/core/bm25_index.py：

import logging
import jieba
from rank_bm25 import BM25Okapi

logger = logging.getLogger(__name__)

# 内存版 BM25 索引：{collection: (bm25, corpus_texts)}
_indexes: dict[str, tuple[BM25Okapi, list[str]]] = {}


def warmup():
    """在 FastAPI 启动时调用，提前加载 jieba 字典（1~3 秒）。"""
    jieba.initialize()
    logger.info("jieba dict loaded")


def _tokenize(text: str) -> list[str]:
    """jieba 分词。比 list(text) 按字切准，SKU-12345 会当成一个词。"""
    return list(jieba.cut_for_search(text))


def add_texts(collection: str, texts: list[str]):
    """
    入库时调用：把新文本加入 BM25 索引。
    ⚠️ 学习阶段每批全量重建（O(n) 次分词 × n 条历史文本 = O(n²)），
    文档量小没问题；生产环境用 ES，增量索引自动维护，不会全量重建。
    """
    if not texts:
        return
    old_texts = _indexes.get(collection, (None, []))[1]
    all_texts = old_texts + texts
    tokenized = [_tokenize(t) for t in all_texts]
    _indexes[collection] = (BM25Okapi(tokenized), all_texts)
    logger.info("BM25 index '%s': %d docs", collection, len(all_texts))


def search(collection: str, query: str, top_k: int = 5) -> list[str]:
    """BM25 关键词搜索，返回文本列表。索引不存在返回空。"""
    entry = _indexes.get(collection)
    if not entry:
        return []
    bm25, corpus = entry
    scores = bm25.get_scores(_tokenize(query))
    top_indices = scores.argsort()[-top_k:][::-1]
    return [corpus[i] for i in top_indices]

# 4.4 合并两路结果（已整合进 ask()）

主函数里的合并逻辑见第 3.2 节。关键设计决策：

  • 向量结果过 score_threshold：向量分数低说明语义不相关，过滤掉。
  • BM25 结果不过滤：BM25 是关键词精确命中，能命中说明 query 词就在文档里，直接保留，给一个中性分数 0.5。
  • 去重：同一段文本如果两路都搜到，只保留向量那一路（分数更可靠）。

⚠️ 曾经踩过的坑：早期版本给 BM25 结果硬编码 score=0.1，结果被 score_threshold=0.3 全过滤掉，混合检索形同虚设。BM25 是精确命中，不能用语义相似度的阈值卡它。

混合检索的价值：

  • 语义问题（"怎么退钱"）→ 向量检索命中
  • 精确关键词（"SKU-12345"、"订单号 88023"）→ BM25 命中
  • 两路互补，召回率明显提升

# 5. 重排（Rerank）：为什么和怎么做

# 5.1 问题

向量检索快但粗糙——它找"语义接近"的，不一定是"最相关"的。比如用户问"退货条件"，向量检索可能把"退货流程"排第一，但其实"退货条件"才是直接答案。

# 5.2 重排的思路

检索阶段粗筛 top_k=20 条（快，可能漏），然后用一个更强的模型对这 20 条两两打分，精排出 top_n=5 条（慢但准）。

# 5.3 学习阶段怎么做

生产用 bge-reranker-v2-m3 或 Cohere Rerank。学习阶段可以先不接重排模型，在代码里留接口：

def rerank(question: str, hits: list[dict], top_n: int = 5) -> list[dict]:
    """
    重排：对初筛结果重新打分。
    ⚠️ 学习阶段这里什么都没做，只是截断到前 top_n。
    接入真正的 bge-reranker 模型才会重新打分排序。
    """
    return hits[:top_n]

# 6. 关键设计决策

决策 做法 原因
score_threshold 默认 0.3 低于这个分的片段不送给 LLM，防止干扰
temperature 0.1 事实型回答要稳定，不要创意
无结果时 直接返回兜底话术 不让 LLM 基于空 context 编造
引用标注 [1][2] 对应 sources 数组 用户能追溯到原文

# 7. 产出物验收清单

  • [ ] 问知识库里有的问题，回答基于文档内容
  • [ ] 问知识库里没有的问题，返回"无法回答"而不是瞎编
  • [ ] 回答末尾带 [1] 标注，sources 数组里能对应到文件
  • [ ] score_threshold 调到 0.8，明显不相关的片段被过滤
  • [ ] 能说清楚 RAG 四步流程、混合检索补了什么短板、重排在哪个环节

# 8. 失败模式速查表

现象 原因 解法
LLM 编造知识库里没有的内容 没加"只根据 context 回答"的约束 检查 system prompt；加 score_threshold 过滤低分片段
回答不带引用 prompt 里没要求标注来源 在 SYSTEM_TEMPLATE 里明确要求 [1][2]
检索到了但回答没用到 context 太长被截断，或 prompt 模板格式错 检查 context 拼接；减少 top_k
数字/编号搜不到 纯向量检索对短数字不敏感 加 BM25 混合检索
BM25 命中了但 RAG 结果里没有 BM25 结果被 score_threshold 过滤掉了 向量结果才过阈值，BM25 结果直接保留
回答总是"无法回答" score_threshold 太高 从 0.3 开始试，逐步调高
引用和对不上 sources 数组顺序和 [1][2] 编号不一致 _build_context 和 sources 必须用同一个 enumerate
中文回答带奇怪英文 模型默认输出语言 system prompt 里加"用中文回答"
回答太慢 top_k 太大，context 太长 减少 top_k；第 10 篇做上下文压缩
