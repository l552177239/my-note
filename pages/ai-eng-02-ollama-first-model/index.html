02.Ollama本地模型跑通

# 02. Ollama 本地模型跑通

系列第 2 篇。在 01 篇的 FastAPI 骨架上接进第一个本地大模型：装 Ollama → 拉 qwen2.5:14b → Chatbox 图形化对话 → 用 openai SDK 调用 → 在 FastAPI 里实现 /api/chat SSE 流式输出。 这是全系列第一个"能说话"的里程碑，先让模型跑起来，再谈工程。

# 1. 学习目标

  • 装通 Ollama，用 qwen2.5:14b-instruct-q4_K_M（9.0 GB）跑起本地模型
  • 用 Chatbox 客户端图形化调用本地模型，不写代码先看到效果
  • 用 openai SDK 调 Ollama（Ollama 兼容 OpenAI 接口），理解 base_url 怎么配
  • 在 FastAPI 里实现两个接口：非流式 /api/chat、SSE 流式 /api/chat/stream
  • 说出"为什么流式输出对聊天体验是必须的"
  • 产出物：浏览器 /docs 里能流式对话；curl 能逐字收到 token

# 2. 装 Ollama 并拉模型

# 2.1 安装

官网下载：https://ollama.com/download (opens new window)（macOS / Windows / Linux 都有安装包）。装完后它常驻后台，监听 http://127.0.0.1:11434。

验证：

curl http://127.0.0.1:11434/api/version
# {"version":"0.x.x"}
1
2

# 2.2 拉模型（本篇用这个）

ollama pull qwen2.5:14b-instruct-q4_K_M
1
项 值
模型名 qwen2.5:14b-instruct-q4_K_M
大小 9.0 GB
量化 Q4_K_M（4-bit，显存/内存占用和效果的折中）
最低要求 16 GB 内存（CPU 跑）或 8 GB 显存（GPU 跑）

为什么选 14B 而不是 7B / 32B？ 7B 适合开发调试（秒级响应），32B 效果好但慢；14B Q4 在普通开发机上已经能做工具调用、长上下文，是"学习+小项目"的甜点尺寸。跑不动就换 qwen2.5:7b，API 调用方式完全一样。

# 2.3 命令行先聊一句

ollama run qwen2.5:14b-instruct-q4_K_M
>>> 用一句话介绍你自己

# 3. 用 Chatbox 图形化调用（先看到效果）

不写代码，先用桌面客户端连上本地 Ollama，建立正反馈。

# 3.1 装 Chatbox

下载：https://chatboxai.app (opens new window)（macOS / Windows / Linux）。

# 3.2 配置 Ollama 渠道

Chatbox → 设置 → 模型提供方，选 Ollama：

配置项 值
Provider Ollama
API Host http://127.0.0.1:11434
Model qwen2.5:14b-instruct-q4_K_M

保存后新建对话，问一句"用 Python 写个快速排序"。能正常流式吐字就通了。

# 3.3 这一步在学什么

Chatbox 本质就是个前端，它做的事情：

  1. 启动时调 GET http://127.0.0.1:11434/api/tags 拉模型列表
  2. 发消息时调 POST http://127.0.0.1:11434/api/chat，stream: true
  3. 逐 token 渲染到界面

第 16 篇我们用 React + TS 自己重写这一套，现在先把 Chatbox 当参照实现，知道最终效果长什么样。

# 4. 在 Python 里调 Ollama

Ollama 同时提供两套 API：

  • 原生 API：POST /api/chat（Ollama 私有格式）
  • OpenAI 兼容 API：POST /v1/chat/completions ← 本篇用这个

用 OpenAI 兼容接口的好处：第 3 篇换 OpenAI / DeepSeek / 任何兼容厂商时，只改 base_url 和 api_key，业务代码零改动。

# 4.3 封装一个客户端单例

新建 app/core/llm.py：

from openai import AsyncOpenAI
from openai.types.chat import ChatCompletionMessageParam
from app.config import settings

client = AsyncOpenAI(
    base_url=f"{settings.ollama_host}/v1",
    api_key="ollama",
)

async def chat(messages: list[ChatCompletionMessageParam]) -> str:
    """非流式：一次性返回完整回复"""
    resp = await client.chat.completions.create(
        model=settings.ollama_model,
        messages=messages,
    )
    return resp.choices[0].message.content or ""

# 5. FastAPI 里实现聊天接口

# 5.1 新建路由 app/routers/chat.py

from fastapi import APIRouter
from pydantic import BaseModel
from openai import AsyncOpenAI

from app.config import settings
from app.core.llm import client

router = APIRouter(prefix="/api", tags=["chat"])

class ChatRequest(BaseModel):
    message: str

# ---------- 5.1.1 非流式：简单粗暴 ----------
@router.post("/chat")
async def chat(req: ChatRequest):
    reply = await client.chat.completions.create(
        model=settings.ollama_model,
        messages=[{"role": "user", "content": req.message}],
    )
    return {"reply": reply.choices[0].message.content}


# ---------- 5.1.2 SSE 流式：逐 token 吐出 ----------
from fastapi.responses import StreamingResponse
import json

@router.post("/chat/stream")
async def chat_stream(req: ChatRequest):
    async def event_generator():
        stream = await client.chat.completions.create(
            model=settings.ollama_model,
            messages=[{"role": "user", "content": req.message}],
            stream=True,
        )
        async for chunk in stream:
            delta = chunk.choices[0].delta.content or ""
            # SSE 格式：data: {...}\n\n
            yield f"data: {json.dumps({'delta': delta}, ensure_ascii=False)}\n\n"
        # 结束标记
        yield f"data: {json.dumps({'done': True})}\n\n"

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",   # 关闭 nginx 缓冲，第 18 篇部署要用
        },
    )

# 6. 为什么必须流式

维度 非流式 流式
用户感知 等 3~10 秒，像卡住 100ms 内开始出字
首 token 时间（TTFT） = 总时长 通常 < 500ms
长回答体验 越长越像死了 边想边写，像人说话
取消能力 做不到 用户想停就能停

14B 模型生成长回答要好几秒，非流式在聊天场景里是不可接受的。从这一篇起，所有对话接口默认走 SSE。

# 9. 失败模式速查表

现象 原因 解法
Connection refused 11434 Ollama 没启动 确认 Ollama 应用在跑，curl http://127.0.0.1:11434/api/version 通
model not found 模型没拉下来或名字拼错 ollama list 看实际名字；注意 tag 大小写，是 q4_K_M 不是 q4_k_m
Chatbox 连不上 API Host 填错或 Ollama 只监听了 localhost Host 填 http://127.0.0.1:11434，别带尾斜杠
流式 curl 卡住，不逐字出 curl 没加 -N，或没关 nginx 缓冲 加 -N；生产环境反向代理要关 proxy_buffering
流式只出一整块就结束 忘了 stream=True，或把整个生成结果塞进一个 chunk 检查 .create(..., stream=True) 和 async for chunk in stream
OpenAI SDK 报 401 Ollama 不校验 key 但 SDK 要求非空 api_key="ollama" 随便填一个非空字符串
响应特别慢（>10s） 14B 在 CPU 上跑，没走 GPU ollama ps 看是不是 GPU；没 GPU 就换 qwen2.5:7b
中文回复乱码 SSE 没加 ensure_ascii=False json.dumps(..., ensure_ascii=False)
