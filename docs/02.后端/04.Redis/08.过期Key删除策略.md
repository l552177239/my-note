# Redis 过期 Key 删除策略

Redis Key 过期后**不会立刻全部删除**，而是采用「**惰性删除 + 定期删除**」组合策略，在 CPU 与内存之间做权衡。

<!-- more -->

## 1. 为什么不立刻删除

若每个 Key 到期都精确触发删除：

- 大量定时器 / 事件开销大
- 到期高峰可能拖垮 CPU

因此 Redis 选择更 pragmatic 的组合方案。

---

## 2. 惰性删除（主力）

**访问 Key 时**才判断是否过期；若已过期，立刻删除并当作不存在处理。

| 优点 | 缺点 |
|------|------|
| 节省 CPU，不做无意义扫描 | 冷门过期 Key 可能长期占用内存 |

```
GET key
  → Key 存在？
  → 已过期？ → 删除并返回空
  → 未过期 → 返回值
```

---

## 3. 定期删除（兜底）

Redis **定时随机抽样**带过期时间的 Key，批量清理，释放内存。

作用：弥补惰性删除留下的「垃圾数据」，避免内存被大量冷门过期 Key 占满。

特点：

- 抽样而非全量扫描，控制 CPU 成本
- 不能保证「一过期立刻删干净」
- 与惰性删除互补

---

## 4. 总结

| 策略 | 角色 |
|------|------|
| 惰性删除 | 主力：访问时清理 |
| 定期删除 | 兜底：后台抽样清理 |

一句话：**惰性删除为主，定期删除为辅，兼顾性能与内存利用率。**

若内存仍持续上涨，再结合 [内存淘汰机制](/pages/redis-eviction/)（如 `allkeys-lru`）兜底。
