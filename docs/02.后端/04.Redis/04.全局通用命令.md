# Redis 全局通用命令

不区分数据类型，对所有 Key 生效的通用命令。日常运维与排查时最常用。

<!-- more -->

## 1. 命令一览

| 命令 | 作用 | 注意 |
|------|------|------|
| `KEYS *` | 查询所有 Key | **生产禁止**，会阻塞 |
| `EXISTS key` | 判断 Key 是否存在 | 返回 1/0 |
| `DEL key` | 删除 Key | 可删多个 |
| `EXPIRE key seconds` | 设置过期时间（秒） | 到期后按删除策略清理 |
| `TTL key` | 查看剩余过期时间 | -1 永不过期；-2 不存在 |
| `PERSIST key` | 移除过期时间 | 变为永久 Key |
| `TYPE key` | 查看 Value 数据类型 | string/hash/list/set/zset |
| `RENAME key newkey` | 重命名 Key | newkey 已存在会被覆盖 |
| `FLUSHDB` | 清空当前库 | 危险操作 |
| `FLUSHALL` | 清空所有库 | 更危险 |

---

## 2. 常用示例

```bash
SET demo:name redis                    # 写入示例 Key
EXISTS demo:name                       # 是否存在 → 1
TYPE demo:name                         # 类型 → string
EXPIRE demo:name 60                    # 60 秒后过期
TTL demo:name                          # 查看剩余 TTL（秒）
PERSIST demo:name                      # 移除过期，变为永久 Key
RENAME demo:name demo:nickname         # 重命名 Key
DEL demo:nickname                      # 删除 Key
```

## 3. 生产注意事项

### 3.1 不要用 KEYS

`KEYS` 会扫描全库并阻塞单线程，Key 多时可能导致 Redis 卡顿。

生产替代：

- 使用 `SCAN` 游标渐进式扫描
- 业务侧维护明确的 Key 命名与索引集合

```bash
# 渐进扫描：从游标 0 开始，匹配 user:*，每批约 100 个
SCAN 0 MATCH user:* COUNT 100
```

### 3.2 慎用 FLUSHDB / FLUSHALL

清空命令不可恢复（除非有备份）。建议：

- 生产账号禁用或严格鉴权
- 清理数据优先用明确的 `DEL` / 业务过期策略

### 3.3 Key 命名建议

统一前缀，便于管理与排查：

```
业务:模块:标识
user:1001:profile
order:lock:20260908001
limit:api:user:1001
```

## 4. 与数据类型命令的关系

- 通用命令：管 **Key 本身**（存在、过期、类型、删除）
- 类型命令：管 **Value 内容**（`GET`/`HSET`/`LPUSH`/`ZADD` 等）
