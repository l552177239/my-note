# Redis 核心基本原理

本文说明 Redis 为何能做到高吞吐：单线程模型、内存存储结构，以及一条命令从客户端到返回的执行路径。

<!-- more -->

## 1. 单线程模型

Redis 核心读写采用**单线程**处理命令。瓶颈通常不在 CPU，而在：

- 避免多线程竞争锁、上下文切换开销
- 内存操作速度远快于网络 IO
- 所有命令串行执行，天然保证**单命令原子性**

> Redis 6.0+ 引入多线程处理**网络 IO**，核心命令执行依旧是单线程。

简化理解：

```
多个客户端并发请求
        ↓
   IO 多路复用（epoll 等）
        ↓
   单线程命令队列串行执行
        ↓
   依次返回结果
```

---

## 2. 内存存储结构

底层基于**字典（HashTable）** 存储所有 Key-Value，支持高效增删改查；所有数据默认驻留内存。

要点：

- Key 全局唯一（同一 DB 内）
- Value 可对应不同编码与数据结构（String、Hash、List 等）
- 内存有限，需要配合过期策略与淘汰策略（见后续章节）

---

## 3. 命令执行流程

一条典型命令的路径：

```
客户端发送命令
    → 网络层接收
    → 命令解析
    → 单线程执行
    → 返回结果
```

面试常问对照：

| 问题 | 要点 |
|------|------|
| 为什么单线程还快？ | 内存操作 + 无锁 + IO 多路复用 |
| 6.0 多线程改了什么？ | 主要加速网络读写，命令执行仍单线程 |
| 单命令原子性从哪来？ | 串行执行，执行期间不被打断 |
