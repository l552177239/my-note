# Redis 概述

本文介绍 Redis 是什么、核心特点，以及适合与不适合的使用场景，作为后续原理与实战章节的入口。

<!-- more -->

## 1. 什么是 Redis

**Redis（Remote Dictionary Server）** 是一款开源、高性能、基于内存的键值（Key-Value）数据库，常被用作缓存、中间件、分布式锁、限流计数器、消息队列等场景。

Redis 区别于 MySQL 等关系型数据库：数据主要存在内存中，读写速度极快，同时支持持久化落地磁盘，兼顾高性能与数据可靠性。

| 对比项 | Redis | MySQL |
|--------|-------|-------|
| 存储位置 | 内存为主 | 磁盘为主 |
| 数据模型 | Key-Value（多种结构） | 关系表 |
| 典型用途 | 缓存、锁、计数、排行榜 | 持久业务数据 |
| 查询能力 | 按 Key / 结构命令 | SQL 关联查询 |
| 速度 | 极高（内存） | 相对较慢（磁盘 IO） |

---

## 2. 核心特点

- **高性能**：单线程模型、内存操作，QPS 可达 10W+
- **多数据类型**：不止 String，支持 List、Set、Hash、ZSet 等
- **持久化**：支持 RDB、AOF 两种持久化方案，降低断电丢数据风险
- **原子操作**：单条命令原子性，事务支持批量串行执行
- **高可用**：主从复制、哨兵、集群模式
- **丰富场景**：缓存、限流、分布式锁、会话存储、排行榜、计数器

---

## 3. 适用 / 不适用场景

### 3.1 适合

- 热点高频读写（接口缓存、热点商品）
- 临时数据、会话 Session
- 计数器、限流、防刷
- 分布式锁
- 排行榜、延迟队列雏形

### 3.2 不适合

- 海量冷数据长期存储（成本高）
- 强一致性复杂事务（弱于关系库 ACID）
- 复杂多表关联查询

> 选型直觉：需要「快 + 简单结构 + 可丢一点也能接受或可重建」时优先 Redis；需要「强一致 + 复杂查询 + 长期归档」时优先 MySQL。
