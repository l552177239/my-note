# Redis 事务

Redis 事务是批量命令打包、一次性串行执行，**无回滚、无锁竞争**。面试常考其与 MySQL 事务的差异。

<!-- more -->

## 1. 事务原理

核心流程：

```
开启事务 → 命令入队 → 执行 / 放弃
```

特点：

- 事务内命令先入队，不立刻执行
- `EXEC` 时按入队顺序一次性串行执行
- 执行期间不会被其他客户端命令插队

---

## 2. 核心命令

| 命令 | 作用 |
|------|------|
| `MULTI` | 开启事务 |
| `EXEC` | 执行事务队列中所有命令 |
| `DISCARD` | 放弃事务，清空队列 |
| `WATCH key` | 乐观锁监听 Key，若变动则事务失败 |

### 2.1 基本用法

```bash
MULTI              # 开启事务，后续命令入队
SET a 1            # 入队：设置 a=1
INCR b             # 入队：b 自增
EXEC               # 按入队顺序一次性执行
```

### 2.2 放弃事务

```bash
MULTI              # 开启事务
SET a 1            # 入队
DISCARD            # 放弃事务，队列作废，不执行
```

### 2.3 WATCH 乐观锁

```bash
WATCH balance              # 监听 balance，被改则事务失败
MULTI                      # 开启事务
DECRBY balance 100         # 入队：余额减 100
INCRBY expense 100         # 入队：支出加 100
EXEC                       # 执行；若被改过则返回 nil
# 若 EXEC 前 balance 被其他客户端修改，则 EXEC 返回 nil，事务失败
```
---

## 3. 事务特性（面试重点）

### 3.1 不支持回滚

| 错误类型 | 行为 |
|----------|------|
| **语法错误**（入队阶段） | 整队不执行 |
| **运行时错误**（如对 String 做 List 操作） | 错误命令失败，**其余继续执行** |

因此 Redis 事务不是「要么全成功要么全失败」的强事务。

### 3.2 串行执行

事务内命令不会被其他客户端插队，保证批量命令的隔离执行顺序。

### 3.3 弱事务

- 不满足完整 MySQL **ACID**
- 主要保证：打包入队 + 串行执行 +（可选）WATCH 乐观锁
- 需要复杂回滚与强一致时，应放到业务层或关系型数据库

---

## 4. 与 MySQL 事务对比

| 维度 | Redis 事务 | MySQL 事务 |
|------|------------|------------|
| 回滚 | 不支持 | 支持 |
| 隔离 | 串行执行命令 | 多种隔离级别 |
| 原子性 | 单命令原子；批量弱原子 | 强事务语义更好 |
| 典型用途 | 批量命令、简单乐观锁 | 资金、订单等强一致 |

---

## 5. 小结

- `MULTI` / `EXEC`：批量串行
- `WATCH`：乐观锁防并发覆盖
- 不要把 Redis 事务当成银行转账级强事务方案
