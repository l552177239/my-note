# Redis 内存淘汰机制

当 Redis 内存达到上限后，会根据配置的策略自动删除部分 Key，释放内存，避免写失败或服务不可用。

<!-- more -->

## 1. 何时触发

配置了 `maxmemory`，且当前内存占用达到上限时，新写入可能触发淘汰。

```
写入请求 → 内存已满？ → 按策略淘汰 Key → 再写入
                      → 若策略不允许淘汰 → 返回错误
```

---

## 2. 六大淘汰策略

| 策略 | 作用范围 | 淘汰规则 | 说明 |
|------|----------|----------|------|
| `noeviction` | — | 不淘汰 | **默认**；内存满直接报错 |
| `allkeys-lru` | 所有 Key | LRU | 淘汰最近最少使用；**缓存最常用** |
| `volatile-lru` | 仅带过期时间的 Key | LRU | 未设过期的 Key 不淘汰 |
| `allkeys-random` | 所有 Key | 随机 | 简单但命中率不稳定 |
| `volatile-random` | 仅过期 Key | 随机 | 同上，范围更小 |
| `volatile-ttl` | 仅过期 Key | TTL | 优先删更临近过期的 Key |

> LRU：Least Recently Used，最近最少使用。

补充：较新版本还有 LFU（Least Frequently Used，最少频率使用）相关策略，原理类似「按热度淘汰」，面试若问到可一并提及。

---

## 3. 选型建议

| 场景 | 推荐 |
|------|------|
| 通用缓存（绝大多数业务） | `allkeys-lru` |
| 只有部分 Key 允许被踢，其余必须常驻 | `volatile-lru` / `volatile-ttl` |
| 绝不自动删数据，宁可写失败 | `noeviction`（配合扩容与告警） |

---

## 4. 与过期删除的区别

| 机制 | 目的 | 触发时机 |
|------|------|----------|
| **过期删除** | Key 到点失效 | 惰性访问 / 定期抽样 |
| **内存淘汰** | 内存不够了腾地方 | 达到 `maxmemory` |

两者可同时存在：先有过期时间管理生命周期，内存紧张时再按淘汰策略强制腾挪。
