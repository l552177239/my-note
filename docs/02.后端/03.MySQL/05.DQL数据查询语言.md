# DQL 数据查询语言（核心）

DQL 以 `SELECT` 为核心，覆盖条件过滤、排序、聚合、分组、分页、连接与子查询。表名以 [经典示例数据](/pages/mysql-examples/) 为准；连接进阶见 [多表联查](/pages/mysql-multi-join/)。

<!-- more -->

## 0. SQL 运行原理（逻辑执行顺序）

你**写** SQL 的顺序，和引擎**逻辑上**处理的顺序不一样。先搞清这条流水线，后面 `WHERE` / `HAVING` / 别名能不能用，就都说得通。

（概述里有简表，见 [SQL概述 - SELECT 逻辑执行顺序](/pages/mysql-basic/#5-select-逻辑执行顺序)；本节讲清「为什么」和常用规则。）

### 0.1 流水线

```text
① FROM / JOIN   → 先拿出（连接后的）行集合
② WHERE         → 按「行」过滤（此时还没有分组，也还没有 SELECT 别名）
③ GROUP BY      → 把行分成若干组
④ HAVING        → 按「组」过滤（这时才有聚合结果）
⑤ SELECT        → 算出要输出的列、别名、聚合函数
⑥ ORDER BY      → 排序（通常可用 SELECT 别名）
⑦ LIMIT         → 截取最终结果集的一部分
```

对应书写模板：

```sql
SELECT   列 | 表达式 | 聚合函数   -- ⑤
FROM     表
JOIN     表 ON 连接条件           -- ①
WHERE    行级条件                 -- ②
GROUP BY 分组列                   -- ③
HAVING   分组后条件               -- ④
ORDER BY 排序列                   -- ⑥
LIMIT    偏移, 条数;              -- ⑦
```

### 0.2 核心规则（由执行顺序推导）

| 规则 | 原因 |
|------|------|
| `WHERE` **不能**使用聚合函数（`COUNT` / `SUM` / `AVG` 等） | `WHERE` 在 `GROUP BY` **之前**，聚合结果还不存在 |
| 过滤「分组后的结果」必须用 `HAVING` | 聚合发生在分组之后，只有 `HAVING`（及之后的 `SELECT`）能看到 |
| `WHERE` **不能**使用 `SELECT` 里新起的别名 | `WHERE` 早于 `SELECT`，别名尚未产生 |
| `ORDER BY` 一般**可以**用 `SELECT` 别名 | 排序在 `SELECT` 之后 |
| `GROUP BY` 之外的非聚合列，一般不能单独出现在 `SELECT` | 一组多行时，该列取值不唯一（MySQL 在关闭 `ONLY_FULL_GROUP_BY` 时可能「随便取一个」，生产应避免） |

### 0.3 一眼看懂：先滤行，再分组

```sql
-- 目标：各部门「薪资 > 8000」的人数（先丢掉低薪行，再按部门数）
SELECT dept_id, COUNT(*) AS 高薪人数
FROM employees
WHERE salary > 8000          -- ② 先按行过滤
GROUP BY dept_id;            -- ③ 再分组聚合

-- ❌ 错误：想在 WHERE 里写聚合 → 语法/语义都不成立
-- SELECT dept_id, COUNT(*) FROM employees
-- WHERE COUNT(*) > 2          -- 分组前没有 COUNT(*)
-- GROUP BY dept_id;

-- ✅ 正确：对「组」设门槛用 HAVING
SELECT dept_id, COUNT(*) AS 人数
FROM employees
GROUP BY dept_id
HAVING COUNT(*) >= 2;        -- ④ 分组后才有 COUNT(*)
```

## 1. 基础查询

```sql
-- 查询所有列（生产环境慎用 SELECT *）
SELECT * FROM employees;

-- 查询指定列
SELECT name, salary FROM employees;

-- 去重
SELECT DISTINCT dept_id FROM employees;

-- 别名
SELECT 
    name AS 姓名,
    salary * 12 AS 年薪
FROM employees;

-- 常量列
SELECT name, '正式员工' AS 员工类型 FROM employees;

-- CASE WHEN 条件表达式
SELECT 
    name,
    salary,
    CASE 
        WHEN salary >= 15000 THEN '高'
        WHEN salary >= 10000 THEN '中'
        ELSE '低'
    END AS 薪资等级
FROM employees;
```

## 2. WHERE 条件过滤

`WHERE` 作用在**每一行原始数据**上，发生在分组之前（见第 0 节）。因此：

- 只能写**行级**条件：列与常量比较、`AND` / `OR`、`IN`、`LIKE`、`IS NULL` 等
- **禁止**写聚合：`WHERE COUNT(*) > 1`、`WHERE AVG(salary) > 8000` 都不合法
- **禁止**引用本查询 `SELECT` 里的别名（可用表达式重复写一遍，或包一层子查询）

```sql
-- 比较运算符
SELECT * FROM employees WHERE salary > 10000;
SELECT * FROM employees WHERE age <> 25;        -- != 也可以
SELECT * FROM employees WHERE salary BETWEEN 5000 AND 10000;

-- 逻辑运算符（AND 优先级高于 OR，拿不准就加括号）
SELECT * FROM employees WHERE age > 25 AND salary > 8000;
SELECT * FROM employees WHERE dept_id = 1 OR dept_id = 2;
SELECT * FROM employees WHERE NOT gender = 'M';

-- IN / NOT IN
SELECT * FROM employees WHERE dept_id IN (1, 2, 3);
SELECT * FROM employees WHERE dept_id NOT IN (4, 5);

-- LIKE 模糊查询
SELECT * FROM employees WHERE name LIKE '张%';     -- 张开头
SELECT * FROM employees WHERE name LIKE '%三';     -- 三结尾
SELECT * FROM employees WHERE name LIKE '%伟%';    -- 包含伟
SELECT * FROM employees WHERE name LIKE '李_';     -- 李+任意一个字符

-- NULL 判断（不能用 = / !=）
SELECT * FROM employees WHERE manager_id IS NULL;
SELECT * FROM employees WHERE manager_id IS NOT NULL;
-- SELECT * FROM employees WHERE manager_id = NULL;  -- ❌ 永远得不到行

-- ❌ WHERE 不能用聚合 / 不能用 SELECT 别名
-- SELECT name, salary * 12 AS 年薪 FROM employees WHERE 年薪 > 100000;
-- SELECT dept_id FROM employees WHERE AVG(salary) > 10000;

-- ✅ 别名：把表达式写进 WHERE，或包一层
SELECT name, salary * 12 AS 年薪
FROM employees
WHERE salary * 12 > 100000;

SELECT * FROM (
    SELECT name, salary * 12 AS 年薪 FROM employees
) t
WHERE t.年薪 > 100000;

-- ✅ 聚合条件：先 GROUP BY，再用 HAVING（见第 5 节）
```

`IFNULL` / `COALESCE` 等空值处理见 [常用函数](/pages/mysql-functions/)。

## 3. 排序 ORDER BY

```sql
-- 升序（默认）
SELECT * FROM employees ORDER BY salary ASC;

-- 降序
SELECT * FROM employees ORDER BY salary DESC;

-- 多字段排序
SELECT * FROM employees 
ORDER BY dept_id ASC, salary DESC;

-- 按表达式排序
SELECT * FROM employees 
ORDER BY salary * 12 DESC;
```

## 4. 聚合函数

| 函数 | 说明 |
|------|------|
| `COUNT(*)` | 统计行数 |
| `COUNT(列名)` | 统计该列非 NULL 的行数 |
| `SUM(列名)` | 求和（忽略 NULL） |
| `AVG(列名)` | 平均值（忽略 NULL） |
| `MAX(列名)` | 最大值 |
| `MIN(列名)` | 最小值 |

```sql
SELECT 
    COUNT(*) AS 总人数,
    COUNT(manager_id) AS 有上级的人数,  -- manager_id 为 NULL 的不计入
    AVG(salary) AS 平均薪资,
    MAX(salary) AS 最高薪资,
    MIN(salary) AS 最低薪资,
    SUM(salary) AS 薪资总和
FROM employees;
```

## 5. 分组 GROUP BY / HAVING

执行顺序再强调一次：**WHERE → GROUP BY → HAVING → SELECT**。

- `WHERE`：决定「哪些行参与分组」
- `GROUP BY`：把留下的行按键分成组，组内才能算 `COUNT` / `AVG` 等
- `HAVING`：决定「哪些组保留下来」（此处才能写聚合）

```sql
-- 按部门分组统计
SELECT 
    dept_id,
    COUNT(*) AS 人数,
    AVG(salary) AS 平均薪资,
    MAX(salary) AS 最高薪资
FROM employees
GROUP BY dept_id;

-- 多列分组
SELECT 
    dept_id,
    gender,
    COUNT(*) AS 人数,
    AVG(salary) AS 平均薪资
FROM employees
GROUP BY dept_id, gender;

-- WHERE + GROUP BY + HAVING 同框
-- ① 先丢掉薪资 ≤ 8000 的行
-- ② 再按部门分组
-- ③ 只保留「组内人数 ≥ 2 且平均薪资 > 10000」的部门
SELECT 
    dept_id,
    COUNT(*) AS 人数,
    AVG(salary) AS 平均薪资
FROM employees
WHERE salary > 8000
GROUP BY dept_id
HAVING COUNT(*) >= 2 AND AVG(salary) > 10000;
```

| | WHERE | HAVING |
|---|--------|--------|
| 时机 | 分组**前**，过滤原始行 | 分组**后**，过滤分组结果 |
| 聚合函数 | **不能用** | **可以用** |
| 典型用途 | `salary > 8000` | `AVG(salary) > 8000`、`COUNT(*) >= 2` |
| 别名 | 不能用本查询 `SELECT` 别名 | 部分场景可用（MySQL 常允许），拿不准就写聚合表达式本身 |

## 6. 分页 LIMIT

```sql
SELECT * FROM employees LIMIT 10;           -- 前 10 条
SELECT * FROM employees LIMIT 10 OFFSET 20; -- 跳过 20 条，取 10 条
SELECT * FROM employees LIMIT 20, 10;       -- 等价写法：偏移 20，取 10
```

分页公式（页码从 1 开始，每页 `size` 条）：

```sql
-- 第 page 页：LIMIT (page - 1) * size, size
-- 例：第 3 页，每页 10 条 → LIMIT 20, 10
SELECT * FROM employees ORDER BY id LIMIT 20, 10;
```

> 深分页（`OFFSET` 很大）会扫过大量行再丢弃，大数据量场景需换「基于上次最大 id」等方案，详见 [深度分页问题](/pages/mysql-deep-pagination/)。

## 7. JOIN 连接查询

把两张（或多张）表按关联条件拼成一张「宽表」再查询。常用四类：**内连接、左连接、右连接、全外连接**。表与数据见 [经典示例数据](/pages/mysql-examples/)。

为看清「有匹配 / 无匹配」的差异，先临时补两条数据（练完可删）：

```sql
INSERT INTO departments (dept_name, location) VALUES ('人事部', '广州');  -- 暂无员工
INSERT INTO employees (name, gender, age, salary, dept_id, hire_date)
VALUES ('钱九', 'M', 29, 9000.00, NULL, '2024-06-01');                 -- 暂无部门
```

直觉（以员工 ↔ 部门为例）：

```text
内连接：两边都有匹配才留下
左连接：左表全留，右表对不上 → NULL
右连接：右表全留，左表对不上 → NULL
全外连接：两边全留，对不上的一侧填 NULL
```

三表及以上、自连接、链式写法见专题：[多表联查](/pages/mysql-multi-join/)。

### 7.1 内连接 INNER JOIN

**只保留两表在 `ON` 条件上都能匹配上的行。** 任一表对不上的行都会丢掉。`JOIN` 默认就是 `INNER JOIN`。

```sql
SELECT e.name, d.dept_name, d.location
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;
-- 等价：FROM employees e JOIN departments d ON ...
```

补完演示数据后：`钱九`（无部门）、`人事部`（无员工）都**不会**出现。

旧写法（了解即可，新代码优先 `JOIN ... ON`）：

```sql
SELECT e.name, d.dept_name
FROM employees e, departments d
WHERE e.dept_id = d.id;
```

**例题 1**：查出北京各部门的员工姓名、部门名、薪资。

```sql
SELECT e.name, d.dept_name, e.salary
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
WHERE d.location = '北京';
-- 期望：张三、李四、王五（技术部）
```

**例题 2**：统计每个「有员工」的部门人数与平均薪资。

```sql
SELECT d.dept_name, COUNT(*) AS 人数, AVG(e.salary) AS 平均薪资
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
GROUP BY d.dept_name;
-- 人事部无人，内连接后不会出现
```

### 7.2 左连接 LEFT JOIN

**保留左表全部行**；右表有匹配则拼上，没有则右表列填 `NULL`。写 `LEFT OUTER JOIN` 与 `LEFT JOIN` 等价。

```sql
SELECT e.name, d.dept_name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id;
-- 钱九会留下，dept_name 为 NULL
```

找「左有、右无」是左连接的经典用法：`右表主键 IS NULL`。

```sql
-- 没有部门的员工
SELECT e.name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id
WHERE d.id IS NULL;
-- 期望：钱九
```

**例题 3**：列出全部员工及部门名；没有部门的也要显示。

```sql
SELECT e.name AS 员工, IFNULL(d.dept_name, '未分配') AS 部门
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id;
```

**例题 4**：以部门为左表，找出**没有任何员工**的部门。

```sql
SELECT d.dept_name, d.location
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
WHERE e.id IS NULL;
-- 期望：人事部
```

### 7.3 右连接 RIGHT JOIN

**保留右表全部行**；左表对不上则左表列填 `NULL`。与左连接对称，多数团队更习惯「永远把主表放左边 + `LEFT JOIN`」，右连接了解即可。

```sql
SELECT e.name, d.dept_name
FROM employees e
RIGHT JOIN departments d ON e.dept_id = d.id;
-- 人事部会留下，name 为 NULL；钱九不会出现（他不在右表侧的匹配结果里作为「右表行」保留——右表是 departments）
```

上面这条与下面左连接**结果等价**（只是左右表对调）：

```sql
SELECT e.name, d.dept_name
FROM departments d
LEFT JOIN employees e ON e.dept_id = d.id;
```

**例题 5**：用右连接列出所有部门，并带上员工名（无人部门员工名为 NULL）。

```sql
SELECT d.dept_name, e.name
FROM employees e
RIGHT JOIN departments d ON e.dept_id = d.id
ORDER BY d.id, e.id;
```

**例题 6**：把例题 5 改成等价的左连接写法（答案见上一小节「部门 LEFT JOIN 员工」）。

### 7.4 全外连接（MySQL 用 UNION 模拟）

标准 SQL 有 `FULL OUTER JOIN`：**两边都保留**，任一侧对不上就填 `NULL`。**MySQL 不支持**该语法，用「左连接 ∪ 右连接」模拟：

```sql
SELECT e.name, d.dept_name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id
UNION
SELECT e.name, d.dept_name
FROM employees e
RIGHT JOIN departments d ON e.dept_id = d.id;
-- UNION 去重；钱九（部门 NULL）与人事部（员工 NULL）都会出现
```

只要「左有右无」或「右有左无」之一即可时，不必上全外连接；全外连接适合两边都要完整清单的对账、差异排查。

**例题 7**：模拟全外连接，标出匹配情况。

```sql
SELECT
    e.name,
    d.dept_name,
    CASE
        WHEN e.id IS NOT NULL AND d.id IS NOT NULL THEN '两边都有'
        WHEN e.id IS NOT NULL THEN '仅员工'
        ELSE '仅部门'
    END AS 匹配情况
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id
UNION
SELECT
    e.name,
    d.dept_name,
    CASE
        WHEN e.id IS NOT NULL AND d.id IS NOT NULL THEN '两边都有'
        WHEN d.id IS NOT NULL THEN '仅部门'
        ELSE '仅员工'
    END
FROM employees e
RIGHT JOIN departments d ON e.dept_id = d.id;
```

### 7.5 四种连接对照小结

| 类型 | 关键字 | 保留谁 | 无匹配时 | MySQL |
|------|--------|--------|----------|-------|
| 内连接 | `INNER JOIN` / `JOIN` | 仅匹配行 | 整行丢弃 | 支持 |
| 左连接 | `LEFT JOIN` | 左表全部 | 右列 `NULL` | 支持 |
| 右连接 | `RIGHT JOIN` | 右表全部 | 左列 `NULL` | 支持（可用左连接改写） |
| 全外连接 | `FULL OUTER JOIN` | 左右全部 | 对侧 `NULL` | **不支持**，用 `UNION` 模拟 |

选型口诀：

1. 只要「对得上的」→ **内连接**
2. 以某表为主清单，附带另一表信息 → **左连接**（主表放左边）
3. 查「没有关联数据」的行 → **左连接 + `IS NULL`**
4. 两边清单都要 → **UNION 模拟全外连接**

### 7.6 ⚠️ ON vs WHERE（左/右连接易错）

- **`ON`**：决定「怎么拼」；外连接时，不满足的右表列可为 `NULL`，**左表行仍保留**
- **`WHERE`**：在拼接结果上再过滤；若写 `WHERE 右表列 = …`，会把右表为 `NULL` 的行滤掉，**效果接近内连接**

```sql
-- ✅ 条件放 ON：非北京部门不匹配，但员工行仍留下（dept 侧为 NULL）
SELECT e.name, d.dept_name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id AND d.location = '北京';

-- ⚠️ 条件放 WHERE：无部门或非北京的都会被滤掉，接近内连接
SELECT e.name, d.dept_name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id
WHERE d.location = '北京';
```

**例题 8**：左连接查出所有员工；仅当部门在北京时带出部门名，否则部门名为 NULL（不要用 `WHERE` 滤掉非北京员工）。

```sql
SELECT e.name, d.dept_name
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id AND d.location = '北京';
```

## 8. 子查询

| 类型 | 含义 | 常见用法 |
|------|------|----------|
| 标量（单行单列） | 返回一个值 | `>` / `=` 等比较 |
| 列（多行单列） | 返回一列多值 | `IN` / `ANY` / `ALL` |
| 表（多行多列） | 当作临时表 | `FROM (子查询) t` |
| 相关子查询 | 外层每行驱动内层 | `EXISTS` |

```sql
-- 标量：薪资高于全公司平均
SELECT * FROM employees 
WHERE salary > (SELECT AVG(salary) FROM employees);

-- 列：部门在北京的员工
SELECT * FROM employees 
WHERE dept_id IN (SELECT id FROM departments WHERE location = '北京');

-- ANY / ALL
SELECT * FROM employees 
WHERE salary > ANY (SELECT salary FROM employees WHERE dept_id = 1);
-- > ANY：大于子查询中任意一个；> ALL：大于子查询全部

-- 相关 + EXISTS：有员工的部门
SELECT * FROM departments d
WHERE EXISTS (
    SELECT 1 FROM employees e 
    WHERE e.dept_id = d.id
);

-- 表子查询：各部门平均薪资再过滤
SELECT * FROM (
    SELECT dept_id, AVG(salary) AS avg_sal
    FROM employees
    GROUP BY dept_id
) t
WHERE t.avg_sal > 10000;
```

## 9. UNION 合并结果

要求：各段 **列数相同**、对应列类型兼容；若要排序，**`ORDER BY` 只能写在最后一段**。

```sql
-- UNION：去重合并
SELECT name, salary FROM employees WHERE dept_id = 1
UNION
SELECT name, salary FROM employees WHERE dept_id = 2;

-- UNION ALL：不去重（通常更快）
SELECT name, salary FROM employees WHERE dept_id = 1
UNION ALL
SELECT name, salary FROM employees WHERE dept_id = 2
ORDER BY salary DESC;
```

## 10. 易错点速查

| 场景 | 注意 |
|------|------|
| `WHERE` 写聚合 | 不行；分组后的条件用 `HAVING`（第 0、2、5 节） |
| `WHERE` 用别名 | 执行顺序在 `SELECT` 之前，不能用本查询 `SELECT` 别名 |
| `NULL` 比较 | 用 `IS NULL` / `IS NOT NULL`，不要用 `=` |
| `NOT IN` 子查询含 NULL | 可能导致整句无结果，优先 `NOT EXISTS` |
| 左连接 + `WHERE 右表列` | 易把外连接变成内连接，过滤尽量放 `ON` 或先确认意图；见第 7.6 节、[多表联查](/pages/mysql-multi-join/) |
| `SELECT` 非分组列 | 未出现在 `GROUP BY` 且未聚合的列，不要单独选出 |
| `SELECT *` | 笔记演示可以，接口/生产尽量写明确列名 |
| 深分页 | 大 `OFFSET` 性能差，见 [深度分页问题](/pages/mysql-deep-pagination/) |

动手练习：[经典示例数据 - 练习题](/pages/mysql-examples/#2-经典练习题)；多表进阶：[多表联查](/pages/mysql-multi-join/)。
