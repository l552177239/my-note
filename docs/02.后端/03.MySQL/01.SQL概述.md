# SQL 概述

本文介绍 SQL 是什么、与 MySQL 的关系、关系型数据库核心概念，以及语句分类与学习路径，为后续章节打基础。

<!-- more -->

## 1. SQL 是什么

**SQL（Structured Query Language，结构化查询语言）** 是操作关系型数据库的标准语言，用于定义结构、增删改查数据、控制权限与事务。

常见关系型数据库（RDBMS）都支持 SQL，但各有方言差异：

| 数据库 | 特点（简要） |
|--------|--------------|
| **MySQL** | 开源、轻量，Web 后端常用 |
| **MariaDB** | MySQL 兼容分支 |
| **PostgreSQL** | 功能强、标准遵循好 |
| **SQL Server** | 微软生态，企业应用多 |
| **Oracle** | 大型企业、金融等高可靠场景 |

本系列文档基于 **MySQL** 语法编写。

---

## 2. 核心概念

关系型数据库把数据组织成「表」，表之间通过键建立关联：

| 概念 | 说明 |
|------|------|
| **数据库（Database）** | 一组相关表的集合 |
| **表（Table）** | 二维结构，由行和列组成 |
| **列 / 字段（Column）** | 表的属性，有名称与数据类型 |
| **行 / 记录（Row）** | 一条完整数据 |
| **主键（Primary Key）** | 唯一标识一行，非空且唯一 |
| **外键（Foreign Key）** | 引用其他表主键，表达表间关系 |
| **索引（Index）** | 加速查询，但会增加写入成本 |
| **约束（Constraint）** | 保证数据合法（非空、唯一、检查等） |

示意：

```
数据库 mydb
 ├── 表 departments（部门）
 │     id | dept_name | location
 └── 表 employees（员工）
       id | name | salary | dept_id  ← dept_id 关联 departments.id
```

## 3. SQL 语句分类

按用途可将 SQL 分为五类（日常开发中 DQL / DML / DDL 最常用）：

| 分类 | 全称 | 作用 | 常用语句 |
|------|------|------|----------|
| **DDL** | Data Definition Language | 定义数据库结构 | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| **DML** | Data Manipulation Language | 操作数据 | `INSERT`, `UPDATE`, `DELETE` |
| **DQL** | Data Query Language | 查询数据 | `SELECT` |
| **DCL** | Data Control Language | 权限控制 | `GRANT`, `REVOKE` |
| **TCL** | Transaction Control Language | 事务控制 | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

记忆要点：

- **DDL** 改的是「结构」（库、表、索引），一般自动提交
- **DML** 改的是「数据」，可与事务一起回滚
- **DQL** 只读，不修改数据
- **DCL** 管「谁能做什么」
- **TCL** 管「一组操作是成功提交还是全部撤销」

## 4. 语法特点

- 关键字通常**不区分大小写**（`SELECT` / `select` 等价），习惯上关键字大写、表名列名小写
- 语句以 **`;`** 结束
- 字符串用**单引号** `'...'`（双引号在 MySQL 中常表示标识符）
- 注释：`-- 单行` 或 `/* 多行 */`
- 多数语句可读成自然语言，例如：`从 employees 表中选出 name，条件是 salary > 5000`

```sql
-- 一条最简查询
SELECT name, salary
FROM employees
WHERE salary > 5000
ORDER BY salary DESC;
```

## 5. SELECT 逻辑执行顺序

书写顺序与引擎实际处理顺序不同，理解这一点有助于写对 `WHERE` / `GROUP BY` / `HAVING`：

| 书写顺序 | 逻辑执行顺序 |
|----------|--------------|
| `SELECT` | ① `FROM` / `JOIN` |
| `FROM` | ② `WHERE` |
| `WHERE` | ③ `GROUP BY` |
| `GROUP BY` | ④ `HAVING` |
| `HAVING` | ⑤ `SELECT`（含别名、聚合） |
| `ORDER BY` | ⑥ `ORDER BY` |
| `LIMIT` | ⑦ `LIMIT` |

因此：`WHERE` 不能使用 `SELECT` 里新起的别名；过滤分组结果要用 `HAVING`。

## 6. 本系列学习路径

建议按以下顺序阅读，并配合「经典示例数据」动手练习：

1. **SQL 概述**（本文）：建立整体认识
2. **数据类型**：选对字段类型
3. **DDL**：建库建表、改表结构
4. **DML**：插入、更新、删除
5. **DQL**（核心）：条件、聚合、连接、子查询
6. **DCL**：用户与权限
7. **约束**：主键、外键、唯一、非空等
8. **常用函数**：字符串、数值、日期、条件函数
9. **经典示例数据**：部门 / 员工练习题
10. **深度分页问题**：大 `OFFSET` 为何慢，游标分页与延迟关联
11. **多表联查**：自连接、三表链式、联查与分组/子查询

> **提示**：本文档基于 MySQL 语法编写，部分语法在其他数据库（如 PostgreSQL、SQL Server、Oracle）中可能略有差异，使用时请注意适配。
