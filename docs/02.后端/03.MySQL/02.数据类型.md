# 数据类型

本文整理 MySQL 常用数值、字符串、日期时间与其它类型，并给出选型建议，便于建表时选对字段。

<!-- more -->

## 1. 数值类型

### 1.1 整数

| 类型 | 存储 | 有符号范围（约） | 常见用途 |
|------|------|------------------|----------|
| `TINYINT` | 1 字节 | -128 ~ 127 | 状态码、是否标志 |
| `SMALLINT` | 2 字节 | -32768 ~ 32767 | 较小计数 |
| `MEDIUMINT` | 3 字节 | 约 ±800 万 | 中等规模 ID |
| `INT` / `INTEGER` | 4 字节 | 约 ±21 亿 | 主键、常规整数 |
| `BIGINT` | 8 字节 | 极大整数 | 雪花 ID、大计数 |

- 可加 `UNSIGNED` 表示无符号（如 `INT UNSIGNED`），范围整体右移到非负侧
- `BOOL` / `BOOLEAN` 是 `TINYINT(1)` 的别名，常用 `0` / `1` 表示否/是
- `INT(11)` 里的数字是**显示宽度**（配合 `ZEROFILL`），**不限制**存储范围；日常可直接写 `INT`

### 1.2 小数

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| `FLOAT` | 单精度浮点，有精度误差 | 科学计算、对精度不敏感 |
| `DOUBLE` | 双精度浮点，仍有误差 | 同上，范围更大 |
| `DECIMAL(M,D)` | 精确小数，M 总位数，D 小数位 | **金额、汇率、精确计量** |

```sql
-- 金额务必用 DECIMAL，避免 FLOAT 误差
salary DECIMAL(10,2)   -- 最大 99999999.99
price  DECIMAL(12,4)
```

## 2. 字符串类型

| 类型 | 说明 | 特点 |
|------|------|------|
| `CHAR(n)` | 定长字符串，最长 255 | 不足补空格，适合长度固定的字段 |
| `VARCHAR(n)` | 变长字符串 | 按实际长度存储，最常用 |
| `TINYTEXT` | 最长 255 字节 | 很少单独用 |
| `TEXT` | 最长 65,535 字节 | 文章摘要、较长内容 |
| `MEDIUMTEXT` | 最长约 16MB | 较长正文 |
| `LONGTEXT` | 最长约 4GB | 超大文本 |
| `ENUM('a','b')` | 枚举，只能取列出的值之一 | 状态、性别等有限选项 |
| `SET('a','b')` | 集合，可多选组合 | 标签类多选（用得较少） |

**CHAR vs VARCHAR**：

- 长度几乎固定（如性别 `M`/`F`、国家码）→ 可用 `CHAR`
- 长度不固定（姓名、邮箱、标题）→ 用 `VARCHAR`
- 特别长且不常检索的正文 → `TEXT` / `LONGTEXT`（注意索引限制）

**字符集**：新建库/表建议 `utf8mb4`，可完整支持 emoji 与多数 Unicode 字符。

```sql
name    VARCHAR(50) NOT NULL
gender  CHAR(1) DEFAULT 'M'
status  ENUM('pending', 'paid', 'cancelled') DEFAULT 'pending'
content TEXT
```

## 3. 日期时间类型

| 类型 | 格式 | 范围（约） | 说明 |
|------|------|------------|------|
| `DATE` | `YYYY-MM-DD` | 1000-01-01 ~ 9999-12-31 | 只存日期 |
| `TIME` | `HH:MM:SS` | -838:59:59 ~ 838:59:59 | 时分秒 / 时间间隔 |
| `DATETIME` | `YYYY-MM-DD HH:MM:SS` | 1000-01-01 ~ 9999-12-31 | 与时区无关的日期时间 |
| `TIMESTAMP` | 同上显示 | 1970-01-01 ~ 2038-01-19（传统） | 内部存 UTC，受时区影响 |
| `YEAR` | `YYYY` | 1901 ~ 2155 | 仅年份 |

**DATETIME vs TIMESTAMP**：

| 对比 | `DATETIME` | `TIMESTAMP` |
|------|------------|-------------|
| 时区 | 存什么取什么 | 按会话时区转换 |
| 范围 | 更大 | 传统上限到 2038 |
| 常用场景 | 业务时间（下单、生日） | 创建/更新时间戳 |

```sql
hire_date   DATE
created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
event_time  DATETIME
```

## 4. 其它常用类型

| 类型 | 说明 |
|------|------|
| `JSON` | 存 JSON 文档，支持函数查询与部分索引（MySQL 5.7+） |
| `BLOB` / `LONGBLOB` | 二进制大对象（图片、文件）；更常见做法是存文件路径或对象存储 URL |
| `BINARY(n)` / `VARBINARY(n)` | 定长 / 变长二进制 |

```sql
extra   JSON                          -- {"vip": true, "tags": ["new"]}
avatar  VARCHAR(255)                  -- 存 URL，而不是把图片塞进 BLOB
```

## 5. 选型速查

| 场景 | 推荐类型 |
|------|----------|
| 主键自增 | `INT` / `BIGINT` + `AUTO_INCREMENT` |
| 金额、价格 | `DECIMAL(M,D)` |
| 短文本（姓名、标题） | `VARCHAR(n)` |
| 固定短码（性别、国家码） | `CHAR(n)` 或 `ENUM` |
| 长文本 | `TEXT` / `LONGTEXT` |
| 是否 / 开关 | `TINYINT(1)` 或 `BOOL` |
| 业务日期时间 | `DATE` / `DATETIME` |
| 记录创建、更新时间 | `TIMESTAMP` + `DEFAULT` / `ON UPDATE` |
| 扩展属性 | `JSON` |

建表示例（与后续 DDL / 示例数据章节一致）：

```sql
CREATE TABLE employees (
    id          INT PRIMARY KEY AUTO_INCREMENT,
    name        VARCHAR(50) NOT NULL,
    gender      CHAR(1) DEFAULT 'M',
    age         TINYINT UNSIGNED,
    salary      DECIMAL(10,2),
    hire_date   DATE,
    is_active   TINYINT(1) DEFAULT 1,
    profile     JSON,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

> **提示**：类型选小了会截断或报错，选太大浪费空间与索引效率；金额、状态码、主键是最容易选错的三类，优先对照上表。
