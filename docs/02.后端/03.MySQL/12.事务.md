# 事务

事务把一组 SQL 当成**不可分割的整体**：要么全部成功提交，要么全部失败回滚。资金、库存、下单等强一致场景依赖事务。引擎以 **InnoDB** 为准（MyISAM 不支持事务）。

<!-- more -->

## 1. 什么是事务

一次业务往往对应多条语句。例如「A 转账给 B」至少两步：

1. A 账户减钱
2. B 账户加钱

若第 1 步成功、第 2 步失败，数据就不一致。事务保证这两步**同生共死**。

与 [DML](/pages/mysql-dml/) 的关系：`INSERT` / `UPDATE` / `DELETE` 改数据，可放进事务里回滚；[DDL](/pages/mysql-ddl/)（`CREATE` / `ALTER` / `DROP` 等）多数会**隐式提交**，一般不要指望用 `ROLLBACK` 撤销。

对照：[Redis 事务](/pages/redis-transaction/) 是批量串行、**无回滚**的弱事务；MySQL（InnoDB）提供更完整的 ACID。

---

## 2. ACID 四大特性

| 特性 | 英文 | 含义 |
|------|------|------|
| **原子性** | Atomicity | 事务内操作要么全做，要么全不做 |
| **一致性** | Consistency | 事务前后数据满足业务约束与完整性 |
| **隔离性** | Isolation | 并发事务互不干扰（由隔离级别调节） |
| **持久性** | Durability | 提交后修改永久保存（即使宕机） |

记忆：原子管「成败一体」，一致管「规则没错」，隔离管「并发别乱」，持久管「提交不丢」。

## 3. 基本用法

### 3.1 开启、提交、回滚

```sql
-- 开启事务（二选一）
START TRANSACTION;
-- BEGIN;

-- 业务 SQL
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- 全部成功则提交
COMMIT;

-- 出错则回滚（二选一，不要既 COMMIT 又 ROLLBACK）
-- ROLLBACK;
```

| 语句 | 作用 |
|------|------|
| `START TRANSACTION` / `BEGIN` | 开启事务 |
| `COMMIT` | 提交，永久生效 |
| `ROLLBACK` | 回滚，撤销未提交修改 |

### 3.2 自动提交（autocommit）

MySQL 默认 `autocommit = 1`：每条 DML **单独成事务**，执行完立刻提交。

```sql
-- 查看
SHOW VARIABLES LIKE 'autocommit';
SELECT @@autocommit;

-- 关闭自动提交（之后需手动 COMMIT / ROLLBACK）
SET autocommit = 0;

-- 恢复默认
SET autocommit = 1;
```

实践建议：

- 单条无关紧要的修改：用默认自动提交即可
- 多语句业务：显式 `START TRANSACTION` … `COMMIT` / `ROLLBACK`
- 连接池 / ORM 里也常由框架包一层事务，原理相同

### 3.3 保存点（SAVEPOINT）

事务很长时，可只回滚到中间某点，而不是整笔作废：

```sql
START TRANSACTION;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
SAVEPOINT sp1;

UPDATE accounts SET balance = balance + 100 WHERE id = 2;
-- 第二步发现问题：只撤回到 sp1
ROLLBACK TO SAVEPOINT sp1;

-- 再决定整笔提交或整笔回滚
COMMIT;
-- 或 ROLLBACK;
```

| 语句 | 作用 |
|------|------|
| `SAVEPOINT 名称` | 设置保存点 |
| `ROLLBACK TO SAVEPOINT 名称` | 回滚到该点（事务仍未结束） |
| `RELEASE SAVEPOINT 名称` | 删除保存点 |

## 4. 转账示例

用账户表演示完整流程（可自行建表练习）：

```sql
CREATE TABLE accounts (
    id       INT PRIMARY KEY,
    name     VARCHAR(50) NOT NULL,
    balance  DECIMAL(12,2) NOT NULL CHECK (balance >= 0)
);

INSERT INTO accounts (id, name, balance) VALUES
(1, '张三', 1000.00),
(2, '李四', 500.00);
```

```sql
START TRANSACTION;

-- 张三转 200 给李四
UPDATE accounts SET balance = balance - 200 WHERE id = 1 AND balance >= 200;
-- 影响行数为 0 说明余额不足，应 ROLLBACK
UPDATE accounts SET balance = balance + 200 WHERE id = 2;

COMMIT;
```

应用层常见写法：捕获异常后 `ROLLBACK`，成功则 `COMMIT`；并检查 `UPDATE` 影响行数，避免「扣款条件不满足却继续加款」。

## 5. 并发问题与隔离级别

### 5.1 三种典型读异常

多事务同时读写同一数据时，可能出现：

| 问题 | 说明 |
|------|------|
| **脏读** | 读到别的事务**尚未提交**的修改，对方一回滚，你读到的就是假数据 |
| **不可重复读** | 同一事务内两次读同一行，结果不同（中间被别的事务**改/删并提交**） |
| **幻读** | 同一事务内按条件两次查询，行数/集合变了（中间被别的事务**插入/删除并提交**） |

不可重复读侧重「行内容变了」；幻读侧重「多了或少了行」。

### 5.2 四种隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 说明 |
|----------|------|------------|------|------|
| `READ UNCOMMITTED` | 可能 | 可能 | 可能 | 几乎不用 |
| `READ COMMITTED` | 否 | 可能 | 可能 | Oracle 等默认常见 |
| `REPEATABLE READ` | 否 | 否 | 可能* | **MySQL InnoDB 默认** |
| `SERIALIZABLE` | 否 | 否 | 否 | 最严，并发差 |

\* InnoDB 在 `REPEATABLE READ` 下通过 **MVCC + Next-Key Lock** 等机制，很多场景下也能避免幻读，但并非所有写法都绝对免疫；面试常按上表答标准语义，再补充 InnoDB 的加强。

```sql
-- 查看当前隔离级别
SELECT @@transaction_isolation;
-- 旧版本也可能是：
-- SELECT @@tx_isolation;

-- 设置当前会话隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 设置全局（需权限，影响新连接）
SET GLOBAL TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

也可在开启事务时指定：

```sql
START TRANSACTION;
-- 或
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;
```

### 5.3 怎么选（实务）

- 默认 **`REPEATABLE READ`** 对多数业务够用
- 报表、对账若更能接受「读到最新已提交」，可降到 `READ COMMITTED`（减少部分锁冲突）
- `SERIALIZABLE` 仅在必须强串行、且能接受吞吐下降时使用

## 6. 使用注意

1. **事务尽量短**：持锁时间短，降低阻塞与死锁概率  
2. **避免事务里做远程调用 / 大文件 IO**：拉长事务窗口  
3. **DDL 会隐式提交**：建表、改表等不要夹在指望回滚的业务事务中间  
4. **锁与死锁**：并发更新同一行会等待；互相等待则一方回滚。应用应重试或调整更新顺序  
5. **只有 InnoDB**：建表时 `ENGINE=InnoDB`（MySQL 8 默认已是）  
6. **与自动提交**：显式事务期间，未 `COMMIT` 前其他会话按隔离级别规则可见或不可见你的修改

## 7. 小结

| 要点 | 内容 |
|------|------|
| 本质 | 一组操作的原子提交 / 回滚 |
| 控制 | `START TRANSACTION` / `COMMIT` / `ROLLBACK` / `SAVEPOINT` |
| 默认 | `autocommit=1`；隔离级别 `REPEATABLE READ` |
| 引擎 | InnoDB 支持事务与行锁 |
| 对比 Redis | MySQL 有真回滚与 ACID；Redis 事务无回滚 |
