# 多表联查

两表四种连接（内 / 左 / 右 / 全）见 [DQL - JOIN 连接查询](/pages/mysql-dql/#7-join-连接查询)。本文讲**自连接、三表及以上链式联查**，以及联查与分组、子查询的搭配。基础表仍用 [经典示例数据](/pages/mysql-examples/)。

<!-- more -->

## 1. 为什么要多表联查

单表装不下完整业务时，会拆成多表（部门、员工、项目……），查询时再按外键「拼回去」。多表联查就是：

```text
表 A  JOIN  表 B  ON 关联条件
      JOIN  表 C  ON 关联条件
      …
```

引擎逻辑上先做连接得到中间结果集，再 `WHERE` / `GROUP BY` / `ORDER BY`（见 [DQL - 逻辑执行顺序](/pages/mysql-dql/#0-sql-运行原理逻辑执行顺序)）。

---

## 2. 自连接（同一张表联两次）

一张表里行与行有关联（员工 → 上级、分类 → 父分类），把该表**起两个别名**再 `JOIN`。

示例库 `employees.manager_id` 指向另一名员工的 `id`：

| id | name | manager_id |
|----|------|------------|
| 1 | 张三 | NULL |
| 2 | 李四 | 1 |
| 3 | 王五 | 1 |
| 4 | 赵六 | NULL |
| 5 | 孙七 | 4 |
| 6 | 周八 | NULL |

```sql
SELECT
    e.name AS 员工,
    m.name AS 上级
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```

用 `LEFT JOIN`：没有上级的人（`manager_id` 为 NULL）仍会留下，上级列为 NULL。若只要「有上级」的员工，改 `INNER JOIN`。

**例题 1**：查出每位有上级的员工，以及上级所在部门名（自连接 + 再联部门）。

```sql
SELECT
    e.name AS 员工,
    m.name AS 上级,
    d.dept_name AS 上级部门
FROM employees e
INNER JOIN employees m ON e.manager_id = m.id
LEFT JOIN departments d ON m.dept_id = d.id;
```

**例题 2**：查出「上级」是张三的所有下属姓名。

```sql
SELECT e.name AS 下属
FROM employees e
INNER JOIN employees m ON e.manager_id = m.id
WHERE m.name = '张三';
-- 期望：李四、王五
```

## 3. 两表联查复习（链式的基础）

```sql
SELECT e.name, e.salary, d.dept_name, d.location
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
WHERE e.salary >= 12000
ORDER BY e.salary DESC;
```

要点：

- 每个表起短别名（`e` / `d`），列名写成 `别名.列`
- 连接条件写 `ON`；业务过滤写 `WHERE`
- 外连接时不要轻易对「可空一侧」的列做 `WHERE 列 = …`（会变成内连接效果）

## 4. 三表联查：补一张项目表

经典库只有部门、员工。为演示三表，增加项目与「员工参与项目」中间表：

```sql
CREATE TABLE projects (
    id           INT PRIMARY KEY AUTO_INCREMENT,
    project_name VARCHAR(50) NOT NULL,
    dept_id      INT,          -- 归属部门
    FOREIGN KEY (dept_id) REFERENCES departments(id)
);

CREATE TABLE emp_projects (
    emp_id     INT,
    project_id INT,
    role       VARCHAR(20),
    PRIMARY KEY (emp_id, project_id),
    FOREIGN KEY (emp_id) REFERENCES employees(id),
    FOREIGN KEY (project_id) REFERENCES projects(id)
);

INSERT INTO projects (project_name, dept_id) VALUES
('官网重构', 1),
('春季促销', 2),
('预算系统', 3);

INSERT INTO emp_projects (emp_id, project_id, role) VALUES
(1, 1, '负责人'),
(2, 1, '开发'),
(3, 1, '开发'),
(4, 2, '负责人'),
(5, 2, '执行'),
(6, 3, '负责人');
```

关系：

```text
departments 1──n employees
departments 1──n projects
employees   n──n projects   （经 emp_projects）
```

### 4.1 链式 INNER JOIN

```sql
SELECT
    e.name,
    d.dept_name,
    p.project_name,
    ep.role
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
INNER JOIN emp_projects ep ON e.id = ep.emp_id
INNER JOIN projects p ON ep.project_id = p.id;
```

写法习惯：从「主表」出发，按外键一环一环接；每加一张表就写清一个 `ON`。

**例题 3**：列出技术部参与「官网重构」的员工及角色。

```sql
SELECT e.name, ep.role
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
INNER JOIN emp_projects ep ON e.id = ep.emp_id
INNER JOIN projects p ON ep.project_id = p.id
WHERE d.dept_name = '技术部'
  AND p.project_name = '官网重构';
```

### 4.2 左连接找「未参加任何项目」的员工

```sql
SELECT e.name, d.dept_name
FROM employees e
LEFT JOIN emp_projects ep ON e.id = ep.emp_id
LEFT JOIN departments d ON e.dept_id = d.id
WHERE ep.emp_id IS NULL;
```

若示例数据里人人都有项目，结果为空；可先删一条 `emp_projects` 再验证。

**例题 4**：查出没有任何项目归属的部门（部门左连项目）。

```sql
SELECT d.dept_name
FROM departments d
LEFT JOIN projects p ON d.id = p.dept_id
WHERE p.id IS NULL;
```

### 4.3 联查 + 分组

```sql
-- 每个项目的参与人数
SELECT p.project_name, COUNT(ep.emp_id) AS 人数
FROM projects p
LEFT JOIN emp_projects ep ON p.id = ep.project_id
GROUP BY p.id, p.project_name;
```

**例题 5**：各部门「参与过项目」的员工人数（同一人多项目只计一次可用 `COUNT(DISTINCT …)`）。

```sql
SELECT d.dept_name, COUNT(DISTINCT ep.emp_id) AS 参与项目的员工数
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
LEFT JOIN emp_projects ep ON e.id = ep.emp_id
GROUP BY d.id, d.dept_name;
```

## 5. JOIN 与子查询怎么选

| 场景 | 更常见写法 |
|------|------------|
| 结果里要带出多表字段 | `JOIN` |
| 只按另一表做过滤（不展示其列） | `JOIN` 或 `IN` / `EXISTS` 均可 |
| 相关存在性判断 | `EXISTS` 往往清晰 |
| 每组极值（部门最高薪） | `JOIN` + 聚合子查询，或窗口函数 |

```sql
-- 子查询过滤：部门在北京的员工（结果只需员工列）
SELECT e.*
FROM employees e
WHERE e.dept_id IN (
    SELECT id FROM departments WHERE location = '北京'
);

-- 等价 JOIN（还方便选出 dept_name）
SELECT e.*, d.dept_name
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
WHERE d.location = '北京';
```

**例题 6**：用 `EXISTS` 查出至少有一名薪资 ≥ 15000 员工的部门名。

```sql
SELECT d.dept_name
FROM departments d
WHERE EXISTS (
    SELECT 1 FROM employees e
    WHERE e.dept_id = d.id AND e.salary >= 15000
);
```

## 6. 书写与排错清单

1. **别名**：多表同名列（如两边都有 `id`）必须 `表.列`，否则报错或歧义  
2. **连接条件别漏**：漏 `ON` 或写成笛卡尔积，行数会爆炸  
3. **外连接 + WHERE**：对右表列等值过滤，容易把左连接变成内连接  
4. **一对多再聚合**：先想清粒度（按员工还是按部门），必要时 `COUNT(DISTINCT …)`  
5. **驱动顺序**：可读性上「主表在前」；性能上让优化器选路径，重要查询用 `EXPLAIN`  
6. **自连接**：两个别名语义要分清（员工 / 上级），条件方向别反

## 7. 综合例题

**例题 7**：显示员工、部门、上级姓名（无上级显示「无」）。

```sql
SELECT
    e.name AS 员工,
    IFNULL(d.dept_name, '未分配') AS 部门,
    IFNULL(m.name, '无') AS 上级
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.id
LEFT JOIN employees m ON e.manager_id = m.id
ORDER BY e.id;
```

**例题 8**：每个部门薪资最高的员工（联查 + 子查询）。

```sql
SELECT e.name, e.salary, d.dept_name
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id
WHERE (e.dept_id, e.salary) IN (
    SELECT dept_id, MAX(salary)
    FROM employees
    WHERE dept_id IS NOT NULL
    GROUP BY dept_id
);
```

**例题 9**（需第 4 节项目表）：项目名、归属部门、负责人姓名（`role = '负责人'`）。

```sql
SELECT
    p.project_name AS 项目,
    d.dept_name AS 归属部门,
    e.name AS 负责人
FROM projects p
INNER JOIN departments d ON p.dept_id = d.id
INNER JOIN emp_projects ep ON p.id = ep.project_id AND ep.role = '负责人'
INNER JOIN employees e ON ep.emp_id = e.id;
```

## 8. 小结

| 模式 | 用法 |
|------|------|
| 两表 JOIN | 主从表按外键拼字段 |
| 自连接 | 同表两别名，处理层级 |
| 三表及以上 | 多个 `JOIN … ON` 链式连接 |
| 多对多 | 中间表拆成两次（或三次）连接 |
| 左连接 + `IS NULL` | 找「没有关联」的数据 |
