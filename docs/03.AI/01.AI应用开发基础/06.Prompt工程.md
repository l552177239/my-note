# Prompt工程

把任务目标、约束、材料与输出规格，组织成模型可续写的输入。高质量 Prompt 是应用层性价比最高的杠杆：多数业务先调提示，再谈微调。

承接 [大语言模型](/pages/ai-llm/)，下一篇 [RAG 与 Agent](/pages/ai-rag-agent/)。

<!-- more -->

## 1. 提示词四要素

1. **角色与任务**：你是谁、要完成什么  
2. **输入材料**：文档、表格、用户原话  
3. **输出约束**：格式、字段、长度、禁止事项  
4. **标准 / 示例**：Few-shot、边界声明（不知道就说不知道）

---

## 2. 常用提示模式

| 模式 | 做法 | 适用 |
|------|------|------|
| **指令式** | 祈使句 + 可检验标准 | 大多数任务 |
| **角色扮演** | 设定专家身份与语气 | 客服、写作、评审 |
| **模板填空** | 固定骨架，变量只填业务字段 | 生产环境可维护 |
| **分步任务** | 先分类再处理 / 先抽取再生成 | 复杂流水线前半段 |
| **边界防御** | 仅依据材料；不足则拒绝编造 | 降幻觉 |

反例：模糊的「写得好一点」「专业一些」——模型无法对齐你的「好」。

---

## 3. Few-shot（少样本）

给 1～3 组「输入 → 期望输出」示例，往往比大段文字描述更稳。

```text
将用户反馈标成：正向 / 负向 / 中性。只输出标签。

示例1：
输入：物流太慢了，等了一周。
输出：负向

示例2：
输入：包装完好，第二天就到了。
输出：正向

输入：{user_text}
输出：
```

注意：

- 示例要**覆盖边界**（模糊、短句、多语言）
- 示例也占 Token，别塞十几个长文
- 示例风格要与最终输出格式一致（都是 JSON 就都是 JSON）

---

## 4. Chain-of-Thought（思维链）

对多步推理、数学、规则组合题，要求模型**先列要点再给结论**，常能降低跳步错误。

```text
逐步思考，最后用一行给出答案。
思考过程写在 reasoning 字段，最终答案写在 answer 字段。
```

落地建议：

- **对用户隐藏**冗长思考，或只在调试时打开  
- 要程序消费时，用结构化字段拆开 `reasoning` / `answer`  
- 不是万能：材料不足时 CoT 也可能一本正经地错——仍需 RAG / 工具

变体：先让模型列出计划再执行（Plan-and-Solve）；或对关键步骤强制检查清单。

---

## 5. 结构化输出

目标：程序能稳定 `parse`，而不是散文。

| 手段 | 说明 |
|------|------|
| **提示内 Schema** | 写清字段名、类型、枚举 |
| **低温** | temperature 0～0.3 |
| **官方 JSON 模式** | 若 API 支持优先开启 |
| **失败重试** | 校验失败则纠错再调或降级规则 |

```text
只输出一个 JSON 对象，不要 Markdown 代码围栏：
{
  "answer": string,
  "confidence": number,   // 0~1
  "need_human": boolean
}
```

程序侧：**校验字段存在与类型**，不要假设模型永远合法。

## 6. RAG 场景最小模板

```text
你是文档问答助手，只允许依据【给定文档】回答，禁止编造。
文档不足时回复：信息不足。

【给定文档】
{docs}

【用户问题】
{question}

【输出】
{"answer": string, "citations": string[]}
```

检索与向量库细节见 [RAG 与 Agent](/pages/ai-rag-agent/)。

## 7. 实用技巧清单

| 技巧 | 说明 |
|------|------|
| 指令明确 | 可检验：字数、字段、是否允许推测 |
| 把不可信内容当数据 | 用户输入用分隔符包起来，防提示注入 |
| 重要规则每轮带上 | 勿只依赖「很久以前 system 说过」 |
| 先小后大 | 小模型 / 短提示跑通，再加复杂约束 |
| 用评测集 | 改 Prompt 前后对比同一批题 |

---

## 8. 小结

- Prompt = 任务说明书；四要素齐全再谈花活。  
- Few-shot 示范格式；CoT 服务复杂推理；结构化服务程序。  
- 与 RAG/工具配合，才能突破「只会聊天」的天花板。
