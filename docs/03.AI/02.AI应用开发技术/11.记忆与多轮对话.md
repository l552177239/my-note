# 11. 记忆与多轮对话

> 系列第 11 篇。前面的聊天都是"一问一答"——用户说"我想退货"，模型答完，用户追问"那运费谁出"，模型已经不记得刚才说的是退货了。这一篇解决"对话连续性"：怎么存历史、怎么在上下文窗口里管理历史、历史太长怎么办。
> 这是第 13 篇 Agent 的前置——Agent 做工具调用时天然需要记住之前调过什么。

## 1. 学习目标

- 理解为什么单轮对话不行，什么是 session
- 实现短期记忆：按 `session_id` 存取对话历史
- 解决上下文窗口问题：滑动窗口保留最近 N 轮
- 用 LLM 摘要压缩更早的历史
- 知道长期记忆（用户偏好）存哪
- **产出物**：`POST /api/chat/session` 带 `session_id`，连续对话模型能记住上文

---

## 2. 为什么需要记忆

02 篇的 `/api/chat` 每次都只传一条 user 消息：

```python
messages=[{"role": "user", "content": "那运费谁出"}]
```

模型看到的是孤立的一句话，不知道"那"指的是退货。多轮对话要把历史也传进去：

```python
messages=[
    {"role": "user", "content": "我想退货"},
    {"role": "assistant", "content": "好的，请问订单号是？"},
    {"role": "user", "content": "那运费谁出"},   # 模型现在知道"那"指退货
]
```

**记忆的本质**：把之前的对话历史按 OpenAI messages 格式拼回去，让模型"看到"上下文。

---

## 3. 短期记忆：按 session 存历史

### 3.1 内存版会话存储

学习阶段用内存 dict，重启丢。生产换 Redis（第 17 篇可观测性会提到）。

新建 `app/core/memory.py`：

```python
import logging
from collections import defaultdict
from openai.types.chat import ChatCompletionMessageParam

logger = logging.getLogger(__name__)

# {session_id: [消息列表]}
_sessions: dict[str, list[ChatCompletionMessageParam]] = defaultdict(list)


def add_message(session_id: str, role: str, content: str):
    """存一条消息。role: user / assistant。"""
    _sessions[session_id].append({"role": role, "content": content})


def get_history(session_id: str) -> list[ChatCompletionMessageParam]:
    return _sessions.get(session_id, [])


def build_messages(
    system_prompt: str,
    history: list[ChatCompletionMessageParam],
    question: str,
) -> list[ChatCompletionMessageParam]:
    """
    拼装最终的 messages，保证只有一条 system。

    history 里如果第一条是 system（摘要在其中），就把它合并进 system_prompt，
    其余历史消息原样拼在后面。
    """
    summary_text = ""
    if history and history[0].get("role") == "system":
        summary_text = history[0]["content"]
        history = history[1:]

    system_content = system_prompt
    if summary_text:
        system_content = f"{system_prompt}\n\n{summary_text}"

    return [
        {"role": "system", "content": system_content},
        *history,
        {"role": "user", "content": question},
    ]


def clear_session(session_id: str):
    _sessions.pop(session_id, None)
    logger.info("Session '%s' cleared", session_id)
```

### 3.2 问题：历史会无限增长

聊了 50 轮，messages 有 100 条，全部塞进 context：
- 超出模型上下文窗口（qwen2.5:14b 是 32k token）
- 没超窗口也贵——每轮都把全部历史重发一遍，token 成本线性增长

所以要做**上下文管理**。

---

## 4. 滑动窗口：保留最近 N 轮

最简单的策略：只保留最近 N 轮对话，更早的丢掉。

```python
WINDOW_SIZE = 10   # 保留最近 10 条消息（5 轮对话）

def get_recent_history(session_id: str, window: int = WINDOW_SIZE) -> list:
    history = get_history(session_id)
    return history[-window:]   # 只取最近 N 条
```

**优点**：简单、稳定、可预测。
**缺点**：很早说过的关键信息（如"我姓张"）会被丢掉。

---

## 5. 摘要压缩：把旧历史压成一段话

更好的策略：保留最近 N 轮原文，更早的历史用 LLM 压成一段摘要，开头放一条 system 消息。

```python
from app.core.llm import call_llm

async def summarize_old_history(session_id: str, keep_recent: int = 6):
    """
    如果历史超过 keep_recent 条，把更早的部分摘要成一段。
    ⚠️ 生成摘要后必须写回存储，否则每次请求都会重复摘要，历史无限膨胀。
    """
    history = get_history(session_id)
    if len(history) <= keep_recent:
        return history

    old = history[:-keep_recent]
    recent = history[-keep_recent:]

    # 1. 把旧历史拼成文本让 LLM 总结
    dialogue = "\n".join(f"{m['role']}: {m['content']}" for m in old)
    summary = await call_llm(
        messages=[
            {"role": "system", "content": "把以下对话摘要成3-5句话，保留关键事实（人名、订单号、偏好、未解决的问题）。"},
            {"role": "user", "content": dialogue},
        ],
        temperature=0.0,
    )

    # 2. 摘要作为一条 system 消息放最前面
    summarized_history: list[ChatCompletionMessageParam] = [
        {"role": "system", "content": f"对话历史摘要：{summary}"}
    ] + recent

    # 3. 【关键】把压缩后的历史写回 _sessions，下次直接用，不再重复摘要
    _sessions[session_id] = summarized_history

    return summarized_history
```

> **这个函数同时包含了滑动窗口逻辑**：截断到最近 N 条 + 摘要更早的部分。路由里调它一次就够，不要再调 `get_recent_history`。

> **辅助函数 `build_messages`**：`summarize_old_history` 返回的历史里第一条可能是 system（摘要）。如果调用方自己还有 SYSTEM_PROMPT，拼起来会出现两条 system。用这个函数把摘要合并进 system：
>
> ```python
> def build_messages(
>     system_prompt: str,
>     history: list[ChatCompletionMessageParam],
>     user_message: str,
> ) -> list[ChatCompletionMessageParam]:
>     """把摘要合并进 system，保证只有一条 system 消息。"""
>     system_content = system_prompt
>     if history and history[0]["role"] == "system":
>         system_content += "\n\n" + history[0]["content"]
>         history = history[1:]
>     return [{"role": "system", "content": system_content}, *history,
>             {"role": "user", "content": user_message}]
> ```

### 5.1 效果

```
system: 对话历史摘要：用户姓张，订单号88023，想退货但担心运费问题。
user: 那运费谁出？
```

模型既知道"那"指退货，又不用把 20 轮原文都塞进去。

## 6. FastAPI 接口

`app/routers/chat.py` 加一个 session 接口：

```python
from fastapi import APIRouter, HTTPException
from pydantic import BaseModel

from app.core.llm import call_llm
from app.core.memory import add_message, clear_session, build_messages
from app.core.memory import summarize_old_history

router = APIRouter(prefix="/api/chat", tags=["chat"])

class SessionChatRequest(BaseModel):
    session_id: str
    message: str

class ClearRequest(BaseModel):
    session_id: str

@router.post("/session")
async def chat_session(req: SessionChatRequest):
    if not req.message.strip():
        raise HTTPException(status_code=422, detail="message 不能为空")

    # 1. 取历史（滑动窗口 + 摘要）
    history = await summarize_old_history(req.session_id, keep_recent=6)

    # 2. 拼消息（摘要合并进 system，只有一条 system）
    messages = build_messages("你是一个友好的助手。", history, req.message)

    # 3. 调 LLM
    answer = await call_llm(messages=messages, temperature=0.7)

    # 4. 存历史
    add_message(req.session_id, "user", req.message)
    add_message(req.session_id, "assistant", answer)

    return {"session_id": req.session_id, "reply": answer}

@router.post("/clear")
async def clear(req: ClearRequest):
    clear_session(req.session_id)
    return {"cleared": req.session_id}
```

## 7. 验证多轮对话

第一轮：

```json
POST /api/chat/session
{"session_id": "user_001", "message": "我姓张，订单号88023，想退货"}
```

第二轮（追问，模型应该记得）：

```json
POST /api/chat/session
{"session_id": "user_001", "message": "那运费谁出"}
```

模型回复应该提到退货，而不是问"你是谁？"。

换个 session：

```json
POST /api/chat/session
{"session_id": "user_002", "message": "那运费谁出"}
```

模型应该不知道"那"指什么——session 隔离生效。

清空：

```json
POST /api/chat/clear
{"session_id": "user_001"}
```

## 8. 长期记忆：用户偏好存哪

短期记忆（对话历史）和长期记忆（用户是谁、喜欢什么）是两回事：

| 类型 | 存什么 | 存哪 | 例子 |
|------|--------|------|------|
| 短期 | 本次对话说了什么 | 内存/Redis | "刚才说的退货" |
| 长期 | 用户偏好、事实 | 数据库（MySQL） | "用户姓张，邮箱 a@b.com" |

长期记忆在生产环境存 MySQL（就是您现有的业务库），每次对话开头从用户表里拉出来塞进 system prompt。学习阶段不展开，知道区别即可。

> **审计提醒**：摘要压缩后，原始对话在内存里就丢了。生产环境如果需要审计（客服质检、合规留痕），要在摘要写回内存之前先把原始对话落盘到数据库，再用摘要替换内存里的历史。

## 9. 关键设计决策

| 决策 | 做法 | 原因 |
|------|------|------|
| session_id 由谁传 | 前端生成 UUID，每次对话传上来 | 服务端不做用户体系，简单 |
| 历史存哪 | 内存 dict | 学习阶段够用；生产换 Redis |
| 上下文策略 | 滑动窗口 + 摘要 | 窗口简单，摘要保留关键事实 |
| 窗口大小 | 最近 6 条（3 轮） | 太小忘上下文，太大费 token |

## 11. 失败模式速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| 模型忘了刚才说什么 | session_id 不一致或没传 | 确认前端每次传同一个 session_id |
| 两个用户互相看到对方的对话 | session_id 撞了 | 用 UUID，别用 user_001 这种可预测的 |
| 聊几轮后报错 context length exceeded | 历史没截断，全塞进去了 | 开滑动窗口；调小 keep_recent |
| 摘要质量差，丢了关键信息 | summarize prompt 太简单 | 在 system 里明确"保留人名、订单号、未解决问题" |
| 重启服务后对话历史没了 | 内存 dict，重启丢 | 生产换 Redis；学习阶段接受 |
| 模型把摘要当成了用户说的话 | system 消息 role 用错 | 摘要必须用 role=system，不能用 user |
| 追问"那运费呢"模型不知道指什么 | 历史被窗口截掉了 | 加大 keep_recent；或开启摘要 |
