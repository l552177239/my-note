# 12. Function Calling 与工具使用

> 系列第 12 篇。前 11 篇模型只会"说"——查不了订单、查不了物流、提不了工单。这一篇让模型学会"做"：用户问"我的订单 88023 到哪了"，模型自己判断需要调用查物流工具，代码执行完把结果喂回去，模型再用人话回答。
> 这是从"问答助手"到"Agent"的第一步。

<!-- more -->

---

## 1. 学习目标

- 理解 Function Calling 的本质：模型不执行函数，只输出"调用意图"（工具名 + 参数 JSON）
- 会写工具定义（tools schema）：name、description、parameters
- 实现完整的工具调用循环：提问 → tool_calls → 执行 → role=tool 回传 → 最终回答
- 处理常见错误：模型没调工具、参数缺失、工具执行失败
- **产出物**：`POST /api/agent/chat`，问"订单 88023 到哪了"能自动调工具并回答

---

## 2. Function Calling 的本质

关键认知：**模型不会执行任何代码**。它只做一件事——根据你的工具定义，输出一个 JSON：

```json
{
  "name": "get_order_status",
  "arguments": "{\"order_id\": \"88023\"}"
}
```

然后**你的代码**看到这个 JSON，真的去查数据库/调 API，把结果喂回模型，模型再基于结果组织语言。

```
用户提问
   ↓
模型看工具列表 → 决定要不要调工具
   ↓
输出 tool_calls（工具名+参数）
   ↓
你的代码执行工具 → 得到结果
   ↓
结果作为 role=tool 消息塞回 messages
   ↓
模型基于工具结果生成最终回答
```

## 3. 定义工具

新建 `app/services/agent_service.py`：

```python
import json
import logging

from openai.types.chat import ChatCompletionMessageParam
from app.core.llm import client
from app.config import settings

logger = logging.getLogger(__name__)

# ---------- 工具定义 ----------
TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "get_order_status",
            "description": "查询订单的物流状态，需要提供订单号",
            "parameters": {
                "type": "object",
                "properties": {
                    "order_id": {"type": "string", "description": "订单号，如 88023"}
                },
                "required": ["order_id"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "get_product_info",
            "description": "查询商品详情，需要提供商品ID",
            "parameters": {
                "type": "object",
                "properties": {
                    "product_id": {"type": "string", "description": "商品ID"}
                },
                "required": ["product_id"],
            },
        },
    },
]

# ---------- 工具的真实执行逻辑 ----------
# 学习阶段用 mock；第 14 篇接 Java 业务 API 时换成真实 HTTP 调用
def _get_order_status(order_id: str) -> str:
    return f"订单 {order_id} 已发货，快递单号 SF123456，预计明天下午送达。"

def _get_product_info(product_id: str) -> str:
    return f"商品 {product_id}：无线鼠标，价格 99 元，现货。"

# 工具名 → 执行函数的映射
TOOL_IMPL = {
    "get_order_status": _get_order_status,
    "get_product_info": _get_product_info,
}
```

### 3.1 工具定义怎么写才有效

| 要点 | 例子 |
|------|------|
| description 要写清"什么时候用" | "查询订单物流状态"比"查订单"好 |
| 参数要写 description | 模型不知道 order_id 长什么样，告诉他"如 88023" |
| required 明确 | 哪些参数必填写清楚 |
| 一个工具只做一件事 | 不要做"万能查询"工具 |

## 4. ReAct 循环：完整流程

```python
async def agent_chat(question: str) -> str:
    messages: list[ChatCompletionMessageParam] = [
        {"role": "user", "content": question}
    ]

    # 第一轮：模型决定要不要调工具
    resp = await client.chat.completions.create(
        model=settings.ollama_model,
        messages=messages,
        tools=TOOLS,
        temperature=0.0,
    )
    msg = resp.choices[0].message

    # 模型直接回答了（不需要工具）
    if not msg.tool_calls:
        return msg.content or ""

    # 模型要调工具：执行每个 tool_call
    messages.append(msg)   # 必须把模型的 tool_calls 消息加回去
    for tool_call in msg.tool_calls:
        func_name = tool_call.function.name
        try:
            args = json.loads(tool_call.function.arguments)
            logger.info("Calling tool %s(%s)", func_name, args)
            if func_name not in TOOL_IMPL:
                result = f"未知工具: {func_name}"
            else:
                result = TOOL_IMPL[func_name](**args)
        except Exception as e:
            result = f"工具执行失败: {e}"

        # 工具结果作为 role=tool 塞回
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": result,
        })

    # 第二轮：模型基于工具结果生成最终回答
    final = await client.chat.completions.create(
        model=settings.ollama_model,
        messages=messages,
        temperature=0.0,
    )
    return final.choices[0].message.content or ""
```

### 4.1 关键细节

- **`messages.append(msg)`**：模型返回的 tool_calls 消息必须加回 messages，第二轮 API 才知道"之前调了什么工具"。漏了会报错。
- **`role=tool` + `tool_call_id`**：每个工具结果要标明对应哪个 tool_call，多工具并行时靠这个关联。
- **temperature=0**：工具调用参数必须稳定，不能有创意。
- **try/except 包工具执行**：工具崩了不能把整个请求搞挂，把错误信息喂回模型让它自己处理。

## 5. FastAPI 接口

`app/routers/agent.py`：

```python
from fastapi import APIRouter, HTTPException
from pydantic import BaseModel

from app.services.agent_service import agent_chat

router = APIRouter(prefix="/api/agent", tags=["agent"])

class AgentRequest(BaseModel):
    question: str

@router.post("/chat")
async def chat(req: AgentRequest):
    if not req.question.strip():
        raise HTTPException(status_code=422, detail="question 不能为空")
    answer = await agent_chat(req.question)
    return {"answer": answer}
```

注册路由：

```python
from app.routers import ..., agent
app.include_router(agent.router)
```

## 7. 和真实业务 API 对接（预告）

现在工具执行是 mock：

```python
def _get_order_status(order_id: str) -> str:
    return f"订单 {order_id} 已发货..."
```

第 14 篇接 Java 业务系统时，这里换成 HTTP 调用：

```python
import httpx

async def _get_order_status(order_id: str) -> str:
    async with httpx.AsyncClient() as http:
        r = await http.get(f"{settings.java_biz_api_base}/orders/{order_id}")
        return r.text
```

工具定义和 ReAct 循环不变，只换实现。这就是 Function Calling 的价值——业务能力是可插拔的。

## 9. 失败模式速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| 模型不调工具，直接编答案 | 工具 description 不够明确 | 写清"什么时候用这个工具" |
| 调了工具但参数为空/错 | 参数 description 不清楚 | 在 parameters 里给示例，如 "如 88023" |
| 报 "tool_calls message not found" | 没把模型的 tool_calls 消息加回 messages | `messages.append(msg)` 不能漏 |
| 报 "tool_call_id mismatch" | role=tool 的 id 和 tool_call.id 对不上 | 严格用 `tool_call.id`，别自己生成 |
| 工具执行 500 但整个接口崩了 | 没 try/except | 工具执行包 try/except，错误喂回模型 |
| 模型重复调同一个工具 | 死循环 | 限制最大工具调用次数（如 3 次），第 13 篇讲 |
| 本地小模型工具调用不稳 | 14B 对 function calling 支持有限 | 确认 qwen2.5 版本支持 tool calling；或换更大模型 |
| 回答里暴露了工具原始返回 | 模型直接贴了数据库结果 | system prompt 里加"用自然语言转述，不要贴原始 JSON" |
