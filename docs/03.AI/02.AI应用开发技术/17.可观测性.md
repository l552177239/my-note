# 17. 可观测性

> 系列第 17 篇。系统能跑了，但线上出问题怎么排查？"用户说回答不对"——你拿什么定位？是检索错了、prompt 拼错了、还是 LLM 自己抽风？这一篇用**结构化日志 + Langfuse** 把每次调用完整记录下来：token 花了多少、检索命中了什么、每步耗时多久。

<!-- more -->

---

## 1. 学习目标

- 理解 LLM 应用可观测性的三要素：日志、指标、追踪
- 用结构化日志记录每次 LLM 调用的关键字段
- 部署 Langfuse（Docker Compose）
- 用 `@observe` 装饰器自动追踪函数调用
- 用一次真实 badcase 演示 trace 排查
- **产出物**：每次 RAG / Agent 请求都能在 Langfuse UI 看到完整链路

---

## 2. 为什么 LLM 应用需要可观测性

普通 Web 应用：请求进来 → 查数据库 → 返回。出错看堆栈就行。

LLM 应用：请求进来 → 检索（可能错）→ 拼 prompt（可能错）→ 调 LLM（不确定）→ 生成回答（可能幻觉）。

**问题是：出错时你不知道哪一步错了。**

```
用户："运费怎么算"
  → 系统回答："退货需在签收后 7 天内申请"
     ↑ 到底是检索错了？还是 LLM 没看 context？
```

没有 trace，你只能靠"改一下再试试"。有了 trace，打开界面就能看到：检索命中了哪 3 个片段、LLM 看到的完整 prompt、token 消耗、各步耗时。

---

## 3. 三层可观测性

| 层 | 工具 | 作用 |
|----|------|------|
| **日志** | Python `logging` + JSON | 单次调用的关键字段，机器可读 |
| **指标** | Prometheus / Langfuse | 聚合统计：QPS、P95 延迟、平均 token |
| **追踪** | Langfuse / OpenTelemetry | 一次请求的完整链路，跨函数跨服务 |

本篇重点：**结构化日志** + **Langfuse 追踪**。指标层可以后续按需加。

## 4. 结构化日志：先打好基础

### 4.1 为什么不用 `logger.info("xxx")`

```python
logger.info(f"LLM call done, tokens={tokens}, latency={ms}ms")
```

看起来能用，但：
- 无法按字段过滤（"找出所有 tokens > 4000 的调用"）
- 无法聚合（"过去 1 小时平均延迟"）
- 日志解析靠正则，脆

结构化日志：输出 JSON，字段固定。

### 4.2 改造 call_llm

`app/core/llm.py`（一份代码同时完成重试限流、结构化日志、Langfuse 追踪三件事）：

```python
# app/core/llm.py
import json
import logging
import time

from langfuse.decorators import observe, langfuse_context

logger = logging.getLogger(__name__)

@observe(as_type="generation")   # 标记为 LLM 生成，Langfuse 自动统计 token
async def call_llm(
    messages: list,
    model: str | None = None,
    temperature: float = 0.0,
    json_mode: bool = False,
) -> str:
    start = time.perf_counter()
    result = await _do_call(messages, model, temperature, json_mode)
    latency_ms = int((time.perf_counter() - start) * 1000)

    # 1. 结构化日志
    logger.info(json.dumps({
        "event": "llm_call",
        "model": model or settings.ollama_model,
        "prompt_tokens": result["prompt_tokens"],
        "completion_tokens": result["completion_tokens"],
        "total_tokens": result["total_tokens"],
        "latency_ms": latency_ms,
        "temperature": temperature,
        "json_mode": json_mode,
    }, ensure_ascii=False))

    # 2. Langfuse 记录
    langfuse_context.update_current_observation(
        model=model or settings.ollama_model,
        input=messages,
        output=result["content"],
        usage={
            "input": result["prompt_tokens"],
            "output": result["completion_tokens"],
        },
        metadata={"latency_ms": latency_ms},
    )

    return result["content"]
```

输出：

```json
{"event": "llm_call", "model": "qwen2.5:14b", "prompt_tokens": 312, "completion_tokens": 58, "total_tokens": 370, "latency_ms": 3204, "temperature": 0.1, "json_mode": false}
```

> 这份代码复用 04 篇的 `_do_call`（重试、限流、超时都在里面），不会绕过工程化封装。

## 5. 部署 Langfuse

Langfuse 是开源的 LLM 可观测性平台，支持自托管。用 Docker Compose 一键起：

`docker-compose.langfuse.yml`：

```yaml
version: "3.8"

services:
  langfuse-db:
    image: postgres:16
    environment:
      POSTGRES_USER: langfuse
      POSTGRES_PASSWORD: langfuse
      POSTGRES_DB: langfuse
    volumes:
      - langfuse-db-data:/var/lib/postgresql/data

  langfuse:
    image: langfuse/langfuse:2
    depends_on:
      - langfuse-db
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgresql://langfuse:langfuse@langfuse-db:5432/langfuse
      NEXTAUTH_SECRET: change-me-in-production
      SALT: change-me-in-production
      NEXTAUTH_URL: http://localhost:3000
      TELEMETRY_ENABLED: "false"

volumes:
  langfuse-db-data:
```

启动：

```powershell
docker compose -f docker-compose.langfuse.yml up -d
```

浏览器打开 `http://localhost:3000`，注册一个账号，创建一个 Project，拿到 Public Key 和 Secret Key。

`.env`：

```bash
LANGFUSE_PUBLIC_KEY=pk-lf-xxx
LANGFUSE_SECRET_KEY=sk-lf-xxx
LANGFUSE_HOST=http://localhost:3000
```

`app/config.py`：

```python
class Settings(BaseSettings):
    # ...
    langfuse_public_key: str = ""
    langfuse_secret_key: str = ""
    langfuse_host: str = "http://localhost:3000"
```

## 6. 接入 Langfuse

### 6.1 装依赖

```powershell
uv add langfuse
```

### 6.2 初始化客户端

新建 `app/core/tracing.py`：

```python
from langfuse import Langfuse
from app.config import settings

langfuse = Langfuse(
    public_key=settings.langfuse_public_key,
    secret_key=settings.langfuse_secret_key,
    host=settings.langfuse_host,
)
```

### 6.3 用 @observe 装饰器自动追踪

Langfuse 的 `@observe` 装饰器会自动把函数调用记录成一个 span，支持嵌套。

```python
from langfuse.decorators import observe, langfuse_context

@observe()
async def ask(collection: str, question: str, top_k: int = 5) -> dict:
    # 这一步自动成为一个名为 ask 的 trace
    hits = await search_documents(collection, question, top_k)
    # ...
    answer = await call_llm(messages=messages, temperature=0.1)

    # 手动补充输入输出
    langfuse_context.update_current_observation(
        input={"question": question, "collection": collection},
        output={"answer": answer},
    )
    return {"answer": answer, "sources": [...]}
```

### 6.4 给关键函数加 @observe

`@observe()` 会为每个被装饰的函数创建一个 span。除了 `call_llm`（4.2 节已加 `@observe(as_type="generation")`），检索函数也要加：

```python
from langfuse.decorators import observe

@observe()
async def search_documents(collection: str, query: str, top_k: int = 5) -> list[dict]:
    ...
```

> 跨进程调用（如 MCP）不会自动串联——需要在客户端和服务端各自加 `@observe()` 并通过 trace_id 手动关联。

### 6.5 FastAPI 请求级追踪

在 router 上加 `@observe()` 就能记录整个请求：

```python
from langfuse.decorators import observe

@router.post("/ask")
@observe()
async def ask_endpoint(req: AskRequest):
    ...
```

## 7. 用一次 badcase 演示

### 7.1 现象

用户问："生鲜食品能退吗？"

系统回答："退货需要在签收后 7 天内申请。"

明显答错了——生鲜是不能退的，且回答没提到生鲜。

### 7.2 打开 Langfuse

进入 Traces 页面，找到这条 trace，看到：

```
Trace: ask
├── Span: search_documents        (检索，120ms)
│   └── 命中 3 个片段
│       [1] "退货政策：签收后 7 天内可申请..."      score=0.72
│       [2] "定制商品、贴身衣物、生鲜食品不支持..."  score=0.68
│       [3] "退款会在 3 个工作日内原路退回..."       score=0.51
└── Generation: call_llm           (生成，3.2s，tokens 312→58)
    └── input: [system prompt + 3 个片段 + 问题]
    └── output: "退货需要在签收后 7 天内申请。"
```

### 7.3 定位问题

看 input prompt 发现：片段 [2] 明明包含答案，但 LLM 选择引用片段 [1]。这是典型的"上下文精确度问题"——片段 [1] 得分最高，抢了 LLM 的注意力。

### 7.4 修复

- 调高 `score_threshold` 到 0.7，过滤掉 [3] 和 [1]
- 或者接入 rerank，让 [2] 排在前面（第 10 篇讲的）

修复后再问同一问题：

```
命中片段：
  [1] "定制商品、贴身衣物、生鲜食品不支持..."  score=0.85
  [2] "退货政策..."                              score=0.62

回答："生鲜食品不支持 7 天无理由退货。"
```

这就是 trace 的价值——不用猜，直接看到 LLM 吃了什么、吐了什么。

## 8. 敏感数据脱敏

Langfuse 会记录 input/output。用户手机号、订单号、身份证不能进 trace。

### 8.1 简单脱敏

```python
import re

def mask_pii(text: str) -> str:
    text = re.sub(r"1[3-9]\d{9}", "1**********", text)   # 手机号
    text = re.sub(r"\b\d{18}\b", "******************", text)  # 身份证
    return text

langfuse_context.update_current_observation(
    input={"question": mask_pii(question)},
    output={"answer": mask_pii(answer)},
)
```

### 8.2 完全关闭 tracing（兜底）

如果某个环境不需要 Langfuse（比如本地开发），可以完全关掉，业务照常不产生 trace：

```python
langfuse = Langfuse(
    public_key=settings.langfuse_public_key,
    secret_key=settings.langfuse_secret_key,
    host=settings.langfuse_host,
    tracing_enabled=False,   # 完全关闭，不发送任何数据
)
```

推荐做法是保留 tracing 但在 `update_current_observation` 里对 input/output 调 `mask_pii`（8.1 节），而不是直接关。

> **原则**：trace 是开发/运维看的，不是用户看的。但敏感数据一旦进去就删不掉，必须前置脱敏。

## 9. Langfuse 连不上时怎么办

**关键原则：可观测性不能成为主流程的阻塞。** Langfuse 挂了，业务必须照常。

Langfuse SDK 默认就是异步发送、失败静默。但为了保险，可以包一层：

```python
try:
    langfuse_context.update_current_observation(...)
except Exception:
    pass   # trace 失败不影响业务
```

或者完全禁用（通过环境变量）：`LANGFUSE_ENABLED=false`。

## 11. 失败模式速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| Langfuse UI 看不到 trace | 客户端没初始化 或 密钥错 | 检查 `Langfuse(...)` 参数；`langfuse.flush()` 手动刷一次 |
| trace 有但 span 缺失 | `@observe` 没加在目标函数上 | 确认关键函数都加了装饰器；跨进程调用不会自动串联 |
| token 统计为 0 | Ollama 版本旧不返回 usage | 升级 Ollama；或手动估算 |
| 业务被 Langfuse 拖慢 | 同步发送 trace | 用异步 SDK；或批量上报 |
| Langfuse 挂了导致接口 500 | trace 逻辑没兜异常 | 包 try/except；或 `LANGFUSE_ENABLED=false` 关掉 |
| 日志里出现敏感数据 | 没脱敏 | `mask_pii()` 前置处理 |
| 日志字段名不统一 | 各处随意命名 | 定义常量：`EVENT_LLM_CALL = "llm_call"` |
| Docker Compose 起不来 | 端口冲突或卷权限 | `docker compose logs langfuse` 看错；改 3000 为 3001 |
| `@observe` 在 async 函数上不生效 span | langfuse 版本旧 | `uv add langfuse --upgrade` |
