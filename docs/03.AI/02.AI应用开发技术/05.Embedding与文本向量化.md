# 05. Embedding 与文本向量化

> 系列第 5 篇，阶段二（检索与 RAG）开篇。从这一篇开始不再只和模型聊天，而是**把文本变成数字向量**——这是语义搜索、RAG 的地基。
> 学完你会知道：为什么"向量"能表示语义、bge-m3 怎么用、长文档怎么切、两段文本的相似度怎么算。

## 1. 学习目标

- 理解 Embedding 是什么：一句话变成一个 1024 维向量，语义相近的文本向量也相近
- 用 Ollama 跑起 `bge-m3` embedding 模型
- 用 OpenAI 兼容接口调 `/v1/embeddings`，封装一个 `embed_text()`
- 会做文本切分：固定长度 + overlap，理解为什么需要 overlap
- 用余弦相似度算两段文本的语义相似度
- **产出物**：`POST /api/embed` 返回文本向量；`POST /api/similarity` 返回两段文本的相似度分数

## 2. 什么是 Embedding

Embedding（嵌入）就是把一段文本映射成一个**固定长度的浮点数数组**：

```
"猫坐在垫子上" → [0.12, -0.34, 0.56, ..., 0.08]  （1024 个数）
"小猫卧在垫子上" → [0.11, -0.33, 0.55, ..., 0.09]  （和上面很接近）
"今天股市涨了"    → [-0.88, 0.21, -0.42, ..., 0.66] （和上面差很远）
```

关键性质：**语义越接近的文本，向量在数学空间里距离越近**。

这就是为什么后面能做"语义搜索"：用户问"怎么退款"，不用数据库 LIKE 匹配"退款"两个字，而是把问题变成向量，去文档向量里找距离最近的那几段。同义词、改写都能命中。

## 3. 装 bge-m3

BGE-M3 是开源 embedding 模型，中文效果好，支持长文本（最长 8192 token），通过 Ollama 跑：

```powershell
ollama pull bge-m3
```

| 项 | 值 |
|----|-----|
| 模型名 | `bge-m3` |
| 向量维度 | 1024 |
| 最大长度 | 8192 token |
| 中英文 | 双语，中文效果好 |

验证：

```powershell
ollama run bge-m3 "测试一下"
```

> bge-m3 是 embedding 模型，不会"对话"，它只输出向量。命令行跑它会报奇怪的回复，正常——用 API 调才对。

### 4.3 新建 `app/core/embedding.py`

```python
import logging
import numpy as np
from openai import AsyncOpenAI

from app.config import settings

logger = logging.getLogger(__name__)

# 复用 04 篇的 client，但 embedding 走另一个端点
_client = AsyncOpenAI(
    base_url=f"{settings.ollama_host}/v1",
    api_key="ollama",
)


async def embed_text(text: str) -> list[float]:
    """把一段文本转成 1024 维向量。"""
    resp = await _client.embeddings.create(
        model=settings.embedding_model,
        input=text,
    )
    return resp.data[0].embedding


async def embed_texts(texts: list[str], batch_size: int = 50) -> list[list[float]]:
    """批量转向量。自动分批，防止一次塞太多把 Ollama 打爆。"""
    results: list[list[float]] = []
    for i in range(0, len(texts), batch_size):
        batch = texts[i : i + batch_size]
        resp = await _client.embeddings.create(
            model=settings.embedding_model,
            input=batch,
        )
        results.extend(item.embedding for item in resp.data)
    return results


def cosine_similarity(a: list[float], b: list[float]) -> float:
    """余弦相似度：两个向量方向越一致，分数越接近 1。"""
    a_arr = np.array(a)
    b_arr = np.array(b)
    denom = np.linalg.norm(a_arr) * np.linalg.norm(b_arr)
    if denom < 1e-8:
        return 0.0   # 零向量或近乎零向量，直接返回不相关
    return float(np.dot(a_arr, b_arr) / denom)
```

### 4.4 余弦相似度怎么理解

```
cos(a, b) = a·b / (|a| × |b|)
```

| 分数 | 含义 |
|------|------|
| 接近 1.0 | 语义非常接近 |
| 接近 0   | 不相关 |
| 接近 -1  | 语义相反（实际中很少见） |

## 5. 文本切分：长文档怎么切成块

embedding 有长度限制（bge-m3 最长 8192 token），而且**一整篇文章塞进去，向量会"失焦"**——讲了十个话题，向量代表的是平均话题，哪个都不精准。所以入库前必须把长文档切成小块（chunk）。

### 5.1 为什么需要 overlap

如果硬切：

```
原文："退货需要在签收后7天内申请，且商品不影响二次销售。"
切在中间：
  chunk1: "退货需要在签收后7天内申"
  chunk2: "请，且商品不影响二次销售。"
```

一句话被切成两半，embedding 出来的向量语义是乱的。所以相邻块要**重叠（overlap）**，让边界上的句子在两块里都出现一次。

### 5.2 切分函数

新建 `app/core/chunking.py`：

```python
def split_text(
    text: str,
    chunk_size: int = 500,      # 每块约 500 字
    overlap: int = 80,          # 相邻块重叠 80 字
) -> list[str]:
    """
    按字符长度切分，带 overlap。
    生产环境会按 token 切或按段落/标题结构切，这里先讲最简单的。
    """
    if not text:
        return []
    if overlap >= chunk_size:
        raise ValueError(
            f"overlap({overlap}) 必须小于 chunk_size({chunk_size})，否则会死循环"
        )
    chunks = []
    start = 0
    text_len = len(text)
    step = chunk_size - overlap   # 每步前进的距离，必须 > 0
    while start < text_len:
        end = min(start + chunk_size, text_len)
        chunks.append(text[start:end])
        if end == text_len:       # 最后一块，结束
            break
        start += step
    return chunks
```

### 5.3 参数怎么选

| 参数 | 教学起步值 | 说明 |
|------|-----------|------|
| `chunk_size` | 300~500 字 | 太小丢失上下文，太大向量失焦 |
| `overlap` | chunk_size 的 15%~20% | 太小救不了边界，太大冗余多 |

第 9 篇 RAG 实战会讲更精细的切分（按段落、按 markdown 标题、按 token），现在先用简单字符切跑通。

## 6. FastAPI 接口

新建 `app/routers/embed.py`：

```python
from fastapi import APIRouter
from pydantic import BaseModel

from app.core.embedding import embed_text, cosine_similarity
from app.core.chunking import split_text

router = APIRouter(prefix="/api", tags=["embedding"])

class EmbedRequest(BaseModel):
    text: str

class SimilarityRequest(BaseModel):
    text_a: str
    text_b: str

class ChunkRequest(BaseModel):
    text: str
    chunk_size: int = 500
    overlap: int = 80

@router.post("/embed")
async def embed(req: EmbedRequest):
    vec = await embed_text(req.text)
    return {"dim": len(vec), "vector": vec[:5], "total": len(vec)}
    # 只返回前 5 维示意，完整向量太长不打出来

@router.post("/similarity")
async def similarity(req: SimilarityRequest):
    vec_a = await embed_text(req.text_a)
    vec_b = await embed_text(req.text_b)
    score = cosine_similarity(vec_a, vec_b)
    return {"score": round(score, 4)}

@router.post("/chunk")
async def chunk(req: ChunkRequest):
    chunks = split_text(req.text, req.chunk_size, req.overlap)
    return {"chunk_count": len(chunks), "chunks": chunks}
```

注册路由（`main.py`）：

```python
from app.routers import health, chat, prompt_demo, embed
app.include_router(embed.router)
```

curl -X POST http://127.0.0.1:8000/api/similarity `

## 8. 几个关键认知

1. **Embedding 模型和聊天模型是两回事**：bge-m3 不会说话，它只把文本变成向量；qwen2.5 负责生成回复。RAG 流程里两个模型都要用到。
2. **换 embedding 模型 = 重建所有向量**：不同模型产出的向量空间不同，不能混着存。生产环境定下来就别轻易换。
3. **维度不是越高越好**：1024 维是效果和性能的平衡点，bge-m3 还有 512/768 的变体可选。
4. **中文场景别用英文 embedding 模型**：`text-embedding-ada-002` 这类英文模型对中文效果差，中文优先 bge 系列。

## 10. 失败模式速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| `model not found` | bge-m3 没拉 | `ollama pull bge-m3` |
| embedding 接口 404 | 旧版 Ollama 不支持 /v1/embeddings | 升级 Ollama；或用原生 `/api/embeddings` |
| 向量长度不对 | 配置里 `EMBEDDING_DIMENSION` 和实际不符 | bge-m3 是 1024，确认配置 |
| 相似度全很低（连"猫"和"小猫"都不像） | 模型没加载对 / 文本太短 | 检查 `embedding_model` 配置；embedding 对短文本敏感，至少给一整句 |
| 切分后语义碎成渣 | chunk_size 太小或没 overlap | chunk_size 调到 300+，overlap 设成 15%~20% |
| 批量 embed 报长度错 | 一次塞太多或太长 | bge-m3 最长 8192 token，超长文本先切分 |
| 余弦分数算出来 >1 或 <-1 | 浮点数精度问题 | 正常，截断到 [-1, 1]；或 `np.clip(score, -1, 1)` |
