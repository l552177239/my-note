# 04. OpenAI 兼容接口与调用封装

> 系列第 4 篇。前三篇都是直接 `client.chat.completions.create(...)`，能跑但脆：网络抖一下就 500、并发一上来就把 Ollama 打满、换个 API 就要改一堆代码。
> 这一篇把它包成一个**全项目统一的 `call_llm()`**：自动重试、超时、并发限流、错误分类、多模型切换、Token 统计。后面所有篇目（RAG、Agent、Skill）都调它，不再重复写样板。

<!-- more -->

---

## 1. 学习目标

- 说清楚裸调 SDK 在生产环境会遇到的五类问题
- 用 `tenacity` 实现指数退避重试，且只重试该重试的错误
- 用 `asyncio.Semaphore` 控制并发，防止把本地 Ollama 打爆
- 设置合理超时，不让一个慢请求拖垮整个服务
- 支持多模型配置（本地 Ollama / 云端 API），按场景切换
- 记录每次调用的 token 用量，为第 17 篇可观测性铺路
- **产出物**：`app/core/llm.py` 里一个 `call_llm()`，带重试、超时、限流、返回用量

---

## 2. 为什么要封装：裸调的五个坑

```python
# 现在的写法（02/03 篇）
resp = await client.chat.completions.create(
    model=settings.ollama_model,
    messages=messages,
)
```

这行代码在生产会出什么事：

| 坑 | 现象 | 后果 |
|----|------|------|
| 网络抖动 | 偶发 `APIConnectionError` | 用户看到 500 |
| Ollama 短暂忙碌 | 偶发 503 / 超时 | 整个请求失败 |
| 并发太高 | 同时来 10 个请求 | 14B 模型 OOM 或全部排队 |
| 慢请求卡死 | 某个请求模型不响应 | worker 被占住，服务假死 |
| 换 API | 从 Ollama 换到 DeepSeek | 全项目到处改 base_url |

封装的目标：**这些问题在一个地方解决，业务代码只管调 `call_llm()`**。

## 5. 封装 `call_llm()`

重写 `app/core/llm.py`：

```python
import asyncio
import logging
from dataclasses import dataclass

from openai import AsyncOpenAI, APIConnectionError, APIStatusError, RateLimitError
from openai.types.chat import ChatCompletionMessageParam
from tenacity import (
    retry,
    retry_if_exception,
    stop_after_attempt,
    wait_exponential,
)

from app.config import settings

logger = logging.getLogger(__name__)

# ---------- 客户端单例 ----------
client = AsyncOpenAI(
    base_url=f"{settings.ollama_host}/v1",
    api_key="ollama",
    timeout=settings.llm_timeout_seconds,
)

# ---------- 并发信号量：全局限制同时在跑的 LLM 请求数 ----------
_semaphore = asyncio.Semaphore(settings.llm_max_concurrency)


# ---------- 哪些错误值得重试（必须在 @retry 之前定义）----------
def _is_retryable(exc: BaseException) -> bool:
    """网络错误、5xx、限流 -> 重试；4xx（认证、参数错）-> 不重试"""
    if isinstance(exc, (APIConnectionError, RateLimitError, asyncio.TimeoutError)):
        return True
    if isinstance(exc, APIStatusError):
        return exc.status_code >= 500   # 500/502/503/504 才重试
    return False


# ---------- 返回值：文本 + Token 用量 ----------
@dataclass
class LLMResult:
    content: str
    prompt_tokens: int
    completion_tokens: int
    total_tokens: int


# ---------- 核心调用：真正发请求，带重试 ----------
@retry(
    retry=retry_if_exception(_is_retryable),   # 只重试 _is_retryable 判定为 True 的错误
    stop=stop_after_attempt(settings.llm_max_retries + 1),
    wait=wait_exponential(multiplier=1, min=1, max=5),
    reraise=True,
)
async def _do_call(
    messages: list[ChatCompletionMessageParam],
    model: str | None = None,
    temperature: float = 0.0,
    json_mode: bool = False,
) -> LLMResult:
    """业务不要直接调它。"""
    kwargs: dict = {
        "model": model or settings.ollama_model,
        "messages": messages,
        "temperature": temperature,
    }
    if json_mode:
        kwargs["response_format"] = {"type": "json_object"}

    async with _semaphore:
        resp = await client.chat.completions.create(**kwargs)

    usage = resp.usage
    return LLMResult(
        content=resp.choices[0].message.content or "",
        prompt_tokens=getattr(usage, "prompt_tokens", 0),
        completion_tokens=getattr(usage, "completion_tokens", 0),
        total_tokens=getattr(usage, "total_tokens", 0),
    )


def _log_usage(result: LLMResult) -> None:
    logger.info(
        "LLM call: tokens=%d (prompt=%d, completion=%d)",
        result.total_tokens, result.prompt_tokens, result.completion_tokens,
    )


async def call_llm(
    messages: list[ChatCompletionMessageParam],
    model: str | None = None,
    temperature: float = 0.0,
    json_mode: bool = False,
) -> str:
    """业务代码统一调这个。只返回文本（简单场景）。"""
    result = await _do_call(
        messages=messages, model=model,
        temperature=temperature, json_mode=json_mode,
    )
    _log_usage(result)
    return result.content


async def call_llm_with_usage(
    messages: list[ChatCompletionMessageParam],
    model: str | None = None,
    temperature: float = 0.0,
    json_mode: bool = False,
) -> LLMResult:
    """需要统计成本/接 Langfuse 时调这个。返回完整结果。"""
    result = await _do_call(
        messages=messages, model=model,
        temperature=temperature, json_mode=json_mode,
    )
    _log_usage(result)
    return result
```

### 5.1 各部分在干什么

| 组件 | 作用 |
|------|------|
| `timeout=120` | 单次请求最多等 120 秒，超时抛异常 |
| `_semaphore` | 全局最多 3 个并发，第 4 个排队——保护本地模型不被打爆 |
| `@retry` + `retry_if_exception(_is_retryable)` | 失败后等 1s → 2s → 4s 重试，最多 3 次尝试；**只重试该重试的错误** |
| `_is_retryable` | 4xx（认证错、参数错）不重试，5xx/网络错/限流才重试 |
| `LLMResult` | 返回值对象：content + 三种 token 数，第 17 篇接 Langfuse 直接取 |
| `call_llm()` | 简单场景用，返回 str |
| `call_llm_with_usage()` | 要统计成本/token 时用，返回完整 `LLMResult` |

### 5.2 为什么要区分可重试错误

```python
# 错误：所有异常都重试，会把"API Key 错"也重试 3 次
@retry(stop=stop_after_attempt(3))
async def bad():
    await client.chat.completions.create(...)
```

API Key 错（401）、模型名拼错（404）、参数错（400）——这些重试多少次都没用，反而拖慢错误暴露。**只有"对方可能临时抽风"的错误才重试**。

@router.post("/chat")

## 8. 验证：模拟一次失败

临时把 `ollama_host` 改错（比如 `http://127.0.0.1:9999`），重启服务，调 `/api/extract`：

你会看到日志里：

```
Retrying __main__._do_call in 1.0 seconds as it raised APIConnectionError...
Retrying __main__._do_call in 2.0 seconds as it raised APIConnectionError...
```

三次都失败后才把异常抛给用户。这就是重试在工作。验证完记得把 `ollama_host` 改回来。

## 10. 失败模式速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| 重试后还是失败 | Ollama 真挂了 | 先 `ollama list` 看模型在不在，`curl /api/version` 看服务活没活 |
| 并发请求全都卡住 | 信号量太小或 Ollama 本身只能串行 | 本地 14B 模型 `LLM_MAX_CONCURRENCY` 设 2~4 合适，太大反而更慢 |
| 重试间隔太长，用户等不及 | `wait_exponential` max 设太大 | 本地场景 `max=3` 够了，云端 API 才需要 10 秒级退避 |
| `TimeoutError` 频繁 | 120 秒不够，长文本生成慢 | 调大 `LLM_TIMEOUT_SECONDS`；或检查是不是模型在 CPU 上跑 |
| 改了 `.env` 里的配置不生效 | Settings import 时加载一次 | 重启 uvicorn（01 篇踩过这个坑） |
| 流式接口没有走重试 | 流式和非流式是两套调用 | 本篇明确说：流式暂不重试，第 15 篇再处理 |
| token 用量全是 0 | 本地 Ollama 旧版本不返回 usage | 升级 Ollama；或用 `/api/tokenize` 自己数 |
