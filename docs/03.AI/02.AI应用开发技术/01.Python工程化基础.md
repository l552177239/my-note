## 2. 环境管理：venv / uv

### 2.1 传统方式（venv + pip）

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install fastapi "uvicorn[standard]"
pip freeze > requirements.txt
```

### 2.2 推荐方式：uv（2026 年的默认选择）

```bash
# 安装 uv
curl -LsSf https://astral.sh/uv/install.sh | sh
# windows 
winget install --id=astral-sh.uv -e

# 一键初始化项目（自动生成 .venv、pyproject.toml、.python-version）
uv init ai-app && cd ai-app

# 加依赖（自动写入 pyproject.toml + 锁文件）
uv add fastapi "uvicorn[standard]" pydantic-settings python-dotenv

# 同步环境（换机器/CI 上恢复环境）
uv sync

# 跑命令（自动使用项目 .venv，无需手动 activate）
uv run uvicorn app.main:app --reload
```

| 对比项 | pip + venv | uv |
|--------|-----------|-----|
| 解析速度 | 慢（分钟级） | 秒级 |
| 锁文件 | 手动 requirements.txt | 自动 uv.lock |
| Python 版本管理 | 需 pyenv | 内置 |
| 命令 | 先 activate 再执行 | `uv run` 直接跑 |

**约定**：全系列项目统一用 `uv`，命令全部写成 `uv run ...`，README 只写三步：`uv sync` → 复制 `.env.example` → `uv run ...`。

## 4. FastAPI 最小服务

`app/config.py`：

```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    app_name: str = "ai-app"
    host: str = "127.0.0.1"
    port: int = 8000

    # 后续篇目会在这里加：OLLAMA_HOST、LANGFUSE_KEYS、EMBEDDING_MODEL...
    # —— 现有 Java 业务系统接入位（第 12 篇 Function Calling 会用到）
    java_biz_api_base: str = "http://localhost:8080/api"
    jwt_secret: str = ""          # 透传前端登录 token 时校验用

settings = Settings()  # 全局单例，import 即用
```

`app/routers/health.py`：

```python
from fastapi import APIRouter

router = APIRouter(tags=["system"])

@router.get("/health")
def health():
    return {"status": "ok"}
```

`app/main.py`：

```python
import logging
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.config import settings
from app.routers import health

# 统一日志格式（第 17 篇接 Langfuse 时在此基础上加 handler）
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
)
logger = logging.getLogger(settings.app_name)

app = FastAPI(title=settings.app_name)

# CORS：第 16 篇 React(Vite) 从 5173 端口调过来，现在就开好
# 生产环境改成前端实际域名，不要用 "*"
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

app.include_router(health.router)
```

启动与验证：

```bash
uv run uvicorn app.main:app --reload --port 8000
curl http://127.0.0.1:8000/health        # {"status":"ok"}
# 交互式 API 文档（FastAPI 自动生成，后面调试 RAG 接口全靠它）：
# 浏览器打开 http://127.0.0.1:8000/docs
```

> **为什么现在就配 CORS 和日志？**
> CORS 不配，等到第 16 篇 React 前端调接口时浏览器直接拦截，新手会以为接口写错了；日志不配，第 17 篇上 Langfuse 时还要回头补。这两行是后面省半小时排查的预付款。

## 5. 异步基础：为什么 LLM 应用必须 async

LLM 调用、向量检索、HTTP 请求都是 **IO 密集** 操作：CPU 99% 时间在等网络返回。同步写法下，一个请求卡 3 秒，服务器就只能干等 3 秒。

```python
import asyncio
import time

async def fake_llm_call(prompt: str) -> str:
    await asyncio.sleep(1)        # 模拟 1 秒的模型调用
    return f"reply to: {prompt}"

async def main():
    prompts = [f"问题{i}" for i in range(5)]

    # 同步思路（错误示范）：5 个调用串行 = 5 秒
    t0 = time.perf_counter()
    for p in prompts:
        await fake_llm_call(p)
    print(f"串行: {time.perf_counter() - t0:.2f}s")   # ≈ 5s

    # 并发：5 个调用同时发出 = 1 秒
    t0 = time.perf_counter()
    await asyncio.gather(*(fake_llm_call(p) for p in prompts))
    print(f"并发: {time.perf_counter() - t0:.2f}s")   # ≈ 1s

asyncio.run(main())
```

三个必须记住的点：

1. **`async def` + `await`**：IO 操作前加 await，让出事件循环
2. **`asyncio.gather`**：并发执行一组协程——09 篇的"混合检索 = 向量检索 ∥ BM25 检索"就是靠它
3. **FastAPI 路由怎么选 async def 还是 def？**
   - 路由写成 `async def`：在事件循环里跑，遇到阻塞操作必须 `await`，否则卡住所有请求
   - 路由写成普通 `def`：FastAPI 自动把它丢进线程池执行，不会卡事件循环——适合调用老的同步库（如没异步版本的 SDK）
   - **红线**：在 `async def` 里禁止用同步阻塞调用（`requests.get`、`time.sleep`、同步 `psycopg2` 查询），一律换 `httpx.AsyncClient` / `asyncio.sleep` / 异步驱动

```
.env
.venv/
__pycache__/
*.pyc
```

**纪律**（阶段四第 18 篇会系统讲，现在先立规矩）：

- 密钥永远只进 `.env`，`.env.example` 只留键名

- 读取配置只从 `app.config.settings`，禁止在业务代码里 `os.getenv` 散落各处

## 8. 失败模式速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| `uv run` 找不到依赖 | 没跑 `uv sync` | 换机器/拉代码后第一步永远 `uv sync` |
| 改了代码不生效 | `--reload` 没生效或看错端口 | 确认启动命令带 `--reload`，确认 curl 的端口 |
| `.env` 修改后 Settings 没变化 | 服务没重启 | Settings 在 import 时加载一次，改配置必须重启 |
| `pydantic_settings` 报 `extra fields` | `.env` 里有未声明的键 | `SettingsConfigDict(..., extra="ignore")` 或在类里补字段 |
| 路由 404 | `include_router` 漏了 / 路径前缀拼错 | 先看 `/docs`，没有的接口就是没注册上 |
| 异步代码偶发卡死 | 在 async 函数里用了同步 IO（`requests`、`time.sleep`） | 换 `httpx.AsyncClient`、`asyncio.sleep`；或路由改普通 `def` |
| 前端调接口报 CORS / 浏览器控制台 No 'Access-Control-Allow-Origin' | `main.py` 没挂 CORSMiddleware，或前端源不在 allow_origins 里 | 按第 4 节配置，把前端 origin 加进去 |
| 访问日志格式乱 / 看不到 INFO | 没配 logging.basicConfig，uvicorn 默认 WARNING | 在 main.py 顶部加第 4 节的 basicConfig |
