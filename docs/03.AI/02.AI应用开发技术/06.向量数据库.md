# 06. 向量数据库

> 系列第 6 篇。05 篇把文本变成了向量，但存在内存里，重启就没了。这一篇引入 **Chroma**——一个轻量嵌入式向量数据库，把文本块、向量、metadata 持久化存下来，支持"给一段查询，返回最相似的 N 段"。
> 它是第 7 篇语义搜索、第 9 篇 RAG 的存储底座。

<!-- more -->

---

## 1. 学习目标

- 说清楚为什么不能用 Python list 存向量、为什么需要向量数据库
- 用 Chroma 的 `PersistentClient` 把数据持久化到磁盘
- 理解 Collection、document、embedding、metadata 的关系
- 实现三个操作：写入文本块、按向量搜 top_k、按 metadata 过滤
- 知道什么时候该从 Chroma 换到 Qdrant
- **产出物**：`POST /api/vector/add` 写入文本块；`POST /api/vector/search` 按查询返回最相似的 N 段

---

## 2. 为什么不能用 numpy list 存

05 篇我们能算两段文本的相似度，但要存 10000 段文本：

```python
# 纯内存方案的问题
vectors = [embed_text(t) for t in texts]   # 10000 × 1024 维
# 搜最相似的：
for v in vectors:
    cosine_similarity(query_vec, v)         # 10000 次循环，慢
```

问题：
- **重启就没**：存在内存里，进程一停全丢
- **全表扫描**：每来一个查询要和所有向量算一遍，10 万段就开始卡
- **没有元数据**：想只搜"产品手册"分类下的段落，纯 numpy 做不到
- **没有持久化格式**：每次启动都要重新 embed 一遍文档，白烧时间

向量数据库就是为这四件事设计的：**持久化 + 索引（加速相似度搜索）+ metadata 过滤 + 批量写入**。

### 4.2 新建 `app/core/vector_store.py`

```python
import logging
import uuid
import asyncio
import chromadb
from chromadb.config import Settings as ChromaSettings

from app.config import settings
from app.core.embedding import embed_texts

logger = logging.getLogger(__name__)

# 持久化客户端：数据写到磁盘，重启不丢
_client = chromadb.PersistentClient(
    path=settings.chroma_path,
    settings=ChromaSettings(anonymized_telemetry=False),
)


def _get_collection(name: str):
    """获取或创建 collection。"""
    return _client.get_or_create_collection(
        name=name,
        metadata={"hnsw:space": "cosine"},   # 用余弦距离
    )


async def add_documents(
    collection: str,
    documents: list[str],
    metadatas: list[dict] | None = None,
    ids: list[str] | None = None,
) -> list[str]:
    """
    写入文本块。自动 embed。
    id 默认用 uuid（避免多次 add 互相覆盖）；
    也可传 ids 做业务主键映射（如 doc_id="order_123"）。
    """
    if not documents:
        return []

    if ids is None:
        ids = [str(uuid.uuid4()) for _ in documents]
    elif len(ids) != len(documents):
        raise ValueError(f"ids 数量({len(ids)})和 documents 数量({len(documents)})不一致")

    vectors = await embed_texts(documents)
    metadatas = metadatas or [{} for _ in documents]

    col = _get_collection(collection)
    # Chroma 是同步阻塞库，丢到线程池，不卡死 FastAPI 事件循环
    await asyncio.to_thread(
        col.add,
        ids=ids,
        documents=documents,
        embeddings=vectors,
        metadatas=metadatas,
    )
    logger.info("Added %d docs to collection '%s'", len(documents), collection)
    return ids


async def search(
    collection: str,
    query: str,
    top_k: int = 5,
    where: dict | None = None,
) -> list[dict]:
    """
    语义搜索：返回最相似的 top_k 段。
    where: metadata 过滤条件，如 {"category": "faq"}
    """
    if not query.strip():
        return []

    query_vec = (await embed_texts([query]))[0]
    col = _get_collection(collection)

    results = await asyncio.to_thread(
        col.query,
        query_embeddings=[query_vec],
        n_results=top_k,
        where=where,
    )

    hits = []
    for doc, meta, dist in zip(
        results["documents"][0],
        results["metadatas"][0],
        results["distances"][0],
    ):
        hits.append({
            "text": doc,
            "metadata": meta,
            "score": round(1 - dist, 4),
        })
    return hits


async def delete_collection(name: str) -> None:
    """清空某个 collection（调试用）。"""
    try:
        await asyncio.to_thread(_client.delete_collection, name)
        logger.info("Deleted collection '%s'", name)
    except Exception as e:
        logger.warning("Delete collection '%s' failed: %s", name, e)
```

> **为什么用 `asyncio.to_thread`？**
> Chroma 的 `col.add()`、`col.query()` 都是同步阻塞调用。FastAPI 的 `async def` 路由跑在事件循环里，直接调同步 I/O 会卡住整个事件循环——并发一上来所有请求排队。`asyncio.to_thread` 把它们丢到线程池执行，主循环继续接新请求。
>
> **未来换 Qdrant？** Qdrant 官方 Python 客户端有 async 版本，到时候把 `_get_collection` 和 `asyncio.to_thread(col.add, ...)` 换成 `await qdrant_client.add(...)` 即可，`add_documents` / `search` 的函数签名和返回结构不变。

### 4.3 几个关键点

| 概念 | 说明 |
|------|------|
| **Collection** | 一个独立的"表"，不同用途分开存（如 `faq`、`product_manual`、`employee_handbook`） |
| **document** | 原始文本块 |
| **embedding** | 05 篇产出的向量 |
| **metadata** | 附加信息（来源、分类、权限），第 9 篇按权限过滤全靠它 |
| **cosine space** | `hnsw:space="cosine"` 告诉 Chroma 用余弦距离排序 |
| **score = 1 - distance** | Chroma 返回的是 distance（0~2），转成相似度（0~1）更直观 |

## 5. FastAPI 接口

新建 `app/routers/vector.py`：

```python
from fastapi import APIRouter, HTTPException
from pydantic import BaseModel, Field

from app.core.vector_store import add_documents, search, delete_collection

router = APIRouter(prefix="/api/vector", tags=["vector"])

class AddRequest(BaseModel):
    collection: str
    documents: list[str] = Field(..., min_length=1)
    metadatas: list[dict] | None = None
    ids: list[str] | None = None        # 可选：业务主键映射，不填则自动 uuid

class SearchRequest(BaseModel):
    collection: str
    query: str
    top_k: int = 5
    where: dict | None = None

class CollectionRequest(BaseModel):
    collection: str

@router.post("/add")
async def add(req: AddRequest):
    if req.metadatas and len(req.metadatas) != len(req.documents):
        raise HTTPException(
            status_code=422,
            detail=f"metadatas 数量({len(req.metadatas)})和 documents 数量({len(req.documents)})不一致",
        )
    if req.ids and len(req.ids) != len(req.documents):
        raise HTTPException(
            status_code=422,
            detail=f"ids 数量({len(req.ids)})和 documents 数量({len(req.documents)})不一致",
        )
    try:
        ids = await add_documents(req.collection, req.documents, req.metadatas, req.ids)
    except ValueError as e:
        raise HTTPException(status_code=422, detail=str(e))
    return {"added": len(ids), "ids": ids}

@router.post("/search")
async def search_endpoint(req: SearchRequest):
    hits = await search(req.collection, req.query, req.top_k, req.where)
    return {"hits": hits}

@router.post("/clear")
async def clear(req: CollectionRequest):
    await delete_collection(req.collection)
    return {"deleted": req.collection}
```

注册路由（`main.py`）：

```python
from app.routers import health, chat, prompt_demo, embed, vector
app.include_router(vector.router)
```

## 7. Chroma vs Qdrant vs FAISS

| 维度 | Chroma | Qdrant | FAISS |
|------|--------|--------|-------|
| 部署方式 | 嵌入式（Python 进程内） | 独立服务 | 库（无服务） |
| metadata 过滤 | 支持 | 强（DSL 丰富） | 自己写 |
| 生产可用 | 小项目可以 | 生产级 | 库，要自己包 |
| 学习成本 | 最低 | 中 | 中 |
| 适合阶段 | **本篇（学习/原型）** | 第 18 篇生产部署 | 理解原理 |

**结论**：学习和原型用 Chroma 完全够。第 18 篇上 Docker 时如果数据量上去了（10 万+块），再换 Qdrant——接口设计和本篇几乎一样，迁移成本低。FAISS 不用深究，知道是 Meta 的相似度搜索库即可。

## 9. 失败模式速查表

| 现象 | 原因 | 解法 |
|------|------|------|
| 重启后数据没了 | 用了 `chromadb.Client()` 而不是 `PersistentClient` | 确认用的是 `PersistentClient(path=...)` |
| 搜索结果全不对 | 写入时的 embedding 和查询时的不是同一个模型 | 确认 `EMBEDDING_MODEL` 没换过；换模型必须清空重建 |
| metadata 过滤不生效 | where 语法错 | Chroma 用 `{"category": "售后"}`，不是 SQL 的 `WHERE` |
| `add` 报 id 重复 | 同一批 id 写了两次 | 调试时先调 `/clear` 清空；生产用 UUID |
| chromadb 装不上 | 缺少系统依赖 | Windows 一般没问题；Linux 可能要 `build-essential` |
| 磁盘占用暴涨 | 数据没清理过 | 调 `/clear` 或删 `./data/chroma/` 重建 |
| `where` 里查不到中文 | metadata 值编码问题 | metadata 用英文 key，value 可以中文；或确认 UTF-8 |
| 搜索结果 score 都在 0.5 以下 | 写入的文档太短，向量区分度低 | 文档块至少一整句，别只存几个字 |
| 多次 add 后旧数据被覆盖 | 默认 `doc_0/doc_1` 自增 id，第二次 add 从 0 重新开始 | 用 uuid（默认已改），或传 `ids` 指定业务主键 |
| 并发时接口整体变慢 | Chroma 同步调用阻塞了事件循环 | 确认 `col.add/query` 都包在 `asyncio.to_thread` 里 |
