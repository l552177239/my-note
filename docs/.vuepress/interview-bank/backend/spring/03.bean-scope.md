## 题目

Spring Bean 常用作用域有哪些？单例 Bean 一定线程安全吗？为什么？

## 答案

1. **常用作用域**：`singleton`（默认）、`prototype`；Web 下还有 `request`、`session`、`application`。
2. **单例 ≠ 线程安全**：容器只保证「一个 JVM 容器内一份实例」，不保证并发访问成员变量安全。
3. **原因**：多线程共享同一对象；若有可变成员状态，仍需同步、无状态设计或改用原型/ThreadLocal。

### 解释与扩展

#### 1. 作用域一览

| 作用域 | 含义 | 典型场景 |
|---|---|---|
| `singleton` | 容器内唯一 | Service、Repository |
| `prototype` | 每次获取新建 | 有状态、短生命周期对象 |
| `request` | 每个 HTTP 请求一个 | 请求上下文 |
| `session` | 每个 Session 一个 | 用户会话状态 |
| `application` | ServletContext 级 | 很少用 |

#### 2. 为什么单例常「看起来安全」

实践中 Service 多做成 **无状态**（只依赖注入的线程安全协作对象，不在字段里攒业务可变数据），所以并发下也安全——这是设计结果，不是 singleton 的保证。

```java
// 危险：单例里可变状态
@Service
class CounterService {
  private int count; // 多请求共享 → 竞态
}

// 更稳：无状态 / 局部变量 / 并发安全结构
@Service
class OrderService {
  public void place(Order o) { /* 局部变量 + 注入的 repo */ }
}
```

#### 3. 选型提示

- 有请求级状态 → `request` 或方法内局部变量，别塞进单例字段。
- 真要有状态又要注入单例 → 注意原型注入单例的「只注入一次」陷阱（需 `Provider` / `@Lookup`）。

### 注意

- 面试必答：**作用域管实例个数，线程安全管并发访问**——两回事。
- Controller/Service 默认单例；别在成员变量里存用户相关可变数据。
