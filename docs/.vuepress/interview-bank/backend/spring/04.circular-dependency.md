## 题目

Spring 单例 Bean 循环依赖如何解决？三级缓存原理，以及三级缓存与 AOP 的关联关系？

## 答案

1. **能解决的典型场景**：单例 + 属性/Setter 注入形成的环（构造器注入环一般不行）。
2. **三级缓存**：提前暴露「半成品」引用，让另一方先完成注入，再回来补全自己。
3. **与 AOP**：三级缓存存的是 **ObjectFactory**，需要时才生成 **早期引用**；若该 Bean 需要代理，早期引用可以是 **提前创建的代理**，保证注入出去的和最终单例池里的是同一代理对象。

### 解释与扩展

#### 1. 三级缓存分别干什么

| 缓存 | 结构（概念） | 存什么 |
|---|---|---|
| 一级 `singletonObjects` | 成品单例 | 完全初始化好的 Bean |
| 二级 `earlySingletonObjects` | 早期引用 | 已实例化、可能已是代理，尚未完成初始化 |
| 三级 `singletonFactories` | `ObjectFactory` | 延后创建早期引用的工厂（关键：可在此决定是否 AOP） |

流程直觉（A ↔ B）：

```text
创建 A → 实例化 A → 把 A 的 ObjectFactory 放入三级缓存
填充 A 依赖 B → 去创建 B
创建 B → 实例化 B → B 的工厂入三级
填充 B 依赖 A → 从三级拿到 A 的早期引用（必要时先 AOP）→ 放入二级
B 初始化完成 → 入一级
回到 A，注入 B，A 初始化完成 → 入一级（清理二/三级）
```

#### 2. 为什么要三级，而不是二级就完事

- 若只有二级：实例化后立刻把原始对象放早期缓存，**无法统一处理「要不要变成代理」**。
- 有 AOP 时：希望注入到别人手里的是 **代理**，且与最终暴露一致。
- 三级把「生成早期引用」推迟到 **第一次被循环依赖方需要时**，在 `ObjectFactory.getObject()` 里通过 `SmartInstantiationAwareBeanPostProcessor.getEarlyBeanReference` 决定是否创建代理。

#### 3. 和 AOP 的关联（面试加分）

- 正常无循环：AOP 多在 `postProcessAfterInitialization` 包代理。
- 有循环且需代理：在获取早期引用时就可能 **提前创建代理**，后续初始化后置处理发现已是早期代理则不再包第二次，保证引用一致。

### 注意

- 三级缓存解决的是 **单例 setter/字段注入环**；不是万能药。
- Spring Boot 2.6+ 默认禁止循环依赖，需显式允许或重构。
- 详见同目录「三级缓存存什么 / 为何必须三级」「哪些循环依赖无法解决」。
