## 题目

为什么 MySQL InnoDB 使用 B+ 树而不是 B 树或哈希索引？

## 答案

InnoDB 聚簇索引与二级索引默认都基于 B+ 树。

相对 B 树：

- B+ 树非叶子节点只存键，扇出更大，树更矮，磁盘 IO 更少
- 叶子节点形成有序链表，范围查询、排序、`ORDER BY` / 区间扫描更友好

相对哈希索引：

- 哈希等值查询快，但不支持范围查询与排序
- InnoDB 自适应哈希是缓冲池内优化，不能替代磁盘上的 B+ 树索引结构

因此 OLTP 场景下 B+ 树在等值 + 范围查询之间更均衡。
