## 题目

什么是 Java 类加载器？常见有哪些？

## 答案

1. **类加载器（ClassLoader）**：负责把 `.class` 字节码加载进 JVM，生成对应的 `Class` 对象；是「字节码 → 可执行类型」的入口。
2. **常见层级**（JDK 9+）：
   - **Bootstrap ClassLoader**：由 JVM 原生实现，加载核心类（如 `java.lang.*`，来自模块 / 原 `rt.jar`）；
   - **Platform ClassLoader**（原 Extension）：加载平台扩展模块；
   - **Application ClassLoader**（App / System）：加载 classpath / 应用模块上的类；
   - **Custom ClassLoader**：可按需从网络、加密文件、热部署目录等加载。
3. 三者构成父子链：Application → Platform → Bootstrap；应用类默认由 Application ClassLoader 加载。

### 解释与扩展

| 加载器 | 大致职责 | 典型来源 |
|---|---|---|
| Bootstrap | 核心 JDK 类 | JVM 内置 / `java.base` 等 |
| Platform | 平台扩展 | 平台模块 |
| Application | 应用代码与依赖 | classpath / 应用模块 |
| Custom | 插件、热更、隔离 | 自定义路径 / 字节流 |

- 类的唯一标识是 **「全限定名 + 加载它的 ClassLoader」**：不同加载器加载的同名类，彼此不等价（`ClassCastException` 常见根因）。
- 加载器之间如何协作（先找父还是先找自己）见下一题「双亲委派模型」。

类加载全过程五步骤
  1. **加载**：类加载器读取 class 字节码，在堆生成 Class 对象。
  2. **验证**：字节码校验，格式、合法性（字节码安全校验，字节码好处里提到的安全）。
  3. **准备**：给静态变量分配内存，赋**默认初始值**。
  4. **解析**：符号引用转直接引用（把常量池的符号，指向真实内存地址）。
  5. **初始化**：执行静态代码块、给静态变量赋予真正代码写的值。

> 注意：
> 3中不是赋值业务值，`public static int a=10;` 准备阶段 a=0；初始化阶段才赋值 10。
> 5中什么时候触发初始化（主动引用）：new 对象、调用静态方法 / 静态变量、反射、main 方法入口、子类初始化。

### 注意

- JDK 9 起 Extension ClassLoader 更名为 Platform ClassLoader，模块化后路径不再是简单的 `ext/` 目录。
- Bootstrap 在 Java 里常表现为 `null`（`String.class.getClassLoader() == null`），不是 bug。
- 面试若追问「类加载过程」：加载 → 验证 → 准备 → 解析 → 初始化；本题重点在「谁来加载」。
