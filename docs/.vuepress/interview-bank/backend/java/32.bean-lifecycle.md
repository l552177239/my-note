## 题目

Spring Bean 完整生命周期各阶段，以及对应的扩展点有哪些？

## 答案

核心阶段：**实例化 → 属性填充 → Aware 回调 → BeanPostProcessor 前置 → 初始化（@PostConstruct / InitializingBean / init-method）→ BeanPostProcessor 后置（常在此 AOP 代理）→ 使用 → 销毁（@PreDestroy / DisposableBean / destroy-method）**。

关键扩展点：`InstantiationAwareBeanPostProcessor`、`BeanPostProcessor`、`InitializingBean`、`@PostConstruct`、`SmartInitializingSingleton`、销毁回调等。

### 解释与扩展

#### 1. 生命周期主链路（口述版）

```text
1. 实例化（反射 / 工厂方法 / InstantiationAware 可短路）
2. 属性填充（依赖注入）
3. Aware：BeanNameAware / BeanFactoryAware / ApplicationContextAware ...
4. BeanPostProcessor.postProcessBeforeInitialization
5. 初始化：@PostConstruct → InitializingBean.afterPropertiesSet → 自定义 init-method
6. BeanPostProcessor.postProcessAfterInitialization  ← AOP 代理常在这里
7. 单例放入单例池，对外可用
8. 容器关闭：@PreDestroy → DisposableBean.destroy → destroy-method
```

#### 2. 扩展点对照表

| 阶段 | 扩展点 | 典型用途 |
|---|---|---|
| 实例化前/后 | `InstantiationAwareBeanPostProcessor` | 短路创建、修改属性 |
| 初始化前后 | `BeanPostProcessor` | AOP、包装代理 |
| 初始化 | `@PostConstruct` / `InitializingBean` / `init-method` | 资源打开、校验 |
| 单例都创建完 | `SmartInitializingSingleton` | 依赖全部就绪后的启动逻辑 |
| 销毁 | `@PreDestroy` / `DisposableBean` / `destroy-method` | 关连接、释资源 |

#### 3. 和 AOP 的关系

多数情况下，**真正对外暴露的是后置处理后的代理对象**；原始对象完成填充与初始化后才被包装。

### 注意

- 不要背成十几步说明书：按「实例化 / 填充 / 初始化 / 代理 / 销毁」四块讲清即可。
- `@PostConstruct` 早于 `InitializingBean`；销毁顺序与初始化大致对称。
- 原型 Bean 默认不走完整容器销毁管理（除非额外注册）。
