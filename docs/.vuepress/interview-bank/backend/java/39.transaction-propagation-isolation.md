## 题目

Spring 事务传播行为、事务隔离级别分别解决什么业务问题？核心常用类型有哪些？

## 答案

1. **传播行为**：解决「方法嵌套调用时，要不要共用同一个事务、何时新建/挂起」——编排事务边界。
2. **隔离级别**：解决「并发事务之间，脏读/不可重复读/幻读」可见性与一致性问题。
3. **常用传播**：`REQUIRED`（默认）、`REQUIRES_NEW`、`NESTED`、`NOT_SUPPORTED`、`SUPPORTS`。
4. **常用隔离**：`DEFAULT`（跟库）、`READ_COMMITTED`、`REPEATABLE_READ`；极端才用 `SERIALIZABLE` / `READ_UNCOMMITTED`。

### 解释与扩展

#### 1. 传播行为 —— 管「边界怎么套」

| 传播 | 业务直觉 |
|---|---|
| `REQUIRED` | 有就加入，没有就新建（默认，最常用） |
| `REQUIRES_NEW` | 始终新开；外层挂起。审计日志、发号独立提交 |
| `NESTED` | 嵌套事务（保存点）；子失败可回滚到保存点，外层可继续 |
| `SUPPORTS` | 有事务就跟着，没有就非事务执行 |
| `NOT_SUPPORTED` | 挂起当前，非事务执行 |
| `MANDATORY` | 必须已有事务，否则异常 |
| `NEVER` | 必须无事务，否则异常 |

业务例子：下单主流程 `REQUIRED`；「写操作日志必须留下」用 `REQUIRES_NEW`，避免主单回滚把日志也抹掉。

#### 2. 隔离级别 —— 管「并发看见什么」

| 隔离 | 主要防什么 | 代价 |
|---|---|---|
| `READ_UNCOMMITTED` | 几乎不防 | 脏读 |
| `READ_COMMITTED` | 脏读 | 可能不可重复读/幻读 |
| `REPEATABLE_READ` | 脏读+不可重复读（MySQL InnoDB 对幻读也有 MVCC/间隙锁辅助） | 并发度下降 |
| `SERIALIZABLE` | 最强 | 吞吐最低 |

业务例子：对账强一致可提高隔离；高并发读多可 `READ_COMMITTED` + 业务补偿。

### 注意

- 传播 ≠ 隔离：一个管嵌套边界，一个管并发现象。
- MySQL 默认 RR，Oracle 常见 RC；`DEFAULT` 以实际库为准。
- `NESTED` 依赖底层保存点支持，和 `REQUIRES_NEW` 不是一回事。
