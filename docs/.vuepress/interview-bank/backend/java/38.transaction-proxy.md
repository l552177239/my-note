## 题目

Spring 事务为什么依赖代理生效？底层执行原理是什么？

## 答案

1. **为什么依赖代理**：`@Transactional` 的开启/提交/回滚是 **AOP 通知** 织入的；只有调用走代理，拦截器才能在目标方法前后管理事务。
2. **底层原理**：代理拦截 → `TransactionInterceptor` 按传播行为获取/创建事务 → 绑定到当前线程（如 `TransactionSynchronizationManager`）→ 执行业务 → 异常策略回滚或提交 → 清理资源。

### 解释与扩展

#### 1. 为何必须走代理

```text
调用方 → 代理.txMethod()
           ↓
     TransactionInterceptor
           ↓  open / join tx
     target.txMethod()
           ↓  commit / rollback
```

同类内部 `this.txMethod()` **不经过代理**，拦截器不执行 → 事务「失效」。

#### 2. 执行步骤（口述）

1. 解析 `@Transactional`（传播、隔离、rollbackFor…）做成 `TransactionAttribute`。
2. `PlatformTransactionManager` / `TransactionManager` 按传播行为决定新建还是加入。
3. 资源（DataSource Connection 等）与线程绑定。
4. 调用目标方法。
5. 运行时异常（默认）回滚；否则提交（可配 `rollbackFor`）。
6. 清理同步与连接绑定。

#### 3. 和数据源的关系

Spring 事务是 **统一抽象**；真正 commit/rollback 落在具体 `DataSourceTransactionManager`、`JpaTransactionManager` 等。

### 注意

- 「依赖代理」不是玄学，是 **声明式事务 = AOP 环绕通知**。
- 编程式事务（`TransactionTemplate`）可不靠业务方法代理，但声明式是主流。
