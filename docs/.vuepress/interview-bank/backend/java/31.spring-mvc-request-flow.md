## 题目

Spring MVC 一次 HTTP 请求的完整处理流程？

## 答案

请求进入 **DispatcherServlet** → 处理器映射找 Handler → 处理器适配器执行（含拦截器 preHandle）→ Controller 返回 → 拦截器 postHandle → 视图解析/渲染（或直接写 ResponseBody）→ afterCompletion；异常走异常解析器。

### 解释与扩展

#### 1. 主流程

```text
HTTP 请求
  → Filter 链（Servlet 规范，早于 DispatcherServlet）
  → DispatcherServlet.doDispatch
      → HandlerMapping 匹配 Controller 方法（HandlerExecutionChain）
      → 拦截器 preHandle（返回 false 则中断）
      → HandlerAdapter 调 Controller
      → 返回 ModelAndView 或 @ResponseBody 已写响应
      → 拦截器 postHandle
      → ViewResolver 解析视图并 render（若有）
      → 拦截器 afterCompletion（无论成败，在 finally 类逻辑中）
```

#### 2. 关键组件

| 组件 | 职责 |
|---|---|
| `DispatcherServlet` | 前台控制器，调度一切 |
| `HandlerMapping` | URL → Handler |
| `HandlerAdapter` | 统一调用形态各异的 Handler |
| `HandlerInterceptor` | MVC 层拦截 |
| `ViewResolver` | 逻辑视图名 → View |
| `HandlerExceptionResolver` | 统一异常 |

#### 3. 与 REST 的差异口述

`@RestController` / `@ResponseBody`：多数情况 **无视图渲染**，消息转换器（HttpMessageConverter）直接写 JSON。

### 注意

- Filter 在 Servlet 容器层；Interceptor 在 Spring MVC 层——别说成一个东西。
- 一次请求一个 `doDispatch` 是口述主线。
