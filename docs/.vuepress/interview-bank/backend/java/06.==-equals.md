## 题目

== 和 equals 有什么区别？

## 答案

1. `==`：比较栈里存的东西——基本类型比**值**，引用类型比**地址**。
2. `equals`：`Object` 默认实现等价于 `==`；子类常重写为比**内容**（如 `String`、`Integer`）。
3. 重写了 `equals` 必须按契约同步重写 `hashCode`，否则哈希集合（`HashMap` / `HashSet`）会出 bug。

### 解释与扩展

- 基本类型：栈中存变量值；引用类型：栈中存地址，对象内容在堆中。
- `String` 等值对象已重写 `equals`，内容相同即为 `true`，即便不是同一对象。
- 常见陷阱：
  - 字符串池：`"a" == "a"` → `true`（字面量入池）；`new String("a")` 则 `false`
  - Integer 缓存：`-128 ~ 127` 内 `==` 可能为 `true`，超出为 `false`
  - `BigDecimal`：业务比较优先 `compareTo`；`equals` 连精度一起比（`1.0 ≠ 1.00`）

### 注意

- `a.equals(b)` 在 `a` 为 `null` 时会 NPE；可用 `Objects.equals(a, b)`。
- 业务代码比字符串内容应优先用 `equals`，不要依赖常量池或缓存行为。
