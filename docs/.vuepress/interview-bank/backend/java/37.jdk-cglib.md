## 题目

JDK 动态代理和 CGLIB 代理的区别，Spring 中如何选择使用？

## 答案

1. **JDK 动态代理**：基于接口，`InvocationHandler`；代理类实现接口，目标类必须实现接口。
2. **CGLIB**：基于继承，生成目标类子类；可代理无接口的类（不能代理 final 类/方法）。
3. **Spring 选择**：有接口时历史上默认 JDK；Spring Boot 常默认 **CGLIB**（`spring.aop.proxy-target-class=true`）；也可强制指定。

### 解释与扩展

#### 1. 对比

| 维度 | JDK 动态代理 | CGLIB |
|---|---|---|
| 原理 | 实现接口 | 继承目标类 |
| 前提 | 必须有接口 | 类非 final，方法非 final（要增强的） |
| 性能 | 调用开销通常较低（视版本/场景） | 生成成本更高，调用近年也优化很好 |
| 限制 | 只能拦接口方法 | 构造会走子类；注意 final |

#### 2. Spring 如何选

```text
若 proxyTargetClass=true（Boot 默认常如此）→ 优先 CGLIB
否则：
  目标实现了接口 → JDK
  否则 → CGLIB
```

强制接口代理：`@EnableAspectJAutoProxy(proxyTargetClass = false)` 或配置 `spring.aop.proxy-target-class=false`。

#### 3. 实践影响

- 注入类型：JDK 代理应用 **接口类型** 注入；CGLIB 可用具体类类型注入。
- `final` 方法：CGLIB 拦不住。
- 自调用：两种代理都救不了（没走代理对象）。

### 注意

- 面试别说「CGLIB 一定更快」——看场景；选型关键是接口/final/注入类型。
- 事务、`@Async` 等同样走这套代理机制。
