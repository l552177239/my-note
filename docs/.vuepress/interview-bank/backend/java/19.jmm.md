## 题目

JMM 解决什么问题？原子性、可见性、有序性分别是什么？

## 答案

1. **JMM（Java Memory Model）**：规范「多线程如何读写共享变量、何种同步能保证正确性」——屏蔽 CPU 缓存、编译器 / CPU 重排带来的不确定性，让程序员用 `synchronized` / `volatile` / `final` 等得到可预期语义。
2. **解决的核心问题**：跨线程的 **可见性**（缓存不一致）、**有序性**（指令重排）、以及在此之上如何描述 **原子性** 所需的互斥边界；用 **happens-before** 把「谁先对谁可见」说清楚。
3. **原子性**：操作不可分割，中间态不被其他线程观察到。
4. **可见性**：一线程对共享变量的修改，其他线程能及时看到最新值。
5. **有序性**：在符合 happens-before 的前提下，禁止有害重排对外暴露。

### 解释与扩展

#### 1. JMM 解决什么问题

现代 JVM / CPU 为性能会做：
- **线程本地缓存 / 寄存器**：写完不一定立刻刷到主内存，别的核可能一直读旧值。
- **编译器重排、CPU 乱序执行**：单线程看起来等价，跨线程可能看到「半初始化」或「先用后建」的顺序。

若没有统一内存模型，同一份正确源码在不同硬件上行为不可预期。JMM 不规定具体硬件怎么做，而是规定：
- 哪些写对哪些读 **必须可见**；
- 哪些重排 **不允许** 破坏跨线程语义；
- 同步原语（锁、`volatile`、线程 start/join 等）建立怎样的 **happens-before**。

抽象模型（面试口述用）：

```text
  线程A 工作内存          主内存（共享变量）          线程B 工作内存
  ┌─────────────┐         ┌──────────────┐         ┌─────────────┐
  │ 本地副本     │ ←读/写→ │  flag / obj  │ ←读/写→ │ 本地副本     │
  └─────────────┘         └──────────────┘         └─────────────┘
```

要点：线程默认可能只在自己的工作内存里读写；**不加同步就没有「写完别人立刻看到」的保证**。JMM 用同步语义约束何时必须刷新 / 失效本地副本。

#### 2. 三大特性分别是什么

| 特性 | 一句话 | 典型失效场景 | 常见保障手段 |
|---|---|---|---|
| **原子性** | 一组操作要么完整生效，要么像没发生；别人看不到中间态 | `i++` = 读-改-写三步，两线程交错 → 丢更新；`long`/`double` 非原子写（旧模型常提，实践仍勿依赖） | `synchronized` / `Lock`、`Atomic*`、CAS |
| **可见性** | A 改完共享变量，B 能读到新值 | A 写 `flag=true`，B 在循环里永远读到 `false`（停在缓存 / 寄存器） | `volatile`、锁的释放-获取、`final` 初始化安全 |
| **有序性** | 跨线程观察顺序符合 happens-before，禁止有害重排 | DCL 未 `volatile`：先发布引用、后写字段 → B 看到半初始化对象；`ready` 与 `data` 重排导致「看见 ready 却未看见 data」 | `volatile`、锁、`final`、明确的 HB 边 |

口述收束：
1. **原子性**管「做完整」——别让别人看到半截。
2. **可见性**管「改完别人看得到」——别各自缓存各读各的。
3. **有序性**管「顺序别乱到破坏语义」——重排要对其他线程安全。

三者关系：
- `synchronized`：**原子性**（互斥）+ **可见性** + **有序性**（临界区内对后续加锁线程）。
- `volatile`：**可见性** + **有序性**（对该变量的读写建立 HB），**不**保证复合操作原子性（`volatile int` 的 `i++` 仍要锁或原子类）。
- 原子类：主要补 **原子性**（CAS），配合 `volatile` 语义的字段往往也带可见性。

#### 3. happens-before（串起 JMM 的关键词）

若操作 A **happens-before** 操作 B，则 A 的结果对 B 可见，且 A 排在 B 之前（对观察者而言）。常见规则够面试用：
- 同一线程内：前面的操作 HB 后面的操作。
- 解锁 HB 随后对同一锁的加锁。
- 对 `volatile` 的写 HB 随后对该变量的读。
- `Thread.start()` HB 该线程内的任何动作；线程内动作 HB 成功的 `join()` 返回。
- HB 传递：A HB B 且 B HB C ⇒ A HB C。

没有 HB 边时：可能看不到对方的写，也可能看到「重排后」的中间顺序——这就是 JMM 要你用同步把边补上的原因。

### 注意

- JMM 是 **规范 / 语义**，不是某块叫「工作内存」的真实硬件区；别把抽象图画成 JVM 实现细节。
- 三大特性是 **正确性目标**；具体用锁还是 `volatile` 看场景：要互斥用锁 / 原子类，只发布标志 / 单次写可见可用 `volatile`。
- 与上一题衔接：并发三大特性正是 JMM 要保证的核心；本问答侧重「JMM 为何存在、如何描述保证」。
- 面试加分：能举 DCL、`volatile` 标志位、`i++` 丢更新各对应哪条特性。
