## 题目

`sleep`、`wait`、`join`、`yield` 的区别？

## 答案

1. **`Thread.sleep(ms)`**：当前线程休眠一段时间，进入 `TIMED_WAITING`；**不释放**已持有的监视器锁；时间到（或被中断）后继续跑。
2. **`Object.wait()`**：必须在 `synchronized` 里调用；释放对应对象的监视器，进入 `WAITING` / `TIMED_WAITING`，等 `notify` / `notifyAll`（或超时）后再**重新抢锁**。
3. **`Thread.join()`**：当前线程等待**目标线程结束**；无参 → `WAITING`，带超时 → `TIMED_WAITING`；本质是对目标线程对象做 `wait` 系等待。
4. **`Thread.yield()`**：提示调度器让出当前时间片，状态仍是 `RUNNABLE`；**不保证**真的切换，也不释放锁。

### 解释与扩展

#### 1. 对照表

| 方法 | 所属 | 释放监视器锁？ | 进入状态 | 醒来条件 | 典型用途 |
|---|---|---|---|---|---|
| `sleep` | `Thread` 静态方法 | **否** | `TIMED_WAITING` | 时间到 / 被中断 | 限时暂停，与对象锁无关 |
| `wait` | `Object` 实例方法 | **是**（当前 `synchronized` 的那把） | `WAITING` / `TIMED_WAITING` | `notify`/`notifyAll` / 超时 / 中断 | 条件等待、生产者消费者 |
| `join` | `Thread` 实例方法 | 不持有目标线程锁时一般无关；实现上会 wait 目标线程 | `WAITING` / `TIMED_WAITING` | 目标线程 `TERMINATED` / 超时 | 等子线程跑完再汇总 |
| `yield` | `Thread` 静态方法 | **否** | 仍是 `RUNNABLE` | 立刻可再被调度 | 暗示「我可让出 CPU」，几乎不用 |

#### 2. 各自要点

**sleep**
- 谁调用谁睡，与哪个对象无关。
- 持锁睡着：别的线程仍拿不到这把锁 → 易拖长临界区。
- 抛 `InterruptedException`；捕获后应恢复中断标记：`Thread.currentThread().interrupt()`。

**wait**
- 未持有监视器就 `wait` → `IllegalMonitorStateException`。
- 被唤醒后**不保证立刻执行**，要先再拿到同一把锁。
- 标准写法：`while (!条件) { obj.wait(); }`，防止虚假唤醒。

**join**
- `t.join()`：当前线程阻塞，直到 `t` 结束（或超时）。
- 可理解为「等某个线程的生命周期走完」，常用于主线程等 worker。

**yield**
- 只是给调度器的**建议**，实现可忽略。
- 不能当同步手段；生产代码几乎不依赖它控制时序。

#### 3. 和线程状态的关系（口述串联）

```text
sleep(超时)     → TIMED_WAITING → 时间到 → RUNNABLE（锁一直握着）
wait()          → WAITING      → notify 后先抢锁（可能 BLOCKED）→ RUNNABLE
join()          → WAITING      → 目标终止 → RUNNABLE
yield()         → 仍在 RUNNABLE，只是可能让出 CPU
```

### 注意

- 面试高频对比：**sleep 不放锁，wait 放锁**。
- `wait` / `notify` 必须成对、在同一对象的 `synchronized` 上；别和 `sleep` 混着当「暂停」用。
- `join` 超时返回后要用 `isAlive()` 判断对方是否真结束。
- `yield` 不可预期，别用来「解决」竞态。
- 中断：`sleep` / `wait` / `join` 都可能抛 `InterruptedException`；`yield` 不会。
