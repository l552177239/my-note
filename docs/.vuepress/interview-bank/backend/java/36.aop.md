## 题目

AOP 的核心概念、应用场景是什么？Spring 代理对象的创建流程？

## 答案

1. **核心概念**：切面 Aspect、连接点 Join Point、切点 Pointcut、通知 Advice、织入 Weaving；Spring 多用 **运行时代理织入**。
2. **场景**：事务、日志、鉴权、限流、审计、缓存、监控——与主业务正交的横切逻辑。
3. **代理创建流程**：Bean 初始化后，`AnnotationAwareAspectJAutoProxyCreator` 等 `BeanPostProcessor` 匹配切点 → 选 JDK/CGLIB → 生成代理 → 方法调用时走拦截链执行 Advice。

### 解释与扩展

#### 1. 概念速记

| 概念 | 一句话 |
|---|---|
| Aspect | 横切逻辑模块（类） |
| Join Point | 可插入点（Spring 中主要是方法执行） |
| Pointcut | 匹配哪些连接点 |
| Advice | 具体增强：Before/After/Around/AfterReturning/AfterThrowing |
| Weaving | 把增强织到目标；Spring 默认运行时代理 |

#### 2. 代理创建流程（口述）

```text
Bean 实例化 + 属性填充 + 初始化
        ↓
BeanPostProcessor.postProcessAfterInitialization
        ↓
找到适用的 Advisor / Advice（切点匹配）
        ↓
需要增强？ → 创建代理（JDK 或 CGLIB）→ 放入容器
不需要？ → 返回原对象
        ↓
业务调用代理方法 → MethodInterceptor 链 → 目标方法
```

有循环依赖时：可能在早期引用阶段就通过 `getEarlyBeanReference` 提前创建代理（与三级缓存配合）。

#### 3. 应用场景边界

适合：声明式、与业务无关的横切。  
不适合：强业务分支、需要大量目标类内部状态细节的逻辑——容易变成「隐形业务」。

### 注意

- Spring AOP **默认只拦截 public 的 Spring Bean 方法调用**（自调用不走代理）。
- 与 AspectJ 编译期/加载期织入不同；别混为一谈。
