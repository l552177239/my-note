## 题目

并发容器：ConcurrentHashMap、CopyOnWriteArrayList 的原理与适用场景？

## 答案

1. **`ConcurrentHashMap`**：高并发 `Map`；JDK 8 起 **数组 + 链表/红黑树**，写靠 **CAS 占空桶 + 桶头 `synchronized`**，读大多无锁；**禁止 null key/value**。适合读多写多、按 key 访问的共享字典。
2. **`CopyOnWriteArrayList`**：**写时复制**——写（增删改）加锁后复制整数组再替换；读无锁读当前数组快照。适合 **读极多、写极少**、集合不大、能接受短暂「读到旧快照」的场景（如监听器列表）。
3. **选型**：共享 Map → CHM；偶尔改的 List/观察者 → COW；写很频繁的 List → 不要 COW，改队列、分段、或加锁的普通 List。
4. **都不是银弹**：CHM 的复合操作（先 `get` 再 `put`）仍要 `compute` 等原子 API；COW 写贵、内存翻倍，迭代弱一致。

### 解释与扩展

#### 1. ConcurrentHashMap（原理速记）

JDK 8 心智（面试默认版本）：

```text
Node[] table
  桶空  → CAS 挂新节点
  桶有链/树 → synchronized(桶头) 再插入/树化
读     → volatile 语义，一般不加锁
扩容   → 多线程协助 transfer
size   → baseCount + CounterCell[]（打散，类 LongAdder）
```

| 点 | 说明 |
|---|---|
| 锁粒度 | 到 **桶**（比 Hashtable 整表锁、JDK7 Segment 更细） |
| 与 HashMap | 结构相似，但并发安全；扩容/树化细节为并发设计 |
| null | **不允许**，避免歧义（`get` 分不清「没有」还是「值为 null」） |
| 复合操作 | `putIfAbsent` / `compute` / `merge` 保证单 key 原子性；手写 check-then-act 仍可能竞态 |

适用场景：
- 缓存、去重表、会话/配置索引、统计计数（可配 `LongAdder` 或 CHM 自身计数思想）
- **读多写多** 都常见，只要热点别全砸同一 key

不适用 / 当心：
- 需要 **全局强一致快照遍历**（遍历弱一致，扩容中可能看到旧/新混合观感）
- 业务要 null → 另设计
- JDK7/8 细节对比见专题题「ConcurrentHashMap 原理与 JDK7/8 区别」

#### 2. CopyOnWriteArrayList（原理）

```text
读：直接访问 volatile array 引用，无锁
写：ReentrantLock（或等价互斥）
    → 复制整份 Object[]
    → 在新数组上改
    → 把 volatile array 指向新数组
```

| 特性 | 含义 |
|---|---|
| **读无锁** | 吞吐好，多线程狂读不互斥 |
| **写复制** | 写代价 O(n) 内存 + 拷贝；写写互斥 |
| **迭代器** | 绑定创建时那份数组快照，**不会** `ConcurrentModificationException`；看不到迭代开始后的新写 |
| **弱一致** | 读可能落后于最新写（换引用前） |

```java
CopyOnWriteArrayList<Listener> listeners = new CopyOnWriteArrayList<>();
// 注册少：add 可接受
listeners.add(l);
// 回调多：遍历无锁、不 CME
for (Listener x : listeners) x.onEvent(e);
```

适用场景：
- **读 ≫ 写**：事件监听、配置订阅者、白名单（几乎不改）
- 集合 **偏小**（拷贝才扛得住）
- 能接受读到「稍旧」快照

不适用：
- 写频繁（每次 add/remove 全量拷贝 → CPU/GC 炸）
- 超大 List
- 需要读始终看到最新写、或写多读多的队列场景 → 用 `BlockingQueue` / CHM / 加锁结构

#### 3. 对照选型

| | ConcurrentHashMap | CopyOnWriteArrayList |
|---|---|---|
| 结构 | 哈希表（桶级并发） | 数组（写时整表复制） |
| 读 | 无锁为主 | 无锁 |
| 写 | 桶级竞争，可并行写不同桶 | 全局写锁 + 拷贝，写很贵 |
| 最佳负载 | 高并发读写 Map | 读多写少的小 List |
| 迭代 | 弱一致 | 快照，不 CME |
| 典型替代谁 | `Hashtable` / 同步包装 Map | 同步 `ArrayList` / 手写锁 List |

其他并发容器一笔带过（面试点到即可）：
- `ConcurrentLinkedQueue`：无界非阻塞队列
- `BlockingQueue` 实现：生产者消费者
- `ConcurrentSkipListMap`：并发有序 Map

### 注意

- COW **不是**「并发 List 的默认答案」；写一多就错选。
- CHM 安全的是 **单操作** 与文档保证的原子 API，不是任意业务事务。
- 与伪共享 / LongAdder 题衔接：CHM 计数打散同一思想；与线程池场景里共享状态优先 CHM 而不是全局 `synchronized` Map。
- 面试加分：能对比「桶级锁 vs 写时复制」，并各举一个该用 / 不该用场景。
