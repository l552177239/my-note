## 题目

String、StringBuffer、StringBuilder 的区别及使用场景？

## 答案

1. **String**：不可变；修改会生成新对象；本身线程安全，适合常量、共享、少量拼接。
2. **StringBuilder**：可变缓冲区，无锁；单线程大量拼接性能最好（首选）。
3. **StringBuffer**：API 类似但方法带 `synchronized`；线程安全、有同步开销，仅多线程共享同一缓冲区时考虑。

### 解释与扩展

| | String | StringBuffer | StringBuilder |
|---|---|---|---|
| 可变性 | 不可变（每次拼接产生新对象） | 可变 | 可变 |
| 线程安全 | 不可变本身线程安全 | `synchronized`，线程安全 | 无锁，非线程安全 |
| 性能 | 频繁拼接差 | 有同步开销 | 单线程下最快 |

**使用场景：**
- **String**：常量、少量拼接、作 key / 参数传递
- **StringBuilder**：单线程循环拼装、动态 SQL 等（首选）
- **StringBuffer**：多线程共享同一可变缓冲区（现代代码少见；优先局部 `StringBuilder` 或并发方案）

### 注意

- `"a" + "b"` 等编译期常量会直接折叠；循环里 `+` 在较新 JDK 上也会优化为 `StringBuilder`，但显式使用意图更清晰。
- 不要为「线程安全」盲目选 `StringBuffer`：多数拼接是局部变量，单线程用 `StringBuilder` 即可。
