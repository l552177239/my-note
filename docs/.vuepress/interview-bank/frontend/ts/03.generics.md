## 题目

TypeScript 泛型解决什么问题？和 `any` 比有什么优势？如何在函数、类以及 axios 响应数据上使用泛型？

## 答案

1. **问题**：组件要支持「当前和未来」多种类型，同时保持类型关系（传入什么就返回什么）。

2. **优于 any**：`identity(arg: any): any` 能接收任意类型，但丢失「入参与返回值相同」的信息。泛型用类型变量 `T` 捕获类型：`function identity<T>(arg: T): T`。

3. **泛型函数**：可显式传 `identity<string>('x')`，更常见靠**类型推论** `identity('x')`。函数体内必须把 `T` 当成任意类型用；要访问 `.length` 可写成 `T[]` 或 `T extends Lengthwise`。

4. **泛型类**：`class GenericNumber<T> { zeroValue: T; add: (x: T, y: T) => T }`。泛型作用在**实例部分**，静态属性不能用该类的 `T`。

5. **axios 响应泛型**：后端 data 形状用接口描述，请求方法带 `T`，如 `AxiosResponse<T>`、`axios.get<ResponseData<User>>(url)`，调用方可推断 `code` / `result` / `message` 及 `result` 的具体字段。

### 解释与扩展

- 泛型可放在调用签名上（仍是泛型函数），也可放在接口/类上（使用时锁定 `GenericIdentityFn<number>`）。
- 约束：`T extends Lengthwise`；也可用 `K extends keyof T` 保证 key 存在。
- 实践：`getUser<T>() { return axios.get<ResponseData<T>>('/path').then(res => res.data) }`，再 `await getUser<User>()`。

### 注意

- 无法创建泛型枚举、泛型命名空间。
- 编译器推不出 `T` 时必须显式传入。
- `any` 不是泛型的替代品，只是放弃检查。
