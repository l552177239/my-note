## 题目

请介绍 TypeScript 的基础类型，并说明类型注解、类型推断、类型断言的区别。类型检查发生在什么阶段？

## 答案

1. **基础类型**：与 JS 对齐的有 `boolean`、`number`、`string`、数组（`T[]` / `Array<T>`）、`null`、`undefined`、`object`；TS 补充了元组、`enum`、`any`、`void`、`never`。

2. **类型注解**：显式写出类型，如 `let isDone: boolean = false`。编译器按注解做检查。

3. **类型推断**：未写注解时，TS 根据初始化、默认参数、返回值等自动推断，如 `let x = 3` 推断为 `number`。

4. **类型断言**：程序员比编译器更清楚类型时，用 `<string>value` 或 `value as string` 告诉编译器。**只在编译期生效**，不做运行时转换或检查。JSX 里只能用 `as`。

### 解释与扩展

- **数组 vs 元组**：`number[]` 元素同类型；`[string, number]` 长度与各位置类型固定。TS 3.1 后访问越界元素会报错。
- **enum**：给一组数值起名字，默认从 0 编号，也可反向由值查名字。
- **any**：跳过检查，适合改写旧代码或类型未知的动态数据，会丢失类型信息。
- **void**：通常作无返回值函数的返回类型。
- **never**：永不返回（抛错、死循环）；是任何类型的子类型，`any` 也不能赋给 `never`。
- **object**：非原始类型。默认 `null`/`undefined` 是所有类型的子类型；开启 `--strictNullChecks` 后需用联合类型显式包含。

### 注意

- TS 类型是**编译期**的：编译成 JS 后注解和断言都会擦除，运行时没有这些类型。
- 断言不是类型转换，滥用会把错误推迟到运行时。
- 面试可顺带对比：注解是「我声明」、推断是「编译器猜」、断言是「请相信我」。
