## 题目

TypeScript 类型推断发生在哪些地方？什么是最佳通用类型和上下文类型？

## 答案

1. **基础推断**：未写明类型时，TS 会补全类型。典型场景：**初始化变量和成员**、**设置默认参数**、**决定函数返回值**。如 `let x = 3` → `number`。

2. **最佳通用类型**：从多个表达式推断时，取能兼容所有候选的类型。`let x = [0, 1, null]` 会考虑 `number` 和 `null`。

3. **没有公共超类型时**：`[new Bee(), new Lion()]` 期望是 `Animal[]`，但数组里没有 `Animal` 实例，会推断成 `(Bee | Lion)[]`。需要时显式写 `let zoo: Animal[] = [...]`。

4. **上下文类型**：根据表达式**所在位置**反推，如赋值给 `window.onmousedown` 时，右侧函数参数会按事件类型检查。若函数自己写了参数注解，则忽略上下文类型。

### 解释与扩展

- 函数完整类型也可「按上下文归类」：一边写了 `(x: number, y: number) => number`，另一边参数可省略注解。
- 上下文类型常出现在：函数参数、赋值右侧、类型断言、对象成员、数组字面量、return。它也会作为最佳通用类型的**候选**。例如 `createZoo(): Animal[]` 的 return `[new Bee(), new Lion()]` 会选出 `Animal`。
- 泛型调用里不写 `<>` 时，同样依赖从实参推断 `T`。

### 注意

- 推断失败或不够精确时，应显式注解，不要依赖「猜对」。
- 上下文类型被明确注解覆盖后，访问不存在的属性可能不再报错（如把 mouseEvent 标成 `any`）。
- 最佳通用类型取自候选，不会凭空发明一个没出现过的基类（除非上下文提供了该基类）。
