## 题目

Redux 是什么？三条原则是什么？为什么说组件不应自己长期持有业务 state？

## 答案

1. **定位**：JS 状态容器，提供可预测的状态管理；在 React 里做组件间数据流。是对 Flux 的简化，reducer 来自纯函数思想。

2. **三条原则**
   - 整个应用的 state 以对象树存在**单一 store**。
   - 改变 state 的唯一方式是 **dispatch 一个 action**（描述发生了什么的对象）。
   - 用纯函数 **reducer** 描述 action 如何算出新 state：`(state, action) => newState`。

3. **数据流**：View 派发 action → reducer 计算新 state 写入 store → 订阅的组件更新。组件尽量不私藏应共享的业务数据。

### 解释与扩展

- 纯函数：相同输入相同输出、无副作用，便于测试和时间旅行调试。
- 作者名言：props 还用不好就不要急着学 Redux。局部 UI 状态不必进 store。
- 异步副作用需中间件（笔记中的 Thunk）：action 可以是函数，内部再 dispatch。

### 注意

- reducer 里不要改原对象，应返回新对象/新引用。
- 不是所有 React 项目都需要 Redux；简单父子传参即可。
- 面试把「单 store、dispatch action、纯 reducer」三点说全。
