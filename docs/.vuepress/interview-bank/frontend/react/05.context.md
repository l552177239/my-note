## 题目

为什么需要 Context？如何实现越级传递 props？（可按笔记中的 legacy API 回答，并补充现代写法）

## 答案

1. **动机**：避免中间层无意义地把 props 一层层往下传（prop drilling），实现**越级**传值。

2. **笔记中的旧 API（0.14+ 实验）**：祖先实现 `getChildContext()` 返回数据，并声明 `childContextTypes`；后代声明 `contextTypes`，用 `this.context.hello` 读取。中间组件不用接力 props。

3. **现代 API**：`React.createContext`，祖先 `<MyContext.Provider value={...}>`，后代 `useContext(MyContext)` 或 `MyContext.Consumer`。

### 解释与扩展

- 旧 API 需要 `prop-types` 声明 context 字段类型，否则拿不到。
- Context 适合主题、当前用户、语言等「树的一枝都需要」的数据；频繁变化的数据可能拖累所有消费者。
- Redux 的 Provider 也是基于 Context 把 store 注入子树。

### 注意

- 笔记写明旧 Context 实验性强、不推荐；面试应能说新旧两套，项目用新 API。
- 未匹配的 `contextTypes` / 未包 Provider 时读到的是默认值或空。
- 不要用 Context 代替所有状态管理；局部 state 仍更清晰。
