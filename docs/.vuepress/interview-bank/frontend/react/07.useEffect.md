## 题目

`useEffect` 相当于哪些 class 生命周期？什么是需要清除的副作用？依赖数组 `[]` 和 `[count]` 有何区别？

## 答案

1. **对应关系**：可看作 `componentDidMount`、`componentDidUpdate`、`componentWillUnmount` 的**组合**。默认在**每次渲染之后**（含首次）执行 effect；React 保证此时 DOM 已更新。

2. **副作用**：请求、订阅、改 DOM（如 `document.title`）等。class 里常在 DidMount 和 DidUpdate **写两遍相同代码**；effect 按「每次渲染后」思考即可。

3. **cleanup**：effect 可返回清除函数。订阅在 effect 里注册，在下次 effect 前及卸载时解除，避免泄漏。与 WillUnmount「只在卸载清一次」不同，更新前也会清。

4. **依赖**：第二参数数组。`[count]` 仅 count 变才重跑；`[]` 近似只在挂载/卸载跑（闭包里的 props/state 会是初始值）。

### 解释与扩展

- 多个 effect 可拆分关注点（改标题 vs 订阅好友状态）。
- `useEffect` 不阻塞浏览器绘制；要同步量布局用 `useLayoutEffect`。
- 依赖必须包含 effect 用到的外部可变值，否则会读到过期闭包。推荐 `eslint-plugin-react-hooks` 的 `exhaustive-deps`。

### 注意

- 忘记在 DidUpdate 处理 props 变化是 class 常见 bug；effect 每次按依赖重订阅就是为了避免这个。
- 不要把 `[]` 当万能，漏依赖会出很难查的 bug。
- render 阶段不要做副作用，全部放进 effect。
