## 题目

搜索框输入时如何避免频繁请求接口？请写出 Vue 中常用的 debounce 封装，并说明为何不直接在 watch 里请求。

## 答案

1. **场景**：query 每变一次就请求，快速输入会造成大量无效请求，需要防抖：停止输入一段时间后再执行。

2. **封装**：闭包保存 `timer`，每次调用先 `clearTimeout`，再 `setTimeout` 到期后 `func.apply(this, args)`。

3. **在 Vue 中使用**：`created` 里 `this.$watch('query', debounce((newQuery) => { this.$emit('query', newQuery) }, 200))`，而不是在 watch 选项里直接打接口。

### 解释与扩展

```js
export function debounce(func, delay) {
  let timer
  return function (...args) {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => {
      func.apply(this, args)
    }, delay)
  }
}
```

- 防抖：延迟执行，只认最后一次；节流：固定间隔至少执行一次。搜索用防抖，滚动用节流更常见。
- `apply(this, args)` 保证回调里的 `this` 和参数不丢。

### 注意

- 组件销毁前应取消未完成的 timer，避免卸载后 setState/请求。
- 不要把 debounce 写在 `methods` 里每次渲染新建（或每次 watch 重新包一层），应一次创建、复用同一函数引用。
- 防抖延迟要权衡体验（太长显得卡，太短仍会打爆接口）。
